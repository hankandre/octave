# Proposal: name the web form's packages in DOMAINS.md (T17-01)

Status: step 1 of the change process for guiding documents (`AGENTS.md`, "Guiding documents"). Not reviewed, not approved. `DOMAINS.md` is unchanged until the owner approves this text and a pull request for it alone lands.

## What is missing

T17-01 adds two packages: `apps/web` (the web form's screens and composition root, React DOM) and `packages/web-host` (the web form's adapters). `DOMAINS.md` names neither, so it does not say which domain owns them or which way their imports may point. An agent reading it before adding web code (as `AGENTS.md` asks) finds no place for it.

## The exact new text

**1. In section 8, "App Shell & Presentation", after its "Rules." list**, a new paragraph and list:

```markdown
**The web form.**
- `apps/web` owns the web form's screens and its composition root, written in React DOM. It names no network or browser storage API.
- `packages/web-host` owns the web form's adapters. It is the only web code that may reach the network or browser storage.
```

**2. In "Dependency rules", inside the diagram's code block, after the line `adapters (gateway transport, native modules) ──► domain, ports`**, a blank line and:

```text
web:  apps/web ──► packages/web-host ──► packages/core
      apps/web ─────────────────────────► packages/core
```

**3. In "Dependency rules", directly after the diagram's code block and before rule 1**, one sentence:

```markdown
Neither `apps/web` nor `packages/web-host` imports `apps/tv`, `modules/`, React Native or Expo; `packages/web-host` never imports `apps/web`; and `packages/core` imports neither of them.
```

Nothing else in `DOMAINS.md` changes.

## What this text leaves out, and where it lives

A guiding document holds no per-task or tool detail (`AGENTS.md`). The detail exists already:

- What each package owns today, the exact list of refused network and storage names, and the lint's known limits: `docs/specs/T17-01.md` (Approach 3 to 5) and `eslint.web.config.js`.
- The import rules and how they are enforced: `.dependency-cruiser-web.cjs`, run by `scripts/lint-web-boundaries.mjs` as the second pass of `pnpm lint:boundaries`.
- The commands: `docs/commands.md`, "Web form".

## What it affects

- **`DOMAINS.md` only.** No code, test or task changes with it; the lints already enforce the rules the text states (`scripts/web-boundaries.test.ts`, `scripts/web-lint.test.ts`).
- **Citations.** Placing the web entry after section 8's "Rules." keeps `DOMAINS.md:185`, which plan 017 cites, on the same line. The three additions shift the lines after them; older specs cite `DOMAINS.md:206`, `:211` and `:234`, which already point at other text and are history.
- **Later web tasks.** T17-10 and T17-11, which wire `packages/core` and fill `packages/web-host`, add their own paths to the section only through the same process; until then the specs and configs above are the reference.
- **The TV.** None: no TV domain, rule or path changes.
- **T17-01.** Its acceptance item 6 asks for this proposal, not the edit (Product Owner pass, 2026-11-27).
