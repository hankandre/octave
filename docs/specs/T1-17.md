# T1-17: Retry a CI emulator step only when the emulator never ran the test, and skip the device jobs on pull requests that change only tasks or docs

- Risk: a CI change, which `AGENTS.md` §Pull requests says the PR must call out. The Product Owner flagged it for the owner (`tasks/product-owner-log.md` lines 272 and 289). No playback, server, token or native change, so no Jellyscale wire test applies to this task.
- Takes backlog entries 228 and 229 (`tasks/backlog.jsonl`), each already marked `taken_by: "T1-17"`.

## Goal

Two rules for `.github/workflows/ci.yml`:

1. **Retry.** The three emulator steps (first focus and conformance in `tv`, the wire tests in `wire`) run once more when, and only when, the emulator never reached the step's test script. A step whose script started is never run again, whatever its result. Where the workflow cannot prove the script never started, it does not retry.
2. **Skip.** A pull request whose changed files are all under `docs/` or `tasks/` skips the `tv`, `wire` and `tripwire` jobs. Every other case runs all three: any other changed path, a diff that cannot be read, a push to main, a merge group. `checks` and `dependency-review` are untouched.

## Approach

### 1. The skip

Add this job before `checks` (pins copied from the `checks` job):

```yaml
  # Decides whether the device jobs run (T1-17). Only a pull request whose every
  # changed path is under docs/ or tasks/ gives "skip". A push, a merge group,
  # an unreadable diff and a failure of this job all leave the output empty or
  # "run", and tripwire, tv and wire then run.
  changes:
    runs-on: ubuntu-22.04
    timeout-minutes: 5
    outputs:
      device-jobs: ${{ steps.decide.outputs.device-jobs }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        if: github.event_name == 'pull_request'
        with:
          persist-credentials: false
          fetch-depth: 2 # the merge commit and both parents
      - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
        if: github.event_name == 'pull_request'
        with:
          node-version-file: .node-version
      - id: decide
        if: github.event_name == 'pull_request'
        env:
          OCTAVE_CI_HEAD_SHA: ${{ github.event.pull_request.head.sha }}
        run: node scripts/ci-device-jobs.mjs
```

Add to each of `tripwire`, `tv` and `wire`, directly under the job's name line:

```yaml
    needs: changes
    if: ${{ !cancelled() && needs.changes.outputs.device-jobs != 'skip' }}
```

Why this form:

- **Only an explicit `skip` skips.** With `!cancelled()` the condition is evaluated even when `changes` failed, and a failed or stepless `changes` gives an empty output, which is not `skip`. Without a status function GitHub would skip the three jobs whenever `changes` failed (F13).
- **A cancelled run** skips the jobs it has not started. `checks` is required and is then cancelled, so nothing merges on that run.
- **The diff is the merge commit's.** On `pull_request` the checkout is the pull request's merge commit; `HEAD^1` is the base and `HEAD^2` the pull request's head. `git diff --name-only --no-renames -z HEAD^1 HEAD` is exactly what the merge would change on main. `--no-renames` lists a moved file under both paths, so a move from `apps/` into `docs/` runs the jobs. `-z` keeps odd file names whole.

`scripts/ci-device-jobs.mjs` (Node built-ins and `git` only; importing it runs nothing):

- `SKIPPABLE_PREFIXES`: a frozen `["docs/", "tasks/"]`.
- `deviceJobsDecision({ eventName, paths })` returns `{ decision: "skip" | "run", reason }`. `skip` only when `eventName === "pull_request"`, `paths` is a non-empty array, and every entry is a non-empty string that starts with one of the prefixes (case-sensitive). Everything else is `run`.
- `changedPaths({ repo, headSha })` returns `{ paths }` or `{ unreadable: reason }`. Unreadable when `headSha` is empty, `HEAD` does not have exactly two parents, `HEAD^2` is not `headSha`, or any `git` call fails. Every `git` call is `execFileSync("git", ["-C", repo, ...])`, never a shell.
- CLI (`[--repo <dir>]`, default the working directory): reads `GITHUB_EVENT_NAME` and `OCTAVE_CI_HEAD_SHA`, prints one line `ci device jobs: <decision> (<reason>)`, and appends `device-jobs=<decision>` to the file `GITHUB_OUTPUT` names. An unreadable diff is `run`. Exit 0 once the output is written; exit 1 with an `ERROR ci:` line if it cannot be written (the job then fails and the three jobs run).

### 2. The retry

In `tv`, after "Enable KVM" and before the first emulator step, and in `wire` in the same place, add the shim step:

```yaml
      # T1-17: a pnpm shim, first on PATH, creates the file an emulator step
      # names in OCTAVE_CI_SCRIPT_STARTED before it starts the real pnpm.
      - name: Mark when an emulator step's script starts
        run: |
          real="$(command -v pnpm)"
          mkdir -p "$RUNNER_TEMP/octave-ci/bin" "$RUNNER_TEMP/octave-ci/started"
          install -m 755 scripts/ci-script-started.sh "$RUNNER_TEMP/octave-ci/bin/pnpm"
          echo "OCTAVE_CI_REAL_PNPM=$real" >> "$GITHUB_ENV"
          echo "$RUNNER_TEMP/octave-ci/bin" >> "$GITHUB_PATH"
```

Each emulator step becomes three steps. For first focus (the other two follow the same pattern with ids `e2e` and `wire`, markers `started/e2e` and `started/wire`, and their own names and scripts):

```yaml
      - name: First focus on an Android TV emulator
        id: smoke
        continue-on-error: true
        uses: ReactiveCircus/android-emulator-runner@a421e43855164a8197daf9d8d40fe71c6996bb0d # v2.38.0
        env:
          ANDROID_SERIAL: emulator-5554
          OCTAVE_CI_SCRIPT_STARTED: ${{ runner.temp }}/octave-ci/started/smoke
        with:
          # unchanged
          script: pnpm tv:smoke
      - name: Fail, or allow one more first-focus run if its script never started
        id: smoke-retry
        if: steps.smoke.outcome != 'success'
        env:
          OCTAVE_CI_STEP_OUTCOME: ${{ steps.smoke.outcome }}
          OCTAVE_CI_SCRIPT_STARTED: ${{ runner.temp }}/octave-ci/started/smoke
        run: node scripts/ci-emulator-retry.mjs
      - name: First focus on an Android TV emulator, once more
        if: steps.smoke-retry.outputs.retry == 'true'
        uses: ReactiveCircus/android-emulator-runner@a421e43855164a8197daf9d8d40fe71c6996bb0d # v2.38.0
        env:
          ANDROID_SERIAL: emulator-5554
        with:
          # the same seven inputs as the first attempt
          script: pnpm tv:smoke
```

Order in `tv`: shim step; smoke, its decision, its retry; `- run: pnpm tv:e2e:build`; e2e, its decision, its retry; the upload. This keeps F7 (the first runner line is the first attempt at smoke) and F8 (the first runner line after the e2e build is the first attempt at e2e).

`scripts/ci-script-started.sh` (the shim):

- When `OCTAVE_CI_SCRIPT_STARTED` is set, create that file or leave it when it exists (`scripts/tv-wire.mjs:77-79` starts pnpm again with the variable inherited). If that fails, print an `ERROR ci:` line to stderr and exit non-zero **without starting pnpm**. This is what makes "no file" mean "the script did not start".
- When `OCTAVE_CI_REAL_PNPM` does not name an executable file, print an `ERROR ci:` line and exit non-zero.
- Otherwise `exec "$OCTAVE_CI_REAL_PNPM" "$@"`. With the variable unset (every other step of the job) it only passes through.

`scripts/ci-emulator-retry.mjs` (Node built-ins only; importing it runs nothing):

- `retryDecision({ outcome, scriptStarted, shimFirst })` returns `{ retry, reason }`. `retry` is true only for `outcome === "failure"`, `scriptStarted === false` and `shimFirst === true`.
- `shimIsFirst({ pathValue, shimDir })`: true when the first directory of `pathValue` that holds a file named `pnpm` is `shimDir`.
- CLI: reads `OCTAVE_CI_STEP_OUTCOME`, `OCTAVE_CI_SCRIPT_STARTED`, `RUNNER_TEMP`, `PATH` and `GITHUB_OUTPUT`. `scriptStarted` is whether the marker file exists; a missing marker variable or a missing `started` directory counts as cannot tell.
  - Retry: when `GITHUB_ACTIONS` is `true` only (a developer machine may run other agents' emulators), stop any emulator the failed boot left: `pkill -KILL -f qemu-system`, then `adb kill-server`, each through `PATH` with `execFileSync` and no shell (a shell whose command line holds `qemu-system` is itself matched by `-f`); both may fail, F4. Then print `ci: the emulator never ran the script; running the step once more`, append `retry=true` to `GITHUB_OUTPUT`, exit 0.
  - Otherwise: print `ERROR ci: the step failed after its script started; a started script is never retried` (or the cannot-tell reason) and exit 1. This is what fails the job after `continue-on-error`.

How each case ends:

| First attempt | Marker | Decision step | Retry step | Job |
|---|---|---|---|---|
| success | present | not run | not run | continues |
| failure, script never started | absent | exit 0, `retry=true` | runs once; its result is final | follows the retry |
| failure, script started (any result) | present | exit 1 | not run | fails |
| failure, shim not first on PATH or no `started` directory | unknown | exit 1 | not run | fails |
| cancelled or skipped | any | not run, or exit 1 | not run | cancelled or already failed |

### Hard rules and invariants this task touches

- **"Never skip, weaken, or delete a test to pass a check"** (`AGENTS.md` §Tests). The skip leaves out three jobs only where the change cannot alter what they test (the table in Facts), and it fails closed. The retry never reruns a test that ran. Reviewers should judge the task against this rule first.
- **"Merge only with green CI"** and the required checks of ruleset 26769544. `tv` and `tripwire` can now be green by being skipped. The ruleset itself is not changed.
- **"Pass a playback task only when its wire test passes against Jellyscale."** The `wire` job is skipped only on pull requests with no code change. A playback task's pull request changes code, so its wire test still runs.
- **"Call out changes to invariants, `docs/security.md`, release signing, or CI in the PR."** Required here.
- **"Never change or delete a frozen test."** Item 5; nine frozen files read `ci.yml`.
- **"Never stub a function to make a build pass."** The shim is not a stub: it runs the real pnpm with the same arguments or fails.
- No token, network, playback or code-boundary rule is touched. The new scripts make no network call and print no secret; `OCTAVE_CI_HEAD_SHA` is a commit id.

## Test plan

All new tests are vitest files under `scripts/` (the root suite, `vitest.config.ts`), each test name starting `T1-17 item <n>:`. Manifest runs: `["pnpm", "exec", "vitest", "run", "<file>", "-t", "T1-17 item <n>:"]`. Items 4 and 5 are gates in the manifest (`ci` and `met`).

Each run is red before the implementation: the two `.mjs` modules and the shim do not exist, `ci.yml` has no `changes` job, and `docs/commands.md` lacks the section. Import the new modules inside each test with `await import()`, so a missing module fails only that test.

- **Item 1, `scripts/ci-emulator-retry.test.ts`.**
  - `retryDecision`: all outcomes (`success`, `failure`, `cancelled`, `skipped`, empty, unknown text) times marker present or absent times shim first or not. Exactly one combination retries.
  - `shimIsFirst`: shim directory first; the real pnpm's directory before it; no pnpm on the path.

## Risks and out of scope

Risks:

- **The pull request's own copy of the rule judges it.** On `pull_request`, `ci.yml` and `scripts/ci-device-jobs.mjs` come from the pull request. A pull request that edits them could skip the jobs for itself. This is the trust `ci.yml` already has (any pull request can edit a job), the edit is a non-listed path under the unedited rule, and `checks` runs the item 3 test on the edited files.
- **Item 4 is proven only after the merge.** If skipped jobs did not satisfy the ruleset after all (against F11 and the `dependency-review` precedent), docs-only pull requests would wait for ever. The way out is a pull request that removes the two lines from the three jobs; it changes `ci.yml`, so it runs everything.
- **The item 3 reader also pins** each first attempt's `script:` to `^pnpm [\w:-]+$` (the marker means "started" only for one pnpm command), each retry step to its first attempt (`uses`, `with` block and `ANDROID_SERIAL` line for line), and no `paths`, `paths-ignore` or `branches-ignore` filter under `on:`. The `prebuildInputs()` paths are made repository-relative before the prefix comparison, and the e2e inputs are checked through the exported `e2eSourceHash(root)` on a temp tree, because `isE2eInput` is not exported and no `scripts/tv-*` file may change.
- **The retry path cannot be forced by a test.** It runs for real only when a boot fails. See the optional exercise in Validation commands. If it is not done, the PR lists the live retry as untested.
- **A leftover emulator** (F4) may hold port 5554 or the AVD when the retry starts. The decision step stops it first. If the retry still fails to boot, the job fails as it does today.
- **The shim shadows `pnpm`** for the rest of the `tv` and `wire` jobs. Outside the three first attempts it only passes through. A fault in it fails steps loudly; it cannot make a failed step pass.
- **A boot failure that is not a flake** (a bad image, a broken SDK download) is retried once and fails again, at the cost of one more boot (up to the action's 600 s boot timeout).
- **Cancelled runs** leave not-yet-started device jobs as skipped; see Approach step 1.

Out of scope:

- Merging the two emulator boots (backlog entry 154) and splitting the `tv` job (entry 148); the Product Owner left both out (`tasks/product-owner-log.md` line 291).
- Skipping on other paths (the root markdown files, `.claude/`, `.github/pull_request_template.md`). A later Product Owner pass can widen the list with its own proof.
- Retrying anything in `tripwire` or `checks`, and retrying a failed test anywhere.
- Changing ruleset 26769544 or making `wire` required (T10-01).
- `.github/workflows/dependabot-auto-merge.yml`.
