## Goal

`modules/player` exists as a local Expo module, `@octave/player`, whose JavaScript surface is the PlayerEngine port and nothing else: six functions, one event, and one native view with no props. Kotlin holds the same seam behind an interface, `PlaybackEngine`, that names no Android, Expo, Media3 or OkHttp type, so T8-02 puts Media3 behind it and a Swift engine can mirror it. `apps/tv/src/host/player-engine.ts` turns the module into the core's `PlayerEngine`. Both native modules get a written allowlist, and one test holds each module, its allowlist and `docs/security.md` together.

This task ships **no engine**. With none behind the seam, `initialize` answers `{ probe: "failed" }` ("cannot tell") and a valid launch answers `unsupported-request`. T8-02 passes the Media3 engine to the seam; nothing else here changes then.

## Approach

### The JavaScript surface

Module name `OctavePlayer`. As in the session module (decision 0005, T3-05 amendment), every function takes at most one plain map and resolves one plain map, Kotlin reads the map by hand, and no function rejects on purpose.

| Function | Argument | Resolves |
|---|---|---|
| `initialize` | none | the capability map: `{ probe: "failed" }` or `{ probe: "complete", videoDecoders, audioDecoders, hdr, passthrough }` |
| `launch` | the launch request map (below) | `{}` or `{ error }` |
| `setPaused` | `{ paused: boolean }` | `{}` or `{ error }` |
| `seek` | `{ positionSeconds: number }` | `{}` or `{ error }` |
| `selectTrack` | `{ type: "audio" \| "subtitle", playerId?: number }` | `{}` or `{ error }` |
| `stop` | none | `{}` or `{ error }` |

- Event: `playerEvent`, declared with `Events("playerEvent")`. Its payload is `{ kind, ... }` with one of the six kinds and the port's fields for that kind. One native event with a `kind`, not six, because the port has one subscription (T2-05 D2).
- View: `OctavePlayerView`, no props.
- `error` is one of `PLAYER_ERROR_CODES`. A wrong argument map for `setPaused`, `seek` or `selectTrack` is `unsupported-request`.
- No property, constant, synchronous function, second event or view function.

### The launch request

`launch` accepts exactly these keys.

| Key | Type | Kind |
|---|---|---|
| `kind` | `"original"` or `"hls"` | both |
| `sessionId` | string that `SessionId.parse` accepts | both |
| `startPositionSeconds` | finite number, 0 or more | both |
| `tracks` | list of track maps, at most 256 | both |
| `audioStreamIndex`, `subtitleStreamIndex` | integer, optional (`-1` allowed for subtitles) | both |
| `url` | URL | `original` only |
| `masterUrl`, `serverUrl` | URL | `hls` only |
| `mediaKind` | `"videos"` or `"audio"` | `hls` only |

A track map holds `index` (integer), `type` (`Audio`, `Subtitle`, `Video`), `displayTitle` (string), `external` (boolean) and the optional `codec`, `language`, `title` (strings), `deliveryUrl` (URL), `channels` (integer), `isDefault`, `isForced`, `isHearingImpaired` (booleans): the fields of the port's `MediaTrack`, no other.

Rules, all ending in `unsupported-request` with nothing sent to the engine:

- U0. A missing required key, a key outside the table for the request's kind, a wrong type, a number that is `NaN` or infinite, or an index that is not integral. Numbers arrive as `Double` or `Int`; both are read.
- U1. Every URL is at most 8192 characters, parses with `java.net.URI` (never `java.net.URL`, which K5 refuses), is absolute `http` or `https`, has a host, and has no user info and no fragment.
- U2. Every URL of one request has the same scheme, host (compared in lower case) and effective port.
- U3. An `original` URL's path matches the core's S1 shape, `(/segment)*/Videos/{id}/stream`, with exactly one `Static` parameter (name compared without case) whose value is `true`.
- Strings other than URLs are at most 512 characters.

Not mirrored here, on purpose: the credential-name rule and the base-path rule, which the one client applies to every call an engine sends (`CredentialUrlTest`, `RequestPathTest`), and the master-URL rules and their vectors, which are T8-08's. The reader accepts a well-formed `hls` request; whether an engine plays it is the engine's answer (`unsupported-request` until T8-08).

### The Kotlin seam

Package `dev.octave.player.seam`, plain Kotlin. The frozen JVM tests compile against these names.

```kotlin
enum class PlayerErrorCode(val wire: String) // NETWORK("network") ... UNKNOWN("unknown"), the port's eleven, in its order
class PlayerEngineException(val code: PlayerErrorCode) : Exception(code.wire) // no cause

enum class TrackType(val wire: String) { AUDIO("audio"), SUBTITLE("subtitle") }
enum class MediaKind(val wire: String) { VIDEOS("videos"), AUDIO("audio") }

class MediaTrack(val index: Int, val type: String, val displayTitle: String, val external: Boolean, val codec: String? = null,
  val language: String? = null, val deliveryUrl: String? = null, val title: String? = null, val channels: Int? = null,
  val isDefault: Boolean? = null, val isForced: Boolean? = null, val isHearingImpaired: Boolean? = null)

sealed class LaunchRequest { // toString() is "LaunchRequest([redacted])"
  abstract val session: SessionId; abstract val startPositionSeconds: Double; abstract val tracks: List<MediaTrack>
  abstract val audioStreamIndex: Int?; abstract val subtitleStreamIndex: Int?
  class Original(..., val url: String) : LaunchRequest()
  class Hls(..., val masterUrl: String, val serverUrl: String, val mediaKind: MediaKind) : LaunchRequest()
}
object LaunchRequestReader { fun read(args: Map<String, Any?>): LaunchRequest? } // null is a refusal

sealed class Capabilities { object Failed; class Complete(videoDecoders: List<VideoDecoder>, audioDecoders: List<String>, hdr: List<String>, passthrough: List<String>) }
class VideoDecoder(val codec: String, val hardware: Boolean, val profile: String? = null, val maxBitDepth: Int? = null, val maxWidth: Int? = null, val maxHeight: Int? = null)

sealed class PlayerEvent(val kind: String) {
  class Loaded(val snapshot: PlaybackSnapshot); object FirstFrame; class State(val snapshot: PlaybackSnapshot, val cause: String? = null)
  class TracksChanged(val snapshot: PlaybackSnapshot); class Ended(val reason: String, val snapshot: PlaybackSnapshot? = null); class Error(val code: PlayerErrorCode)
}
// PlaybackSnapshot, PlayerTrack, PlaybackDiagnostics, VideoFacts, AudioFacts: one class per port interface, the port's field names and optionality.
object PlayerEventMaps { fun toMap(event: PlayerEvent): Map<String, Any?>; fun toMap(capabilities: Capabilities): Map<String, Any?> }

interface PlaybackEngine {
  fun capabilities(): Capabilities                       // the port's initialize
  fun setListener(listener: ((PlayerEvent) -> Unit)?)    // the port's subscribe
  fun launch(request: LaunchRequest)
  fun setPaused(paused: Boolean)
  fun seek(positionSeconds: Double)
  fun selectTrack(type: TrackType, playerId: Int?)
  fun stop()
}
fun interface SessionCheck { fun holds(session: SessionId): Boolean }

class PlayerSeam(engine: PlaybackEngine?, sessions: SessionCheck, emit: (Map<String, Any?>) -> Unit) {
  fun initialize(): Map<String, Any?>
  fun launch(args: Map<String, Any?>): Map<String, Any?>
  fun setPaused(args: Map<String, Any?>): Map<String, Any?>
  fun seek(args: Map<String, Any?>): Map<String, Any?>
  fun selectTrack(args: Map<String, Any?>): Map<String, Any?>
  fun stop(): Map<String, Any?>
}
```

`PlayerSeam` behaviour:

- `initialize`: with an engine, `toMap(engine.capabilities())` and the listener is set to `emit(toMap(event))`; with none, or when the engine throws, `{ probe: "failed" }`.
- `launch`, in this order: read the map (refused: `unsupported-request`); `sessions.holds(request.session)` (false: `session-ended`); no engine: `unsupported-request`; `engine.launch(request)`.
- `setPaused`, `seek`, `selectTrack`: a bad map or no engine is `unsupported-request`; `seek` needs a finite position of 0 or more.
- `stop`: with no engine `{}`, so a teardown always completes.
- Every call catches `Throwable`: a `PlayerEngineException` gives its code, anything else `unknown`. Nothing of the throwable but the code is read.
- `toMap` writes each event from its typed fields. Strings in a snapshot (`decodeLabel`, a track's `title` and `language`, codec names) are cut to 256 characters; `reason` and `cause` outside the port's values are written as `error` and left out. No type has a URL field, so an engine cannot hand one to an event.
- `SessionId` is the only type the seam takes from `modules/session`.

Outside the seam, in `dev.octave.player` (Android and Expo types allowed):

- `OctavePlayerModule`: the definition above. It builds `PlayerSeam(null, RegistrySessionCheck, { sendEvent("playerEvent", it) })` and runs each call on its own single-thread scope, never on Expo's shared modules queue, then resolves the promise; a last guard resolves `{ error: "unknown" }`. T8-02 replaces `null` with its engine, which marshals to the thread Media3 needs.
- `RegistrySessionCheck`: `SessionCheck { SessionRegistry.holds(it) }`.
- `OctavePlayerView`: an `ExpoView` that adds one `SurfaceView` filling it and registers a `SurfaceHolder.Callback` with `VideoSurfaceSlot`.
- `VideoSurfaceSlot`: holds the current `Surface?` and one listener an Android engine sets (T8-02). It is the only link between the view and an engine; React is not on that path.

`modules/session`: `SessionRegistry` gains `fun holds(session: SessionId): Boolean = sessions.containsKey(session)`, public. It returns no entry, origin or header. `build.gradle` of the player: `implementation project(':octave-session')`, the JUnit BOM, no other dependency.

### The adapter

`apps/tv/src/host/player-engine.ts` exports `createPlayerEngine(native: PlayerNative): PlayerEngine`, as `transport.ts` does for the session module.

- `initialize`: `readCapabilities(await native.initialize())`; a rejection is `{ probe: "failed" }`.

### Decision log

- **D1. No engine and no Media3 here.** Settled by `tasks/product-owner-log.md:93`. The seam's answers with no engine (`probe: "failed"`, `unsupported-request`) are the port's own values for "cannot tell" and "the engine refused the request", they are tested, and they stay as the answers when an engine cannot be created. They are behaviour, not a stub written to pass a build.
- **D2. Six functions and one event.** The acceptance names six methods; the port's seventh member, `subscribe`, is Expo's event emitter over `playerEvent` (T2-05 D2). The allowlist test states the mapping.
- **D3. "Exactly" four session methods, with two pending.** The acceptance names the full session surface, but `restoreSessions` and `sessionEnded` need T4-05's store. The allowlist is the five names; `pending` names the two not built; defined must equal allowed minus pending. Building them here would be T4-05's work. If the Product Owner reads item 1 as requiring all five to exist now, T8-01 waits for T4-05.
- **D4. One map in, one map out; errors are values.** The same reasons as the session module: Expo's converter never holds a typed value it could quote in an error, and no native message reaches JavaScript.
- **D5. `SessionRegistry.holds` is added.** Without it the seam cannot tell an unknown session until an engine's first request fails, and item 3 would have no behavioural test. It is a Kotlin function, not a JavaScript method, so the session surface of decision 0005 is unchanged. It answers a boolean for an id 128 random bits long.
- **D6. The engine interface names no OkHttp type.** An engine takes the `SessionId` from the request and asks `OctaveHttp.callFactory` itself (T8-02). A Swift engine does the same with its own client.
- **D7. The surface reaches an engine natively.** `VideoSurfaceSlot` is Android-only and outside the mirrored interface; a Swift engine has its own layer host.
- **D8. The view has no props at all.** The player screen's chrome is native (T8-04), so React only places the view.
- **D9. Native URL checks are U1 to U3 only.** The full Kotlin mirror of the master-URL rules is T8-08's, against the shared vectors; credential names and the base path are the one client's.
- **D10. The app does not construct the engine yet.** `createPlayerEngine` is built and tested; the composition root uses it in T8-03 ("launches the module").
