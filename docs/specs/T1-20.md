- Model: opus (spec). Implementer: **`implementer`**. The work is a Node script, its tests, a fixture, and two docs. Nothing under `modules/`, `apps/tv/android/`, or the PlayerEngine port changes, so `touchesNative` is false.

## Goal

Give the owner numbers before any part of the pipeline is cut. This task delivers three things:

1. A read-only script, `scripts/pipeline-cost.mjs`. For each merged task it sums the wall time and the tokens of every stage from the Workflow tool's journals, and prints one line per task and stage.
2. A test that runs the script on a recorded, scrubbed journal. It proves the numbers, and it proves that no prompt text, credential, address or local path reaches the output.
3. A report, `docs/research/pipeline-cost.md`. It holds the numbers for the tasks merged so far, and it proposes lighter pipelines for small low-risk tasks. For each option it says what the option saves and which check it gives up. The owner chooses.

Nothing in `.claude/workflows/`, `.claude/agents/`, `.claude/skills/`, `WORKFLOW.md` or `AGENTS.md` changes.

### What the journals do not record

The script reports these gaps, and the report states them.

- **The coordinator session.** Its own model calls, which start each run and read its result, are in the session transcript (`~/.claude/projects/<slug>/<session>.jsonl`), not in any journal. They are not counted.
- **Time between runs.** This covers a resumed task waiting for the owner, a ruling, or a parked question. Only each run's `durationMs` and each agent's `queuedAt` / `startedAt` / `durationMs` exist.
- **Phase timing.** Phase entries carry no time. A stage's wall time is the sum of its agents' `durationMs`.
- **Who waited for CI.** On T9-07 the ship agent's `durationMs` was 5,344,874 ms (89 min) of a 113-min run. Its transcript has 13 gaps of 1 to 10 minutes between lines with no model call in them. That this idle time is the agent waiting for CI and the auto-merge is **inferred**, not recorded. CI minutes themselves are not recorded.
- **Human time.** The owner's reviews, approvals, device gates and veto passes.
- **The token split in the journal.** The journal gives one `tokens` number per agent, the end context. The split into input, cache write, cache read and output is only in the transcripts.
- **Money.** There is no price per token. `WORKFLOW.md` §Model routing lists input and output prices only, not cache prices.
- **Work outside a run.** The merge of a task shipped after its run, and tasks with no journal (the two groups above).
- **Retention.** Claude Code may delete old session folders under its `cleanupPeriodDays` setting. `~/.claude/settings.json` does not set it. The default retention (believed to be 30 days) is **unverified** here. So the report's numbers are a snapshot and must be taken while the transcripts exist.

## Approach

### What the script reads (allowlist)

- **From each journal:**
  - `workflowName`, `status`, `durationMs`;
  - `args.task`, `args.tasks`;
  - `result.merged` (the array's `task` and `outcome` only, or the boolean), `result.task`;
  - and from each `workflowProgress` entry: `type`, `phaseTitle`, `label`, `model`, `state`, `durationMs`, `tokens`, `agentId`.
  - Nothing else is copied into a row. `label` is read only to match it against the stage table and the task-id pattern, and is never printed.
- **From each transcript line:** `message.id` and the four numeric fields of `message.usage`:
  - `input_tokens`;
  - `cache_creation_input_tokens`;
  - `cache_read_input_tokens`;
  - `output_tokens`.
  - Each `message.id` is counted once. A line without `message.usage` is skipped. `content`, `cwd` and the other fields are never read into a value.
- **Printed values:**
  - The task id is printed only when it matches `/^[A-Z]+\d+-\d+$/`.
  - The model is printed only when it matches `/^claude-[a-z0-9-]+$/`.
  - Any other value is dropped, so a malformed journal cannot carry text out.

### Finding the files

- The script takes `--projects <dir>`, which can be given more than once. Without it, the default is `path.join(os.homedir(), ".claude", "projects")`.
- It reads `<projects>/*/*/workflows/wf_*.json`, and keeps a journal whose `workflowName === "task"`.
- A transcript is `<session>/subagents/workflows/<journal basename without .json>/agent-<agentId>.jsonl`. When it is missing, the token fields are `n/a`.
- A file that does not parse is reported on stderr as `ERROR pipeline-cost: wf_<id>.json unreadable`, and the run goes on.
- **No path is ever printed.** The projects folder's own path holds the account name.
- **Zero `task` journals:** `ERROR pipeline-cost: no task journals read`, exit 1. This follows the repository's rule that a check fails on zero inputs (`WORKFLOW.md` §Mechanical enforcement backlog, the paragraph at line 197).

### Attribution

1. **Task.** Take the first `/\b[A-Z]+\d+-\d+\b/` match in the agent's `label`.
   - With no match, when the run has exactly one task (`args.task`, or `args.tasks` of length 1), use that task.
   - Otherwise the agent goes to the run's `unattributed` bucket, which is counted in the header and never dropped silently.
2. **Merged.** A task counts as merged when any journal has either:
   - `result.merged` as an array holding `{task, outcome: "merged"}`, or
   - `result.merged === true` with `result.task` naming the task.

   `--merged <ID>[,<ID>…]` adds tasks the caller knows were merged after their run; their lines carry `\tmerge=unrecorded`. Only merged tasks get lines. Every journal that touched a merged task counts toward it, whatever that run's own outcome: stopped, resumed, killed, or `error` and `progress` agents included. That is the true cost of getting the task merged.
3. **Stage.** Strip the task id and any trailing `(…)` suffix from the label, lower-case it, and look the verb up:

   | Label verb | Stage |
   |---|---|
   | `sync` | `Sync gate` |
   | `red gate` | `Red gate` |
   | `frozen gate` | `Frozen gate` (every phase) |
   | `green gate` | `Green gate` |
   | `fixtures down` | `Fixtures down` |
   | `ruling history`, `ruling log` | `Ruling log gate` |
   | `owner ruling`, `rule on frozen tests` | `Ruling` |
   | `fix ci` | `Fix CI` |
   | anything else | the agent's `phaseTitle` (`Spec`, `Check`, `Tests`, `Implement`, `Review`, `Verify`, `Ship`) |
   | no `phaseTitle` and no match | `Other` |

   So `revise` and `spec revision` count in Check, `follow-ups` and `verify after review` in Review, and `ship` in Ship. `stageOf({label, phaseTitle})` is exported and pure.

### Output

- **Header:** first, one header line with counts only: `# journals=<n> task-runs=<n> merged-tasks=<n> unmerged-tasks=<n> agents=<n> unattributed=<n> no-transcript=<n>` (`unmerged-tasks` counts tasks with runs but no merge, so none is dropped silently).
- **Stage lines:** then, per merged task in task-id order (numeric within the phase), one line per stage that has agents, in this order: `Spec, Sync gate, Check, Ruling, Ruling log gate, Tests, Red gate, Implement, Frozen gate, Review, Green gate, Verify, Ship, Fix CI, Fixtures down, Other`. Then a `Total` line. Each line has tab-separated fields:

  `<task>\t<stage>\tagents=<n>\twall_ms=<n>\tinput=<n|n/a>\tcache_write=<n|n/a>\tcache_read=<n|n/a>\toutput=<n|n/a>\tcontext=<n>\tmodels=<model>[,<model>…]`

  - `wall_ms` sums the agents' `durationMs`.
  - The four token fields sum the transcripts' usage. A field is `n/a` only when no agent of that line has a transcript. When some have one and some do not, the field sums those that have one, and the line adds `\tpartial=<missing count>`.
  - `context` sums the journal's `tokens`.
- **`--json`:** prints `{header, rows}` with the same fields as numbers (or `null` for `n/a`).
- **Exit code:** 0 when at least one `task` journal was read, else 1.
- **Size and style:** the file stays under 400 lines. It uses only `node:` built-ins, two-space indentation and semicolons, like the other `scripts/*.mjs`.

### The report

`docs/research/pipeline-cost.md` is built from `node scripts/pipeline-cost.mjs --json` on the owner's machine. The implementer runs it read-only and pastes only task ids, stage names, models and numbers. It has these headings:

- **`## How the numbers were taken`**: the date, the command, the journal count, the date range, and the field meanings, including that `context` is end-context size and not usage.
- **`## What the journals do not record`**: the list in this spec's Facts.
- **`## Cost per merged task`**:
  - One row per merged T-task (the 30 in Facts): task, a risk proxy, agents, total wall time, and total input, cache write, cache read and output.
  - The run passes `--merged T3-02,T3-03,T3-23` (and any other task `pnpm task list --status done` gives that has runs but no merge record), so those rows carry their recorded runs, marked "merge not recorded".
  - Then a line lists the done tasks with no journal at all as "not recorded".
  - P-tasks are left out of the table, because they ran a pipeline without tests-first. One sentence gives their count.
- **`## Cost per stage`**: one row per stage, giving its share across the T-tasks: the sum, the median per task, and the share of total wall time and of total tokens. It shows tasks with no high-risk path apart from tasks with one.
- **`## Options for small low-risk tasks`**:
  - First, a definition of "small low-risk" the data supports. The proposed one is: risk `routine`, no path the workflow sends to `guardian`, nothing native, and at most four acceptance items.
  - Then a table with the columns `Option | Saves | Gives up | Rule or check it touches`. `Saves` gives a measured number, in minutes and tokens per task from the tables above. The implementer covers at least these candidates, and drops none without saying why:
    1. Run the mechanical gates (sync, red, frozen, green, fixtures down) without their own agent each. In the T9-07 run each gate agent wrote about 17k to 37k tokens of cache for a 5 to 10 s command; on that run the gates were 6 of 12 agents. This gives up none of the checks, only the separate relay.
    2. Hand the CI wait in Ship to a cheaper watcher (the Haiku `scout` that `WORKFLOW.md` already names for watching PRs), or to a polling loop. This gives up nothing check-wise.
    3. Skip the separate spec check for small routine tasks. This gives up the fresh-context spec review (`WORKFLOW.md` §2a).
    4. Write the spec of a small routine task with Sonnet instead of Opus. This gives up the stronger refiner.
    5. For a docs-only or process-docs task, fold Tests into Implement. This gives up frozen failing tests (§2b) for that task.
    6. Any further option the numbers suggest.
- **`## For the owner to decide`**:
  - It says plainly that this task changes no stage, and that the owner picks.
  - It gives a recommendation with its reason.
  - It says that a chosen option becomes its own task through a Product Owner pass.

Money is given only if the implementer cites Anthropic's current price page for every token class used, cache write and cache read included. Otherwise the report gives tokens only, and never presents `context` as cost. The report holds no path, address, account name or prompt text. It must not use the desktop stack's name (`pnpm lint:ghost-terms`); the tag name `desktop-tauri-final` alone is allowed.

## Risks and out of scope

- **Retention.** Transcripts may be pruned (`cleanupPeriodDays`, default **unverified**). Run the report now. If a transcript is gone, the line shows `n/a` or `partial=`, never a silent zero.
- **Journal format drift.** The journal format belongs to the Workflow tool, not to Octave. A future format change makes stages land in `Other` or agents in `unattributed`, which the header counts. The script does not guess.
- **Privacy.**
  - The script runs only on the owner's machine. Its input folder holds the account name and full prompts.
  - The allowlist, the value patterns and the "no path printed" rule are what keep that out of the output, and item 2's canaries test them.
  - The report and fixture must also hold no address, credential or owner name (`AGENTS.md` Tasks: "Never commit a server address, a credential, or the owner's name").
- **The numbers undercount.** The coordinator session, the owner's time and CI minutes are not in the journals. The report says so next to its totals.
- **Out of scope:**
  - any change to the pipeline, the agents, the models or `task.js` (item 4);
  - pricing in money without a cited source;
  - P-task analysis beyond a count;
  - adding a `pnpm` alias or a CI job for the script.
