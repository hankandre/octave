## Approach

### Shape

- **One app, generated native project.** `apps/tv/android` comes from `expo prebuild --clean` every time and is git ignored. Native settings change only through `app.config.ts` and config plugins. No hand-edited file lives under `apps/tv/android`.
- **Where Kotlin lives.** Native modules will be workspace packages under the repository's `modules/` (`modules/player` in T8-01, the HTTP module in T3-03), each a dependency of `@octave/tv`, which autolinking finds by dependency resolution (Expo's autolinking guide, step 4). This task creates none: a module with no purpose would be a stub, and a native module method is an architecture change. The only Kotlin here is the app's JVM tests under `apps/tv/native/app/src/test/java/`, added to the generated `:app` project's `test` source set by `with-app-jvm-tests.js`.
- **The application ID is defined once.** `app.config.ts` starts with `import "tsx/cjs";` (Expo's documented route; it resolves from `apps/tv` to the root's `tsx` 4.23.15 by Node's parent-directory lookup, so `apps/tv` does not list `tsx`, and `expo config --json` prints the core's ID) and imports `APP_NAME` and `ANDROID_APPLICATION_ID` from `../../packages/core/src/domain/app-identity`. Nothing else in `apps/tv`, `scripts/` or the plugins writes the ID as a literal except the item 1 and item 3 test expectations, which exist to catch a change to it. If `tsx/cjs` fails under Expo's loader, fall back to `app.config.js` with a plain `require` of the `.ts` file (works in Node 26) and record which was used.
- **TV is on by configuration**, not by environment: the plugin entry is `["@react-native-tvos/config-tv", { "isTV": true }]`, so a build cannot silently drop TV when `EXPO_TV` is unset. `androidTVRequired` stays false (phones are T15). No `androidTVBanner`: the banner is the owner's in T11-01, and the app starts by intent without one.
- **Build settings.** `expo-build-properties`: `android.buildArchs: ["arm64-v8a", "x86_64"]`. New Architecture and Hermes stay on (the defaults). minSdk and targetSdk stay at the SDK 58 template's values (24 and 36 in the spikes). The release APK is signed with the template's debug keystore; real signing is T11.

### First focus (item 4)

The oracle, in `scripts/tv-first-focus.mjs`:

1. Require `ANDROID_SERIAL`; refuse to run without it, even when one device is attached, and never write it to disk or to a log. There is no other way to choose a device.
2. `adb install -r` the APK; clear logcat.
3. Check `cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.LEANBACK_LAUNCHER <id>` names an activity of the app, then start that resolved component as a launcher does, with `am start -a android.intent.action.MAIN -c android.intent.category.LEANBACK_LAUNCHER -n <component>`. (An implicit `am start ... -p <id>` answers `START_INTENT_NOT_RESOLVED`, result code -91, on the API 36 emulator, because an implicit activity start also needs `CATEGORY_DEFAULT`, which a launcher filter does not carry.) The ID is read from the identity file, not written in the script.
4. Send no key. Wait up to 30 s for a focus line (tag `ReactNativeJS`), wait 1.5 s more for the launch transition to end, and save `adb exec-out screencap -p` of the first screen to `release-evidence/tv/first-screen.png` (note 11; the job uploads it with the transcript).
5. Write a marker with `log -t OCTAVE_PRESS "1 RIGHT"`, send one `input keyevent 22`, wait up to 5 s.
6. Pass only if `tile-0` was focused before the marker and `tile-1` is the first focus line after it. Print the transcript on failure, with `ERROR tv focus:` and the reason on one line.

How the screen gets focus without a press is the implementer's to find, in this order, stopping at the first that passes on the emulator:

1. `hasTVPreferredFocus` on `tile-0` (react-native-tvos sets focusable-in-touch-mode and requests focus).
2. A `requestTVFocus` call on `tile-0`'s ref after layout, and again on the navigator's screen-focus event.
3. `TVFocusGuideView` with `autoFocus` around the row.

All three are react-native-tvos APIs that also exist on tvOS. **Result (2026-11-21): the first route passes.** With `hasTVPreferredFocus` on `tile-0`, `pnpm tv:smoke` passed three launches in a row on an API 36 Android TV x86_64 emulator, then three more after the screenshot change. With the prop removed in a scratch build, the same run failed with `ERROR tv focus: the first focus (tile-0) came only after the press: a priming press`, the spike's finding 6, so the oracle catches the real failure. The spike's rail needed the press though it set the same prop; a likely difference is that its preferred item sat inside a `TVFocusGuideView` with `autoFocus` (**[unverified]**). No native change was needed. ## Risks and out of scope

Risks:

- **First focus may need native code.** The spike needed a priming press on this version. The spec orders three shared-TypeScript routes and stops before a native one.
- **pnpm isolated installs with React Native libraries.** Documented fallback: the hoisted linker.
- **Audit at moderate over a much larger tree.** May block the pull request on an advisory nobody here can patch; the rule is to stop and report.
- **TypeScript 7 against Expo's and React Native's types.** Fallback inside the same script, recorded.
- **Build time and runner disk.** A cold React Native release build plus an emulator in one job; the Gradle cache and a 60-minute limit bound it. If the job exceeds 40 minutes warm, log a backlog line to split build and emulator jobs.
- **KVM on the hosted runner**, and the availability of the API 36 Android TV x86_64 system image to the action. If the image is missing, use the newest Android TV x86_64 image `sdkmanager --list` offers and record the level.
