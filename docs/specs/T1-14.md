# T1-14: Make the task workflow hold up on a resumed branch, a wrapped gate result and leftover fixture servers

- Domain: Process (`DOMAINS.md` §Process and Workflow: the rule files, `tasks/`, `.claude/`, CI, and the checks in `scripts/`).
- Model: opus (spec). Implementer: **`implementer`**. The work is Node and workflow JavaScript only. Nothing under `modules/`, `apps/tv/android/`, or the PlayerEngine port changes, so `touchesNative` is false.
- Depends on: T1-12 (done on origin/main; `pnpm task show T1-12` gives status `done`, passes `true`, commit 1da8f94).
- Risk: routine. No playback, server, token, or native change, so no Jellyscale wire test applies.
- Takes backlog entries 201, 202 and 203 (`tasks/backlog.jsonl`), each already marked `taken_by: "T1-14"`.

## Goal

The task workflow (`.claude/workflows/task.js`) has three faults, and each one cost a run on 2026-11-22 (`tasks/product-owner-log.md` line 164). This task fixes all three:

1. **Resumed branches.** A resumed task branch is brought up to date by a rebase onto `origin/main`, never by a merge, and its freeze commit stays first. A branch that already holds a merge of main is stopped, and the message names the merge commit.
2. **Wrapped gate output.** The frozen-test gate reads check-flow's `--json` result from relayed output that has other text around it. It gives up as unreadable only when the output holds no result object at all.
3. **Leftover fixture servers.** When a task ends, whatever the outcome, the workflow brings down the fixture servers that its own worktree started and reports this in the task's result. It never stops another checkout's Compose project.

## Approach

1. **Readable gates first (item 2).** Write the scanner as a small loop with no regular expression over JSON:
   - Treat each `{` in the output as a candidate start. String state starts as "outside" at each candidate and is never carried over from prose, so a stray `"` in a log line cannot hide the result. From the candidate, track depth and string state (a `"` toggles the string state unless escaped, and `\` escapes the next character) until depth returns to 0.
   - Try to parse that span. On success and when it passes `isResult`, record it and continue after its end. Otherwise (it does not parse, or it parses but is not the result, such as an outer wrapper like `{"stdout": {…}}`) continue at the next character, so objects nested inside it are still tried.
   - Return the last recorded object that passes `isResult`.

   Keep `unreadable()` and the retry in `runGate` unchanged.
2. **Branch sync (item 1).**
   - Write `branch-sync.mjs` with the order in the Acceptance table. Every `git` call goes through `execFileSync('git', ['-C', repo, ...])` or `spawnSync`, never a shell. Pass `-c rebase.autoStash=false` so a user's config cannot turn on a stash. Use `git rebase --abort` only to undo the script's own rebase, never `reset --hard`.
   - Output: `{ok, task, base, rebased, before, after, merges: [{sha, subject}], freeze, freezeFirst, first, missingWorktree, problems}` (`first` is the sha of the branch's first commit). ERROR lines go to stderr. Exit 0 when ok, 1 otherwise.
   - In `task.js`, after `if (!skipSpec) { … }`, add `const sync = await runGate(syncCommand, \`sync ${task}\`, skipSpec ? 'Check' : 'Spec', decideSync)`. `syncCommand` is `` `mise exec -- node ${main}/.claude/workflows/branch-sync.mjs --repo ${worktree} --task ${task}` ``. The script skips the freeze check when the branch has no manifest (a preFlow branch). Then return `result('denied', …)` on denied and `result('blocked', sync.detail)` unless the action is `pass`, and log `rebased onto origin/main` when it did.
   - A fresh task is a no-op: the spec agent made the worktree from `origin/main`.
3. **Teardown (item 3).**
   - Write `fixtures-down.mjs`. Then add the TEARDOWN block and change the loop to `const out = await withTeardown(() => runTask(...), () => tearDownFixtures(task, root))`. Keep the line `if (STOP_OUTCOMES.includes(out.outcome)` and add `|| (out.fixtures && out.fixtures.denied)`.
   - `tearDownFixtures` catches its own errors, including a `taskPaths` throw for a bad id, and returns `{stopped: [], detail}`. The teardown therefore never throws or changes an outcome.
   - Leave the Ship prompt's worktree removal as it is. The teardown computes the project name from the path string and uses the main checkout's compose file, so it does not need the worktree.
4. **Docs (item 4).** Add the WORKFLOW.md bullets and the ship skill line.
5. Run `mise exec -- pnpm check` and `node --test .claude/workflows/task.test.mjs`. Then run the one real teardown check by hand (see Validation).

Hard rules and invariants this task touches. All are process rules; no playback, token, or network rule applies:

- **Never run `git stash` or `git reset --hard`.** The sync forces `rebase.autoStash=false`, refuses a dirty tree when a rebase is due, and undoes only its own rebase with `rebase --abort`.
- **Rebase your own unmerged PR branch, then `git push --force-with-lease`; never force-push another agent's branch.** The sync rewrites only the task's own branch in its own worktree. Ship already pushes with `--force-with-lease`.
- **Stop only processes you started.** The teardown stops only the Compose projects whose name is the hash of this task's worktree path. It never uses `pkill`, `killall`, or `docker rm` on other names.
- **Never change or delete a frozen test.** The sync never edits files. A rebase conflict aborts instead of being resolved, so frozen blobs keep their ids. Test (1) of row 1 checks this.
- **When a command is denied, stop and report it.** A denied sync gives outcome `denied`. A denied teardown stops the batch.
- **`pnpm lint:flow` and the frozen-test gate.** check-flow already skips merges (`rev-list --no-merges`) and reads CI's merge ref (`HEAD^2`). This task does not change check-flow. Merge detection lives in the sync step, so CI's pull-request merge ref is never flagged.
- **Model routing and the three `STOP_OUTCOMES`.** These are unchanged.

## Interfaces the frozen tests call

The tests are frozen before the implementation exists, so these shapes are fixed here:

- **`branch-sync.mjs` CLI:** `node .claude/workflows/branch-sync.mjs --repo <dir> --task <ID> [--base <ref>] [--no-fetch]`. It prints one JSON line on stdout and ERROR lines on stderr, and exits 0 when `ok`, 1 otherwise. Output:

  ```ts
  { ok: boolean, task: string, base: string, rebased: boolean,
    before: string | null, after: string | null,
    merges: { sha: string, subject: string }[],
    freeze: string | null, freezeFirst: boolean | null,
    missingWorktree: boolean, problems: string[] }
  ```

  `merges[].sha` is the full sha. Each problem about a merge contains its first 12 characters.
- **`decideSync(gate, final)`** returns one of:
  - `{action: 'pass', detail, rebased}`;
  - `{action: 'retry', unreadable: true, detail}` (when `final` is false);
  - `{action: 'blocked', detail}`, where `detail` joins the script's problems, or reads "the branch sync gave no readable result twice" when `final` is true.

  Its result shape is `typeof rebased === 'boolean' && Array.isArray(problems)`.
- **`fixtures-down.mjs` exports:**
  - `projectNameFor(path: string): string`.
  - `tearDown({worktree, composeFile, exec, exists?, realpath?})` returns `{ok, worktree, projects: string[], stopped: string[], problems: string[], note?: string}`.
  - `exec(file: string, args: string[])` returns `{status: number | null, stdout: string, stderr: string, error?: {code: string}}`, shaped like `spawnSync`'s result. Docker is missing when `error.code === 'ENOENT'`: `ok: true`, `stopped: []`, and `note: 'docker not found'`.
  - `exists` and `realpath` default to `existsSync` and `realpathSync`.
  - The CLI prints `JSON.stringify(tearDown(...))` and exits `ok ? 0 : 1`.
- **`decideTeardown(gate)`** takes a gate output and returns `{stopped: string[], detail: string}`:
  - `detail` reads `stopped <names>`, `none running`, `docker not found`, or the problems joined.
  - On unreadable output it returns `{stopped: [], detail: 'the fixture teardown gave no readable result'}`.
  - It never throws.

  Its result shape is `Array.isArray(stopped) && Array.isArray(problems)`.
- **`fixturesDownCommand({main, worktree})`** returns ``mise exec -- node ${main}/.claude/workflows/fixtures-down.mjs --worktree ${worktree} --compose-file ${main}/tests/integration/docker-compose.yml``.
- **`withTeardown(run, teardown)`** is `async`:
  - It awaits `run()`. A throw becomes `{outcome: 'failed', detail: <message>}`.
  - It then awaits `teardown()` exactly once, which returns `{stopped, detail, denied?}`.
  - It returns the run's result with `fixtures` set to the teardown's return.
  - If `teardown` itself throws, it sets `fixtures: {stopped: [], detail: <message>}`.

## Risks and out of scope

- **Allowlist (unverified).** No repository settings file holds the permission allowlist, so it is not verified that gate agents may run `mise exec -- node <main>/.claude/workflows/*.mjs`. A denied teardown stops every batch; confirm on the first run after this merges.
- **Crashed runs (out of scope).** A run killed before the loop reaches the teardown still leaves its servers. Fixed ports for each checkout and a free-port choice are T3-27 (backlog entry 185), and the Product Owner logged the overlap as intended.
- **Other teardown paths (out of scope).** Servers that the coordinator or a human started outside a run are stopped only when they run under this worktree's project name.
- **A symlinked worktree path.** The project name is hashed from the real path when the checkout ran `fixture:up`. Once the worktree is deleted, only `path.resolve` is available, and through a symlink it gives a different name. The teardown then finds nothing and reports `none running`, so nothing is wrongly stopped. Worktrees under `/home/handre/Code/` have no symlink today.
- **The fake-Docker tests cannot prove the real teardown.** The real check in Validation, bringing this worktree's own servers up and then running the script, is the evidence. If it cannot run (for example because another project holds the ports), the PR lists item 3's real-Docker path as untested.
- **`down -v` on a parked or blocked task** removes that worktree's fixture volumes. A resumed run's `pnpm tv:wire` finds the servers unhealthy and runs `fixture:up` and `fixture:setup` again (`scripts/tv-wire.mjs:77-83`). `setup-servers.sh` reuses the passwords saved in `.credentials` for a fresh server (`saved_value`). This matches what `pnpm fixture:down` does today. It is slower, not broken. Unverified on a real resumed run.
- **A freeze commit that is not first.** T3-19 shows a branch can carry commits before its freeze commit, such as a test fix for another task or a docs note. The sync keeps such a branch's order and reports `freezeFirst: false` rather than blocking it, and it never reorders commits to move the freeze commit first.
- **Changes on main that an agent needs mid-run.** An implementer that needs newer main code can no longer merge it. It returns a blocker, and a rerun with `from` resyncs. This is slower but keeps PRs mergeable under the rebase-only rule.
- **The sync fetches from `origin`.** This is a git network call to GitHub, the same one the Spec step already makes. It opens no new network surface in the app.
- **`readGate` with a scanner** could in theory pick a later result-shaped object that the relaying agent added, for example quoted text. The shape checks and "last result wins" match today's last-line rule. A forged result needs a misbehaving gate agent, which is outside this task's threat model.
- Changing `product-owner.js`, `check-flow.mjs` or `check-red.mjs` is out of scope.

Issues:

1. **Medium.** The scanner misses a result nested inside a non-result object. Approach step 1 says to "continue after its end" once any span parses. Suppose the relay wraps the result, for example `{"stdout": {…check-flow…}}`. The outer object fails `isResult`, the inner result is never tried, and the gate stops as unreadable. The acceptance item allows an unreadable stop only when the output holds no result object. The fix: skip past a span only when it passes `isResult`. Otherwise resume at the next character, so its inner objects are tried. Add a test for one wrapped form.
2. **Medium.** The spec does not say what happens when the post-rebase check (step h) fails after a clean rebase. A freeze commit can edit an existing test, and the test writer is told to update tests the spec changes. If main changed the same file, the rebase can 3-way merge cleanly and change a frozen blob. At that point `rebase --abort` no longer applies, and `reset --hard` is forbidden. Say what the script does: report a problem that names the moved paths, and either leave the rebased branch for the blocked task or restore the old tip without `reset --hard`, for example `git reset --keep <before>` or `git update-ref` while the tree is clean. Add a test for this case.
3. **Low.** Without `root`, `taskPaths` gives a relative worktree (`../octave-<ID>`) and `main` = `.`. Both scripts then resolve paths against the gate agent's cwd. The name still matches only when that cwd is the main checkout. A mismatch is safe, because it reports `none running`, but it is silent. Either resolve against the main checkout or note the assumption, and include a relative `--worktree` in a test.
4. **Low.** The teardown `agent()` call runs outside `runTask`, and `meta.phases` must stay fixed. Name the phase it uses, such as `Ship`.
5. **Low.** The gate prompt says "change nothing", but the sync command rebases. A cautious gate model may refuse or ask. Consider saying that the command itself may change the branch, without changing `const gate`'s text, which the tests pin. One way is to put that note in the command label or in a separate sync gate.
6. **Low.** A resumed run blocks when an earlier agent left tracked files modified and the branch is behind. The block is correct under the no-stash rule, but the `blocked` detail should say to commit or discard the changes and rerun.
7. **Low (unverified).** No repository settings file holds the permission allowlist. Whether gate agents may run `mise exec -- node <main>/.claude/workflows/*.mjs` is not verified. A denied teardown stops every batch, so confirm this on the first run after merge.
