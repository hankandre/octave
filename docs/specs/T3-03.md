## Goal

A native module, `modules/session`, owns the one OkHttp client. Kotlin code gets a call factory for a session id and can do nothing else with the client: the client adds the `Authorization` header only for that session's origin, refuses every other origin before a byte is sent, follows no redirect, uses no proxy, stores no cookie, refuses a URL that carries a credential, allows plain HTTP only to loopback and private-LAN hosts, and hands back an answer that does not carry the header. T3-05 (the transport), T3-11 (artwork) and T8-01 and T8-08 (the player) build on this client and add no second one. This task adds **no JavaScript method and no event**.

A second `start(inetAddress, port)` exists (`:299`). `requestCount` is at `:126`; `RecordedRequest.target` is the request target as sent (`RecordedRequest.kt:62`).
- **`Request.Builder`'s copy constructor is `internal`** (`Request.kt:210`); the only way to copy a request with a tag or a header is `Request.newBuilder()` (`:115`). The same holds for `Response.newBuilder()` (`Response.kt:248`).
- **A response carries the request that was sent.** `Response.request` is a public property (`Response.kt:55`), as are `networkResponse` (`:90`) and `priorResponse` (`:103`), each with its own `request`. `Request.toString()` masks the values of `Authorization`, `Cookie`, `Proxy-Authorization` and `Set-Cookie` (`Request.kt:186`, `internal/-UtilCommon.kt:191-195`) and `Response.toString()` prints only the protocol, code, message and URL (`Response.kt:351`), but `request.header("Authorization")` returns the value.
- **Follow-ups that survive `followRedirects(false)`** (`internal/http/RetryAndFollowUpInterceptor.kt:230-292`): a 503 whose `Retry-After` is `0` is sent once more whatever `retryOnConnectionFailure` says; a 408 is re-sent only when `retryOnConnectionFailure` is true; a 421 only on a coalesced HTTP/2 connection; a 401 goes to the authenticator, which is none by default. A re-sent call returns a response with a non-null `priorResponse` (`:89`).
- **Proxy.** With `builder.proxy` set, `client.proxySelector` is OkHttp's own selector that always answers `Proxy.NO_PROXY`; `ProxySelector.getDefault()` is not read, at build time or later (`OkHttpClient.kt:192-198`, `internal/proxy/NullProxySelector.kt`). With no `proxy`, it is read when the client is built. So the selector does not depend on which test class touched the client first.
- **A SOCKS proxy is not covered by `proxy(Proxy.NO_PROXY)` on the JVM.** For a direct route OkHttp makes its socket with `route.address.socketFactory.createSocket()` (`internal/connection/ConnectPlan.kt:272`). The default factory's `new Socket()` is a `SocksSocketImpl` that asks `ProxySelector.getDefault()` for a `socket://` URI on connect (`java/net/Socket.java:552`, `java/net/SocksSocketImpl.java:279-287` at `jdk-17-ga`); only `Socket(Proxy.NO_PROXY)` skips it (`Socket.java:155`, `:204`). Whether Android's `Socket` behaves the same is **[unverified]**; `Socket(Proxy.NO_PROXY)` is a public API on both.
- **The JDK's proxy exemptions.** `http.nonProxyHosts` defaults to `localhost|127.*|[::1]` (`java/net/doc-files/net-properties.html`), and the default selector applies `localhost|127.*|[::1]|0.0.0.0|[::0]` to `http.nonProxyHosts` and `socksNonProxyHosts` when the property is unset, and appends it when the property is non-empty; only the empty string removes it (`sun/net/spi/DefaultProxySelector.java:128`, `:258-272`). A test against a loopback server that leaves these properties alone proves nothing.
- `HttpUrl` does not agree with the WHATWG parser the core uses (`internal/-HostnamesCommon.kt`): it applies an IDNA mapping table; for a host with a `:` it decodes the IPv6 literal, and an IPv4-mapped one becomes the dotted IPv4 address while any other is re-written in compressed form (`toCanonicalHost`, `:285-303`; `canonicalizeInetAddress`, `:243`). `HttpUrl.host` holds an IPv6 host without brackets (`HttpUrl.kt:320-334`: "An IPv6 address, like `::1`. Note that there are no square braces"). The file has no parser for `0x7f.1` or `2130706433`; that `HttpUrl` leaves those as names is **[unverified]** (inferred from the absence, not run). The classifier therefore cannot rest on `HttpUrl`.
- OkHttp's changelog: "We don't break binary compatibility with non-alpha APIs".

## Approach

### Shape

- **The module is the session module of decision 0005**, at `modules/session`, Kotlin package `dev.octave.session`. Its HTTP code lives in `dev.octave.session.http`. T3-05 adds `signIn` and `request` to the same module; T4-05 adds the store. The player module (T8-01) and the image view (T3-11) depend on this module's Gradle project and call `OctaveHttp.callFactory`.
- **No JavaScript surface.** `OctaveSessionModule` defines `Name("OctaveSession")` and nothing else: no function, property, constant, event or view. The session allowlist of the 2026-11-21 amendment is empty until T3-05. `ModuleSurfaceTest` reads the module's source and fails on `Function(`, `AsyncFunction(`, `Property(`, `Constants(`, `Constant(`, `Events(`, `View(` or `OnCreate`. No TypeScript file imports the module, so the app's JavaScript bundle does not change.
- **Not React Native's client.** The client is never registered as an `OkHttpClientFactory` with `OkHttpClientProvider`, and never handed to Expo, Fresco or a WebView. Doing so would let JavaScript's `fetch` send through it, which is a header bridge (`AGENTS.md`, Playback hard rules). `OneClientTest`'s scan refuses `OkHttpClientProvider` in Octave source.
- **Pure Kotlin, no Android class in the HTTP package.** Nothing under `http/` imports `android.*`. That keeps the package runnable on the JVM, makes a logcat call impossible there, and leaves a shape Swift can mirror (`AGENTS.md`, Code style). `ModuleSurfaceTest` checks the import rule.

### The Kotlin surface

`test-writer` writes the frozen tests against exactly these names; the implementer may add `internal` or `private` members but may not change these.

```kotlin
package dev.octave.session.http

enum class HostClass(val wire: String) { LOOPBACK("loopback"), PRIVATE_LAN("private-lan"), PUBLIC("public") }

object HostClassifier {
    fun classifyServerAddress(address: String): HostClass
}

enum class HttpRefusal(val code: String) {
    NO_SESSION("no-session"), OTHER_ORIGIN("other-origin"), REDIRECT("redirect"),
    CREDENTIAL_URL("credential-url"), PUBLIC_HTTP("public-http"), INVALID_ADDRESS("invalid-address"),
    HEADER_NOT_ALLOWED("header-not-allowed"),
}

// The message is the code. It never holds a URL, a host, a header or a token, and it has no cause.
class OctaveHttpException(val refusal: HttpRefusal) : java.io.IOException(refusal.code)

class MediaBrowserAuthorization private constructor(/* private state */) {
    override fun toString(): String // "MediaBrowserAuthorization([redacted])"
    companion object {
        const val MAX_BYTES: Int = 4096
        fun parse(value: String): MediaBrowserAuthorization? // null when the value is not accepted
    }
}

object MediaBrowserHeader {
    // The value of packages/core/src/jellyfin/authorization-header.ts, byte for byte.
    fun build(client: String, device: String, deviceId: String, version: String, token: String): String
}

class SessionId private constructor(val value: String) { // equals and hashCode by value
    companion object {
        fun parse(text: String): SessionId? // exactly 32 lower-case hex digits, else null
    }
}

object SessionRegistry {
    internal fun open(baseUrl: String, authorization: MediaBrowserAuthorization): SessionId // throws OctaveHttpException
    internal fun close(session: SessionId)
}

object OctaveHttp {
    fun callFactory(session: SessionId): okhttp3.Call.Factory
    internal val client: okhttp3.OkHttpClient // for the module's own tests; never public
}
```

`internal` is visible to the module's own tests and to T3-05's sign-in code in the same Gradle module, and to nothing else. The player module and the image view are other Gradle modules and get the id from JavaScript as a string: they call `SessionId.parse` and then `OctaveHttp.callFactory`. Parsing an id grants nothing; authority is a registry entry, which only `open` makes, and an id is 128 random bits. A factory for an id with no entry refuses every call with `no-session`.

### The client

Built once, lazily, in `OctaveHttp`:

- `followRedirects(false)`, `followSslRedirects(false)`, `proxy(Proxy.NO_PROXY)`, `socketFactory(DirectSocketFactory)`, `cookieJar(CookieJar.NO_COOKIES)` (written out, though it is the default), `cache(null)`, `retryOnConnectionFailure(false)`, connect timeout 15 s and read timeout 30 s as the spike used. T3-05 sets a per-call deadline with `Call.timeout()`, not with a derived client.
- `DirectSocketFactory` is a `javax.net.SocketFactory` whose `createSocket()` returns `Socket(Proxy.NO_PROXY)` and whose other overloads connect such a socket. OkHttp calls only `createSocket()`. It is what makes "no proxy" true for a JVM-wide SOCKS setting, which `proxy(Proxy.NO_PROXY)` alone does not reach (Facts). TLS still comes from OkHttp's default `SSLSocketFactory`, layered over this socket.
- `retryOnConnectionFailure(false)` stops OkHttp's silent second attempt after a connection failure and its 408 re-send. It does **not** stop the one re-send OkHttp makes after a 503 with `Retry-After: 0` (Facts); that goes to the same origin with the same header and stays. It also means a request on a pooled connection the server has since closed fails once instead of being retried, which T3-05 and T8-01 will see as a `network` error; T3-05 decides, with a decision-log entry, whether to turn the retry on (backlog line).
- Exactly one application interceptor, `SessionInterceptor`, and no network interceptor, event listener, authenticator or DNS override. Nothing derives a client from this one (`OkHttpClient.newBuilder()`): a derived client is another client. `Request.newBuilder()` and `Response.newBuilder()` are ordinary copies and are used.
- `callFactory(session)` returns a factory whose `newCall(request)` copies the request (`request.newBuilder().tag(…)`) with a tag of a private type that names the session, then calls `client.newCall`. The interceptor reads that tag. A request with no tag, or a tag whose session was closed, is refused with `no-session`. The tag holds the session id and never the header.

### The interceptor's order of checks

`RequestPolicy.check` is a pure function of the session entry and the request; the interceptor calls it and does the I/O. Every refusal happens before `chain.proceed`, so nothing is resolved, connected or sent.

1. No session for the call: `no-session`.
2. The request carries an `Authorization`, `Proxy-Authorization`, `Cookie`, `Cookie2`, `Host` or `Forwarded` header, or one whose name starts with `:`, `Proxy-`, `X-Forwarded-`, `X-Emby-` or `X-MediaBrowser-` (names compared case-insensitively): `header-not-allowed`. The host-naming headers are refused because OkHttp keeps a caller's `Host` and builds HTTP/2's `:authority` from it, so a virtual-host proxy at the session's address could route the session's header to another backend; the `X-Emby-` and `X-MediaBrowser-` headers carry Jellyfin credentials that would replace the session's. Added after the review (Decision log, 2026-11-21, review fix).
3. User name or password in the URL: `credential-url`. This comes before the origin check, so `http://user:pw@<other origin>/` is `credential-url`.
4. Scheme, host or port differs from the session's base URL: `other-origin`. The comparison is on `HttpUrl.scheme`, `HttpUrl.host` and `HttpUrl.port` of both, so a default port and an explicit one compare equal, and so do two spellings of one IPv6 address. This comes before the query check, so `http://<other origin>/?ApiKey=x` is `other-origin`.
5. A credential query name, or the token value in the URL: `credential-url`. Names are compared after percent-decoding, trimming and lower-casing, against `apikey`, `api_key`, `access_token`, `token`, `x-emby-token`, `apitoken`, `accesstoken`. The token check looks for the raw token and for the token as written in the header in the URL's text, and for the raw token in the text percent-decoded up to four rounds (decision 0005, `no_url_carries_the_token`).
6. Scheme `http` and the host's class is public: `public-http`. **This check cannot be reached through the public surface**: after check 4 the host is the session's, and `open` step 1 refused a public plain-HTTP session. It stays as a guard against a later change to `open`. No frozen test covers it; the implementer's `RequestPolicyTest` calls `RequestPolicy.check` directly with a hand-made entry.
7. Proceed with a copy of the request that has `Authorization` set to the session's value. If the answer's status is 300 to 399, close it and throw `redirect`. Otherwise return the answer as "The answer" says.

Other statuses, 401 included, are returned as they are. Ending a session on a confirmed 401, stripping an echoed token from a body, and the fixed pre-sign-in paths are T3-05's and T4-05's.

### The answer

The `Response` that `chain.proceed` returns holds the authorised request three times over: `response.request`, `response.networkResponse.request`, and, after a 503 re-send, `response.priorResponse.request` (Facts). Any Kotlin caller, and any library that reads a response's request (Media3's OkHttp data source in T8-01), could read the header from there. So the interceptor returns

`response.newBuilder().request(<the request the interceptor was given>).networkResponse(null).priorResponse(null).build()`

and nothing else. The request the interceptor was given has no `Authorization` (check 2) and carries only the session tag. The body, status, headers, protocol and handshake are unchanged; `cacheResponse` is already null (no cache). `OriginPinTest` and `TwoServerRulesTest` hold this. With it, "no public accessor returns the header" is true of the module's whole surface, answers included.

What a caller loses: `networkResponse` (the wire-level request and response headers). No planned caller reads it; T8-01 confirms for Media3 (backlog line).

### Sessions

- `SessionRegistry.open(baseUrl, authorization)`:
  1. Classify the address as written with `HostClassifier.classifyServerAddress`. If it is written with the scheme `http` (the trimmed text starts with `http:` in any case) and the class is public: `public-http`. This comes first, so every public vector gets that code, including the ones that fail R1 or do not parse. The one-time private-LAN confirmation stays the core's (decision 0001); Kotlin checks only the class.
  2. The address must pass R1 (plain ASCII authority), for `https` as well; otherwise `invalid-address`. A Unicode-written host is refused here rather than handed to OkHttp's IDNA mapping, because the core and OkHttp would then disagree on what the origin is (decision log). R1 has no `@`, so a base URL with user info ends at step 1 or here.
  3. `HttpUrl` must parse it, with no query and no fragment; otherwise `invalid-address`. A base path is kept (decision 0005, T2-04 note 3); the pin is the origin.
  4. The host OkHttp will dial must be the host the classifier read; otherwise `invalid-address`. By the kind of host the classifier parsed:
     - **An IPv4 host:** `HttpUrl.host` equals the classifier's dotted-decimal form. So `http://0x7f.1` and `http://2130706433` are `invalid-address` unless OkHttp itself canonicalises them.
     - **A name:** `HttpUrl.host` equals the lower-cased name as written.
     - **A bracketed IPv6 literal that is not IPv4-mapped:** `HttpUrl.host`, parsed by the classifier's own IPv6 parser, gives the same eight groups. The comparison is on the groups, never on text, because OkHttp rewrites the literal (`[0:0:0:0:0:0:0:1]` becomes `::1`).
     - **An IPv4-mapped literal (`::ffff:a.b.c.d`, in either spelling):** `HttpUrl.host` equals the dotted-decimal form of the embedded IPv4 address. The session is accepted and its pinned host is that IPv4 address, which is what OkHttp dials. Its class is the embedded address's class under R3 already (`docs/security.md` §3: "IPv4-mapped IPv6 takes the class of the embedded IPv4 address"), so the class read in step 1 and the class of the dialled host agree; the implementation asserts that and answers `invalid-address` if they ever differ.
     The core hands over the WHATWG-serialised URL. For a mapped literal that is `[::ffff:7f00:1]`, which `HttpUrl` again reads as `127.0.0.1`, so the core's request URLs match the pin.
  5. The id is 128 bits from `java.security.SecureRandom`, written as 32 hex digits, not derived from the token.
- The registry holds any number of sessions in a concurrent map, and nothing outside `http/` can read an entry. `close` removes the entry; calls already in flight finish, and later calls get `no-session`.
- **A session always has a token.** The tokenless header of the four pre-sign-in paths is not a session and is not accepted from any caller: T3-05 builds it in Kotlin from a DeviceId for those fixed paths and adds it as a second, internal kind of call authority beside the session tag. This task leaves room for that (the tag is a sealed type with one case) and builds none of it.

### The header value

`MediaBrowserAuthorization.parse` accepts a value only when all of these hold:

- Its UTF-8 length is at most 4096 bytes.
- The **whole** text matches, with `Regex.matches` (not `find`, and not `$`, which would pass a trailing line break):

  `MediaBrowser Client="V*", Device="V*", DeviceId="V*", Version="V*", Token="V+"`

  where `V` is one character of `A-Z a-z 0-9 - _ . ! ~ * ' ( )` or an escape `%` followed by two hex digits from `0-9 A-F`. That is exactly what `encodeURIComponent` can write. Field names are case-sensitive, the order is fixed, the separator is one comma and one space, and `Token` is the last field and is not empty.

This is the builder's own shape, so nothing the app builds is refused, and it settles every open case at once: one `Token` field, in last place, with no quote, space, control character or non-ASCII character anywhere. It is stricter than the desktop validator, which only looked for `Token="` somewhere in the text. The token the URL check (check 5) searches for is the text between the last pair of quotes and its percent-decoded form.

### The classifier

One public function that needs no URL parser, so it cannot inherit `HttpUrl`'s differences:

1. Trim the characters JavaScript's `trim()` removes (U+0009 to U+000D, U+0020, U+00A0, U+1680, U+2000 to U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF), not Kotlin's `trim()`, which also removes U+001C to U+001F.
2. R1: the regular expression of R1 in `fixtures/README.md` (line 25 here, 26 on origin/main), with no `IGNORE_CASE` option. No match is public.
3. A port, when present, must be at most 65535; otherwise public (the WHATWG parser fails).
4. A bracketed host: parse the IPv6 literal (hex groups, one `::`, an optional dotted-decimal IPv4 tail) into eight groups and classify as `classifyIpv6` does. A literal that does not parse is public.
5. Otherwise lower-case the host. If its last label (ignoring one trailing dot) is all digits or a `0x` number, parse the host as a WHATWG IPv4 number (one to four parts; decimal, `0x` hex or leading-zero octal; the last part fills the remaining bytes); a failure is public; a success is classified as `classifyIpv4` does.
6. Otherwise a name: the rules of `classifyDomain` (`localhost`; an empty label is public; an `xn--` label in any case is public; `*.local` and `*.home.arpa` are private LAN; the rest public).

Step 4 of `open` and the interceptor's check 6 call internal functions of the same file (the IPv6 parser, the IPv4 and name rules) on `HttpUrl.host`, so there is one rule set.

### The header builder

`MediaBrowserHeader.build` mirrors `buildAuthorizationHeader`: `MediaBrowser Client="…", Device="…", DeviceId="…", Version="…", Token="…"`, each value encoded as `encodeURIComponent` does (UTF-8, upper-case hex, with `A-Z a-z 0-9 - _ . ! ~ * ' ( )` left alone; `java.net.URLEncoder` differs on space, `*` and `~`, so it is not used as is). It is not an acceptance item. It is here because `docs/security.md:72`, `authorization-header.json`'s note and `docs/specs/T2-04.md:27` all assign `kotlin_header_matches_the_recorded_vector` to T3-03, and because item 7's accepted values are exactly what it builds. Nothing calls it until T3-05's sign-in.

### Decision log

- 2026-11-21 (refiner). The module is `modules/session` (`@octave/session`), the session module decision 0005 names, not a separate HTTP module: `DOMAINS.md:56` puts the registry, sign-in and `request` in one native session module across T3-03 and T3-05, and the registry must be private to the HTTP package.
- 2026-11-21 (refiner). No JavaScript method or event. Every one is an architecture change, and the accepted four belong to T3-05 and T4-05.
- 2026-11-21 (refiner). One client instance for all sessions, chosen per call by a private request tag. A client per session, or a client derived with `OkHttpClient.newBuilder()` per session, would be "another OkHttpClient" under T3-04's rule.
- 2026-11-21 (refiner). OkHttp 5.5.1 for the module, the tests and therefore the whole APK (Dependencies). The alternative, 4.12.x in the APK with `mockwebserver3` in tests, would test one OkHttp and ship another.
- 2026-11-21 (refiner). The classifier has its own host parser. `HttpUrl` maps IDNA and rewrites IPv6 literals, and `InetAddress` would be a DNS answer, which decision 0001 forbids.
- 2026-11-21 (refiner). An `https` base URL must also be written in plain ASCII (R1). The core lets an HTTPS server with a Unicode-written host sign in; `docs/specs/T2-06.md:243` leaves that case to "the native client (T3-03)". Refusing it is the fail-closed reading: a punycode (`xn--`) host under HTTPS is accepted, a Unicode-written one is `invalid-address`. Backlog line for the Product Owner, since a viewer who types such a name on the TV is told the address is not valid.
- 2026-11-21 (refiner). A session header must hold a non-empty token, stricter than the desktop validator, because item 7 says "with a token" and the tokenless header never comes from a caller.
- 2026-11-21 (refiner, after the spec check). The header value is accepted only in the builder's exact five-field shape. "Holds `Token="…"`" left open where the token sits, whether two are allowed and whether a quote may appear in a value; the exact shape closes all three and costs nothing, because the only producer is `MediaBrowserHeader.build`.
- 2026-11-21 (refiner). A request that already carries `Authorization`, `Proxy-Authorization` or `Cookie` is refused, not overwritten. No caller has a reason to set one, and refusing makes a second source of the header visible.
- 2026-11-21 (refiner, after the spec check). The interceptor returns an answer with the caller's request and no `networkResponse` or `priorResponse`. Without that, every Kotlin caller could read the header from `response.request`, against decision 0005's "keep the token in native memory only" as this module applies it (no accessor) and against I4 once a library logs a request. ## Test plan

Frozen by `test-writer` (Kotlin, JUnit Jupiter, `mockwebserver3`), one class per item as the Acceptance table names; each selected with `node scripts/tv-native-test-only.mjs dev.octave.session.http.<Class>`. Shared rules:
