## Goal

The core's gateway runs in the TV app over Kotlin. The session module gains its first three JavaScript methods, `signIn`, `request` and `endSession` (the ones decision 0005 accepted and the core's `Transport` port names). The app's adapter turns them into the port, so every gateway request leaves the device through the one OkHttp client and JavaScript never holds a token or a header. `pnpm tv:wire` exists: it runs tagged wire tests in the e2e app on the emulator against a local test server and the three pinned servers, records every request, and judges the record. Each checkout's fixture servers run under their own Compose project.

## Approach

### The native seam

Three methods, each taking **one map** and resolving **one map**. Kotlin reads the map by hand, so Expo's converter never holds a typed value it could quote in an error. No method rejects on purpose.

| Method | Argument | Resolves |
|---|---|---|
| `signIn` | `{ server, deviceId, kind: "password", username, password, timeoutMs }` or `{ server, deviceId, kind: "quick-connect", secret, timeoutMs }` | `{ session, userId, userName?, serverId? }` or `{ error, status? }` |
| `request` | `{ session }` or `{ server, deviceId }`, plus `method`, `path`, `query` (a list of two-string lists), `body` (JSON text, or absent), `timeoutMs` | `{ status, body }` (`body` is JSON text or null) or `{ error }` |
| `endSession` | `{ session, timeoutMs }` | `{}` or `{ error, status? }` |

- No argument is a header, an absolute URL or a token. A map with a key outside the table resolves `{ error: "refused" }`. The named refusal tests are T3-16's; each refusal here has one focused JVM case.
- `error` is one of the core's seven codes. `status` accompanies only `error: "status"`.
- **Sign-in.** Kotlin sends `POST /Users/AuthenticateByName` or `POST /Users/AuthenticateWithQuickConnect` with the tokenless header, builds the body with the JSON library (never by string joining), parses the answer, keeps `AccessToken`, builds the header with `MediaBrowserHeader.build`, checks it with `MediaBrowserAuthorization.parse`, opens the session and returns the four fields with the token stripped from each. A non-2xx answer is `status`; a 2xx without a non-empty `AccessToken` and `User.Id`, or a header `parse` refuses, is `unexpected-response`. The password and the secret are local variables of the call.
- **Request.** The URL is the base URL, the path, and the encoded query. Checks before sending: the path starts with `/`, not `//`, and holds no `?` or `#`; `timeoutMs` is a positive integer; no credential query name; the method is `GET`, `POST` or `DELETE`; without a session, method and path are one of the four `PRE_SIGN_IN_ROUTES`. The interceptor then applies `RequestPolicy` as before. The call sets `Accept: application/json`, and `Content-Type: application/json` with a body, as the reference does. The deadline is `Call.timeout()` on the call, not a derived client.
- **Answers.** A 3xx is `redirect`. A status outside 200 to 299 and 400 to 599 is `unexpected-response`. The body is read up to 32 MiB (more is `unexpected-response`), parsed, stripped, and written back as JSON text; an empty or non-JSON body crosses as null, so no HTML error page crosses at all.
- **The echoed token** is replaced with `[redacted]` in every string and every key of the parsed answer, in the forms the reference uses: as written, percent-encoded with upper-case and lower-case hex, and query-encoded. The parse is why the filter cannot miss a JSON escape. A session request only; a tokenless answer has no token to strip.
- **Query encoding** is the reference's, byte for byte, pinned by the shared `transport-query-encoding.json` (names and values with space, `:`, `$`, `,`, `!*'()~`, `+`, `&`, `=`, `%`, non-ASCII and an astral character; the frozen test computes `expected` with the reference). One known difference: OkHttp's URL parser writes `'` in a query as `%27` (Facts). The frozen file holds only the reference's `expected`. `QueryEncodingTest` (Kotlin, not frozen) asserts two things per vector: `QueryEncoding.encode` equals `expected`, and the query MockWebServer receives equals `expected` with each `'` written `%27` and nothing else changed. If OkHttp changes any other character, stop and record it; do not edit the vectors.
- **Authorities.** `CallAuthority.Tokenless(address, headerValue)` for the six tokenless calls (the four routes and the two sign-in posts): `RequestPolicy.checkTokenless` applies the same header, user-info, origin, credential-name and plain-HTTP rules, and refuses any method and path that is not one of the six under the address's base path. `CallAuthority.Closing(entry)` carries a removed session's entry for the one logout call.
- **End a session.** Remove the registry entry first, then `POST /Sessions/Logout` with the closing authority. An unknown session resolves `{}`. A non-2xx logout is `status`; the session is gone either way.
- **Client identity.** `Client` is `Octave`, held equal to the core's `APP_NAME` by a JVM test that reads `app-identity.ts`. `Device` is `android.os.Build.MODEL`, or `Android TV` when blank; `Version` is the app's `versionName`. `OctaveSessionModule` reads both (the `http` package imports no Android class) and hands them to `ClientIdentity`. The model name is a new input to the header builder from outside Octave: a JVM case builds the header with a model name holding a non-ASCII character and a `"`, and holds the result to the header fixture's encoding rules (`authorization-header.json`). The value goes into the header only.
- **Dot segments are not refused here.** OkHttp is expected to resolve `..` when it builds the URL **[unverified]**, so a path such as `/Items/../../x` may leave the session's base path. The refusal is T3-16's (backlog entry 172). One JVM case sends such a path through `SessionTransport` to MockWebServer and records the path the server receives, without asserting containment.
- **Codes.** `REDIRECT` is `redirect`; every other `HttpRefusal` is `refused`; a call timeout or `SocketTimeoutException` is `timeout`; any other `IOException` is `network`; a body that cannot be read or is too large is `unexpected-response`; anything else thrown is `network`. Kotlin catches `Throwable` around each call and never puts a message in the result.
- **No log call** is added anywhere in the module.

### Threading

In `expo-modules-core` 58.1.0 a plain `AsyncFunction` body runs on `appContext.modulesQueue` (`AsyncFunctionComponent.kt:62`), and that queue is one `HandlerThread`, `expo.modules.AsyncFunctionQueue`, shared by every Expo module (`AppContext.kt:70-73,87-91`; read in `node_modules/.pnpm/expo-modules-core@58.1.0_*/…/android/src/main/java/expo/modules/kotlin/`, 2026-11-21). A blocking body there would serialise every request: a stalled call would hold every later one, of every module, until its deadline, and `timeoutMs` would only start when the body runs. So each of the three bodies takes the `Promise` form and launches the blocking `SessionTransport` call on a coroutine scope of this module on `Dispatchers.IO` (a `SupervisorJob`, cancelled in `OnDestroy`), then returns; the coroutine resolves the promise. The modules queue is held only for the argument read. `SessionTransport` itself stays blocking and Android-free, so the JVM tests call it directly. A JVM test (`ConcurrencyTest`) shows a second request completing while a first is stalled at MockWebServer; the wire test `transport-errors` sends its stalled call and a probe together and records that the probe answered first.

### The adapter

`createSessionTransport(native)` in `apps/tv/src/host/transport.ts`:

- Flattens the port's arguments into the maps above; `JSON.stringify` for a body; `JSON.parse` for an answer, `undefined` when null.
- A 4xx or 5xx from `request` is returned as a response; `signIn` and `endSession` raise `TransportError("status", status)`.
- **Cancellation stays inside the accepted surface.** An already-aborted signal raises `cancelled` without calling native. An abort during a call raises `cancelled` at once; the native call runs on to its answer or its deadline and its result is dropped. A sign-in that succeeds after its abort has its session ended with `endSession`, so no session is left that the core does not know. A native cancel would be a fourth method and needs a decision record; a backlog line records the cost (a dropped call still finishes on the wire).
- The catch-all: a rejection, a non-object, an unknown code or a missing field becomes `TransportError("refused")`, built from the code alone.

### Retries

`retryOnConnectionFailure` stays off (T3-03's decision; `OneClientTest` and the wire counts rely on one send per call). With it off, the first request on a pooled connection the server has closed fails once. So `request` sends a **`GET` a second time, once**, when the first attempt fails with an `IOException` that is not a timeout, a cancel or a refusal, inside the same deadline. Nothing else is sent twice: not a `POST`, not a `DELETE`, not a sign-in. The recorder counts both sends. OkHttp's own re-send after a 503 with `Retry-After: 0` remains (T3-03, Risks).

### The wire runner

One e2e APK, one launch, no launch argument and no new native code.

- **Targets on the device are fixed loopback ports**, each an `adb reverse` to an ephemeral port on the host's loopback, so no host port is fixed and two checkouts never share one. `wire-tests.json` holds the base port and the list; each (test, target) pair gets its own device port by its index, so a capture belongs to one test by construction.
- **`scripts/tv-wire-mock.mjs`**, the local test server: a small Jellyfin-shaped server (probe, sign-in issuing the canary, `GET /UserViews`, logout; the frozen capture expects exactly `GET /System/Info/Public`, `POST /Users/AuthenticateByName`, `GET /UserViews`, `POST /Sessions/Logout` and fails an extra `GET /Users/Me`, `scripts/tv-wire.test.ts:111,231`), the routes the tests need under `/Wire/` (echo, 401, 500, stall, not-JSON), a **redirector** origin whose every answer is a 302 to the canary origin, and the **canary origin**, which records and must stay at zero. The probe answer's `LocalAddress` is `http://10.0.2.2:<the mock's host port>`.
- **`scripts/tv-wire-proxy.mjs`**, the recorder: a reverse proxy per (test, server) pair in front of a fixture server. It records method, path, query **names**, whether `Authorization` is present, its scheme, whether the token field is non-empty, the `Host`, the status, and whether the URL holds a known secret. It never stores a header value, a query value or a body.
- **The seam scan and the logcat judge look for** the canary, every real token, every fixture password, and the placeholder password (a password in an error message is the leak item 5 names).
- **The fixture password never reaches the device.** The app signs in with a fixed placeholder user and password from `wire-tests.json`. The proxy replaces both in the body of `POST /Users/AuthenticateByName` with the values from `tests/integration/.credentials`, and reads the issued token from the answer to know the secret to look for. Nothing secret is in the bundle, an argument list or logcat.
- **The app side.** `root.tsx` runs conformance, then `runWire`: the app cannot know what the host selected, so it walks every pair in the list and probes the pair's port; a refused connection writes `OCTAVE_WIRE unreachable test=<id> target=<name>` and the pair is skipped. The host reverses only the selected pairs' ports and fails on an unreachable line for a selected pair. Under `pnpm tv:e2e` nothing is reversed, every pair is unreachable, and that runner ignores the lines. Each test builds a gateway with `hostCrypto`, a transport from `createSessionTransport` wrapped by the seam recorder, and writes `OCTAVE_WIRE result test=<id> target=<name> task=<task> …` with fixed words and counts only, then `OCTAVE_WIRE done`.
- **The five tests of T3-05:** `transport-probe-then-signed-in` (mock and the three servers), `transport-redirect`, `transport-canary`, `transport-errors` (mock), and `transport-private-lan-and-proxy` (mock): one probe to the `LocalAddress` above, which is plain HTTP to a private-LAN address from the app's own process (T3-15's follow-up), the second half of that test is host-side: **the whole run happens with the emulator's global HTTP proxy set** to a canary port (`adb shell settings put global http_proxy 127.0.0.1:<device port>`, reversed to a host listener), and that listener must record no request naming a wire target while every target still records its requests (`docs/security.md` line 88). One launch gives the runner no moment to switch it mid-run, and the whole run is the stronger check. The runner clears the setting (`:0`) at its start and in a `finally`. The frozen judges say nothing about this listener (`scripts/tv-wire.test.ts`), so the rule is the runner's and is proved by hand at milestone 4 (after milestone 0): first observe what an idle emulator sends to the listener with `http_proxy` set and record it; scope the failure to requests whose `Host` or absolute URL names a wire target port, so the system's own traffic cannot fail the run; then record one negative control that makes the check fail (for example a run with a planted Java `URL.openConnection()` in a throwaway build, which honours the global proxy), or record in `docs/security.md` that none is possible and why. `http_proxy` is a device-global setting; `docs/commands.md` says so, and says that `pnpm tv:wire` runs on the implementer's own emulator and not on the Shield (a shared device whose owner's proxy setting it would clear).
- **`pnpm tv:wire [--task <id>] [--list]`**: requires `ANDROID_SERIAL` and never prints it; starts the fixture servers when a real target is selected and not healthy (`pnpm fixture:up`, then `pnpm fixture:setup`; both are safe to repeat) and leaves them running; builds the e2e APK when stale, as `tv:e2e` does; starts the mock and the proxies; sets the reverses; clears logcat; starts the app; waits for `OCTAVE_WIRE done`; removes the reverses; judges; writes `release-evidence/wire/<test>-<target>.jsonl` and `summary.txt` with one line per pair (`<test> <target> <task> pass|fail`); exits 1 on any failure, an unreachable selected target, or an empty capture.
- **What "every request the app makes" covers:** every request the one client sends to a target, plus the canary origins and the `Host` check. With T3-04's fence (`pnpm lint:network`, no other network path in Octave's code) that is the claim. It is not a packet capture of the process; `docs/security.md` says so.
