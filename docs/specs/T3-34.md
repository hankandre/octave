# T3-34: Adopt the Tabler icon set behind the IconComponent type

Task: `T3-34` (phase T3, lane `ui`, App Shell & Presentation). Depends on T3-06, T3-08 and T3-09, all `done` and `passes: true` on `origin/main` (`node scripts/task.mjs show T3-06|T3-08|T3-09`, 2026-11-23). Implementer: **`implementer`** (TypeScript and the Expo config only; nothing under `modules/` or `apps/tv/android/`, and the `PlayerEngine` port is untouched). Not a playback task, so no Jellyscale wire test applies.

## Goal

Replace the empty icon slot with Tabler's outline icons at the owner's light weight. The icons come from Tabler's TTF, bundled at build time through the expo-font config plugin. One typed map in `apps/tv/src/design/icon.ts` turns an icon name into an `IconComponent`. Screens use only icon names, never codepoints. The played mark on a card shows its check, and the side rail shows its icons. No native module, no other icon package and no run-time font loading is added.

## Approach

1. **The font.** Add the dependency and the `TablerIcons` family as in the Acceptance table. `fontDefinitions: [{ weight: 400 }]` matches the CSS's `font-weight: 400` for this file. The weight-300 stroke is baked into the file, so no axis is set. The family name does not include the weight, so a later weight change is a one-line path change. Nothing loads a font at run time: there is no `useFonts` and no `Font.loadAsync`, which the design-token lint forbids anyway. If `pnpm tv:prebuild` fails to resolve the package path under pnpm, which is **unverified**, use the precedent of T3-06's Atkinson files instead. Copy the TTF to `apps/tv/assets/fonts/tabler-icons-300.ttf` and the LICENSE to `apps/tv/assets/fonts/MIT-tabler-icons.txt`, check the SHA-256 against "Facts", and point the path there. Item 1(c) then checks that the copy's SHA-256 equals the installed package's file. Record which path was taken in the decision log.
2. **The map** (`design/icon.ts`): `export const glyphs = { check: 0xea5e, search: 0xeb1c, home: 0xeac1, movie: 0xeafa, "device-tv": 0xea8d, "stack-2": 0xeef7, settings: 0xeb20, user: 0xeb4d } as const;`. Keys are Tabler's own names, so the test can look each one up in the CSS. The map holds only glyphs a screen uses; a new screen adds its entry here. `iconOf` caches one memoised component per name in a module-level `Map`. That keeps the component's identity stable, so a provider's value and React's reconciliation stay stable too. The component renders `<Text accessible={false} importantForAccessibility="no" allowFontScaling={false} style={{ fontFamily: ICON_FAMILY, fontWeight: "400", fontSize: size, lineHeight: size, width: size, height: size, textAlign: "center", includeFontPadding: false, color }}>{String.fromCodePoint(cp)}</Text>`. The control already scales `size` with `px()`, so the icon does not scale it again. No literal size or colour appears, so `octave/design-tokens` has nothing to report.
3. **The played check.** `MediaCard` uses the provider's `playedIcon` when it has one, and `iconOf("check")` otherwise. The slot stays for screens that want another glyph. T3-08's frozen tests still hold: they check only that `c-played` exists, that it is not focusable, and that the title shows on a missing image.
4. **The rail.** `shell/rail-icons.ts` maps each `RailIconName` to a glyph: `search` to `search`, `home` to `home`, `movies` to `movie`, `tvshows` to `device-tv`, `boxsets` to `stack-2`, `settings` to `settings`, and `account` to `user` (shown only when there is no account initial). `App.tsx` passes the map to `AppShell`. `AppShell`'s default stays `{}`, so T3-09's frozen tests, which pass no icons, are unchanged. These glyphs are the owner's choice (`docs/specs/decisions-owner-chat-2026-11-24.md` §2).
5. **Frozen files (resolved here, not an owner question).** Item 4's "test glyphs" are the doubles that stand in for the missing set. T3-06's `TestIcon` lives in frozen files (`harness.tsx`, `cases.tsx`, `select-key.test.tsx`). There it tests the `IconComponent` contract (a control passes a size and a colour to whatever it is given), and that contract stays true. `AGENTS.md` forbids changing a frozen test. So this task does not touch those files. It replaces the doubles in the tests that are not frozen, and it adds `icons-in-controls.test.tsx`, which runs every icon-taking control and the played mark with the real glyphs. If the reviewer reads item 4 as needing `TestIcon` replaced in T3-06's harness, that is a frozen-test question for the Product Owner (`frozenTestProblems`, a `Frozen-Test-Change` trailer), not something the implementer may do.
6. **Codepoint scanner.** `apps/tv/src/design/icon-codepoints.test.tsx` holds a pure `findCodepoints(source, cmap)` and the tree scan. It runs in `pnpm check` through `vitest run`. Decimal numbers are left out on purpose, because timeouts such as `60000` (U+EA60) would collide. `e2e/` is left out because `e2e/wire/find-secret.ts` holds `0x10000` in its UTF-8 encoder.
7. **Backlog line for T11-05** (the implementer appends it, with the fields in `WORKFLOW.md` §2a): "T11-05's notice generator must read `@tabler/icons-webfont`'s LICENSE file (MIT, Paweł Kuna): its npm manifest has no `license` field, so a manifest-only scan reports it unknown and the licence gate would fail." Source T3-34.

## Risks and out of scope

- **Fallback rendering.** If the family fails to register, Android draws codepoints from other fonts: tofu for the Private Use Area, or Linear B letters for U+10000 and above. The milestone 4 captures and smoke run are the check. No test can see it, so the captures (item 7) carry it.
- **Size.** The whole 5,491-glyph font ships (about 2 MB uncompressed) for 8 glyphs. Subsetting it would need a font tool as a build dependency. That is out of scope; if the measured size matters, the implementer logs a backlog line.
- **The `wght` axis.** The expo-font plugin writes `wght` equal to the weight into its generated font call for each definition. For a static font this should be ignored, but that is **unverified**, and the captures show it.
- **Accessibility.** The glyph is hidden from TalkBack, so a control's label and state words still carry the meaning (`DESIGN.md` rule: state is never colour or icon alone).
- **Hard rules and invariants touched.** Dependencies: the maintenance check is recorded and the version pinned. Design: tokens only, D-pad, Back and reduced motion unchanged (no motion is added), and 1920×1080 captures in the PR. Tests: no frozen file changes, and a focused test comes with each behaviour change. Network: the font is bundled and nothing loads at run time (`PRODUCT.md` principle 6, `DESIGN.md` §4), so the one-client rule and `pnpm lint:network` are untouched. No token, URL, header, image path, native module method or event is touched.
- **Out of scope.** Icons for screens not yet built (the player controls, the skip pill, search's field, Watched and Favorite): each screen task adds its glyph names to the map. Filled icons. Iconography for the logo (T3-35). Licence gathering itself (T11-05).
