## Goal

Today every checkout publishes the fixture servers on host ports 18096 (Jellyfin 10.11), 18097 (Jellyfin 12.4) and 18098 (Jellyscale). T3-05 item 8 gave each checkout its own Compose project, but kept the ports fixed, so `pnpm fixture:up` in a second checkout stops and names the holder, and a project left by a deleted worktree blocks every other checkout until someone removes it.

After this task:

1. each checkout chooses its own three host ports, records them in one gitignored file in that checkout, and publishes its servers on them;
2. the setup script, the tripwire, the fixture recorders and the wire runner all read the servers' addresses from that record;
3. two checkouts can run `pnpm fixture:up` at the same time, and a leftover project from a deleted checkout is stepped around, not fatal;
4. 18096-18098 remain only the default: the ports a reader uses when no record exists, and one slot among the candidates.

## Approach

### The record

`tests/integration/.fixture-ports`, an env file Compose reads with `--env-file` and bash reads with `grep`:

```
OCTAVE_FIXTURE_PORT_JELLYFIN_10_11=18143
OCTAVE_FIXTURE_PORT_JELLYFIN_12=18144
OCTAVE_FIXTURE_PORT_JELLYSCALE=18145
```

It is the one source: Compose interpolates it on `up`, so the published ports and the ports every reader uses cannot differ. Written with a temp file and `rename`, mode default (it holds no secret). `fixture-ports.mjs` exports:

- `SERVICES = ["jellyfin-10-11", "jellyfin-12", "jellyscale"]`, `DEFAULT_PORTS` (= `FIXTURE_PORTS`, 18096-18098), `RECORD` (absolute path), `KEYS`.
- `readRecord(file = RECORD)`: `{ "jellyfin-10-11": n, … }` or `null` when absent; a malformed or partial file is an error naming the file and `pnpm fixture:up` (never a silent default).
- `writeRecord(ports, file = RECORD)`.
- `fixtureOrigins(file = RECORD)`: `{ name: "http://127.0.0.1:<port>" }` from the record, or from `DEFAULT_PORTS` when there is none.
- `withFixtureOrigins(credentials, origins = fixtureOrigins())`: a copy with each `<name>_url` set to the record's origin.
- `slotOf(project)`: `parseInt(<the 10 hex of the name>, 16) % 300`.
- `choosePorts({ project, recorded, isUsable })`, pure: returns `{ ports }` or `{ error }`. Order: the recorded triple when all three are usable; then slot `slotOf(project)`, then the next slots in order, wrapping, where slot `k` is `18096 + 3k`, `+1`, `+2` (slots 0-299, ports 18096-18995); the first slot whose three ports are all usable. None: `ERROR fixture ports: no free slot of three ports in 18096-18995`.
- `isUsable(port, project)` (impure): `readPortHolders([port])` names this project, or names nobody and a listener on `0.0.0.0:<port>` and on `::` (`net` server, `exclusive: true`, run in a child process so the answer is synchronous; an address family the host lacks does not count as taken) binds and closes. A port held by another Compose project or `(not Compose)` is not usable.
- CLI: `--choose` (choose, write, print `[fixture-up] ports jellyfin-10-11 <a>, jellyfin-12 <b>, jellyscale <c>`), `--check` (exits 1 when any recorded port fails `isUsable` for this project, printing `judgePortHolders` lines for Compose holders and `ERROR fixture port <n> is held by another process` otherwise; exits 0 when all three are usable), no flag (print the three origins, for a person).

**Why the slot comes from the project name and not 18096 first:** parallel lanes (`docs/specs/T1-19.md:94`) start several worktrees at once. Starting from the defaults, every fresh worktree would pick 18096-18098 at the same moment, and all but one would fail and retry; a per-checkout slot makes two simultaneous fresh checkouts disjoint unless their slots match (1 in 300), and the retry covers that. 18096-18098 is slot 0 and the readers' default.

**Signals trusted:** Docker's own list (`docker ps --filter publish=<port>`, the existing `readPortHolders`) for ports Docker publishes, which also covers a daemon run without the userland proxy, where no host socket exists; the bind probe for any other process. Neither sees a port another checkout has chosen but not yet bound; the retry handles that window.

### The override

`tests/integration/docker-compose.ports.yml`:

```yaml
# T3-27: this checkout's host ports, from tests/integration/.fixture-ports (pnpm fixture:up writes it).
services:
  jellyfin-10-11:
    ports: !override
      - "${OCTAVE_FIXTURE_PORT_JELLYFIN_10_11:?run pnpm fixture:up}:8096"
    environment:
      JELLYFIN_PublishedServerUrl: http://127.0.0.1:${OCTAVE_FIXTURE_PORT_JELLYFIN_10_11:?run pnpm fixture:up}
  jellyfin-12: …same with _JELLYFIN_12…
  jellyscale:
    ports: !override
      - "127.0.0.1:${OCTAVE_FIXTURE_PORT_JELLYSCALE:?run pnpm fixture:up}:8096"
```

Jellyfin keeps today's bind address (all interfaces, as the base file), Jellyscale keeps loopback. Narrowing Jellyfin to loopback is a separate hardening, logged to the backlog, not done here.

### `fixture-up.sh`

After the unchanged `--env-only` exit and project line:

```bash
for attempt in 1 2 3; do
  node "$here/fixture-ports.mjs" --choose
  if docker compose -p "$project" -f "$here/docker-compose.yml" -f "$here/docker-compose.ports.yml" --env-file "$here/.fixture-ports" up -d --wait; then exit 0; fi
  node "$here/fixture-ports.mjs" --check && exit 1   # every recorded port is still usable: the failure was not a taken port
  echo "[fixture-up] a chosen port was taken meanwhile; choosing again"
done
exit 1
```

(Shape, not literal code.) A second `fixture:up` in the same checkout keeps the record (its ports are held by its own project), so Compose finds nothing changed and recreates nothing. When the recorded ports were taken while this checkout was down, it moves to a new slot and Compose recreates its containers on the new ports; the named volumes, and so the users and libraries, are kept, so `fixture:setup` need not run again, and no reader uses the stale `_url` in `.credentials` because each overlays it.

## Risks and out of scope

- **A race inside a slot.** Two fresh checkouts whose slots match, or a person's process that binds a chosen port between choice and `up`, make one `up` fail; the retry chooses again, at most three times, then fails with Compose's error.
- **A partly started project after a failed `up`.** Its containers hold some of the old ports under its own name; the next choice treats those as its own and Compose recreates them on the new ones.
- **A port held outside Compose** (a container without the Compose label, shown as `(not Compose)`, or any other process) is skipped by `choosePorts` through `isUsable`, and `--check` names it, so the retry also covers it.
- **The T2-08 loopback test covers only the base file now.** The new item 1 test asserts the same of the override.
