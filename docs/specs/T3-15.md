## Goal

A release build of the TV app can send plain HTTP at all. Today it cannot: Android refuses cleartext for an app that targets API 28 or higher unless the app opts in, and the release manifest opts in nowhere. After this task:

1. The release APK carries a network security configuration whose only content is `<base-config cleartextTrafficPermitted="true" />`.
2. Android therefore blocks no plain-HTTP host, and the host classifier (the core's `classifyServerAddress`, and its Kotlin mirror inside the one client) is the only thing that decides which host may get plain HTTP, as decision 0001 and `docs/security.md` §3 say.
3. A probe on the emulator shows both halves: a plain-HTTP request through the one OkHttp client reaches a private-LAN server and a loopback server, and every host the shared vectors call public is refused before a request exists.

## Approach

### Shape

The opening and the gate ship in one package. `modules/session` already holds the classifier and the one client; it now also holds the declaration that lets cleartext through Android. An app that links the module gets both; nothing else in the repository opts in.

That placement is also what makes item 2 testable today. A library's own test APK is built from the library's manifest and resources, so the probe runs in a process whose network security configuration is the same file, through the same manifest attribute, that the release app gets. Without the declaration the probe goes red on the device (Android refuses the connection); with it, green. The release APK check (item 1) proves the same declaration arrived in the app.

### The configuration

```xml
<?xml version="1.0" encoding="utf-8"?>
<network-security-config>
    <base-config cleartextTrafficPermitted="true" />
</network-security-config>
```

No comment inside the file beyond one line naming decision 0001; no other element, ever, without a new task. The debug build type keeps the template's `usesCleartextTraffic="true"`, which Android now ignores because a configuration is present (Facts); the debug build still reaches Metro over plain HTTP because the configuration permits it. Milestone 1 starts one debug build against Metro to confirm.

### The release APK check

`readNetworkSecurity(aapt2, apk)` gathers facts with three `aapt2` calls and no guessing of paths:

1. `dump xmltree <apk> --file AndroidManifest.xml`: the `application` element's `networkSecurityConfig` value (a resource id) and its `usesCleartextTraffic` value, if any.
2. `dump resources <apk>`: the file path of that resource id.
3. `dump xmltree <apk> --file <path>`: the element tree of the configuration.

Since T3-22, `pnpm tv:apk:check` is two scripts in sequence: `tv-apk-check.mjs` (badging, then this network security check) and `tv-apk-manifest.mjs` (T3-22's permissions, queries and backup). Both must print their pass lines; T3-22's lists are not loosened for this task.

`judgeNetworkSecurity(facts)` returns `ERROR tv apk: ...` lines, empty only when: the attribute is present and resolves to a file; the tree is `network-security-config` with exactly one child, `base-config`, with exactly one attribute, `cleartextTrafficPermitted` true, and no children. `usesCleartextTraffic` is neither required nor refused (the debug overlay sets it; it is ignored). The facts object is plain data, so the frozen tests need no `aapt2` text:

```ts
type NetworkSecurityFacts = {
  configAttribute: string | null;      // "@0x7f150002", or null when the manifest has none
  configFile: string | null;           // "res/a1.xml", or null when the id resolves to no file
  usesCleartextTraffic: boolean | null;
  tree: XmlElement | null;             // { name, attributes: Record<string, string>, children: XmlElement[] }
};
```

Attribute values in `tree` are as `aapt2` prints them after the `=`, so a boolean is `"true"` (milestone 1 records the real text; if `aapt2` prints `0xffffffff` or similar for booleans in a resource file, the parser normalises it to `"true"`/`"false"` and the parse test pins that).

### The device probe

`CleartextProbe` extends `android.app.Instrumentation`. `onCreate` calls `start()`; `onStart` runs on the instrumentation thread and ends with `finish(Activity.RESULT_OK, results)`. It uses the module's own internals (`SessionRegistry.open`, `SessionRegistry.close`, `OctaveHttp.callFactory`, `MediaBrowserAuthorization.parse`) and Android's `NetworkSecurityPolicy`, `org.json` and `AssetManager`. It builds no client, opens no socket of its own, and logs nothing.

Argument: `hostPort` (`am instrument -e hostPort <n>`). Result keys, each a fixed word or a number, never a URL, a host, a header or an exception message:

| Key | Value |
|---|---|
| `policy` | `permitted` or `refused`, from `NetworkSecurityPolicy.getInstance().isCleartextTrafficPermitted()` |
| `target-sdk` | the test APK's `applicationInfo.targetSdkVersion` |
| `private-lan` | the HTTP status of `GET http://10.0.2.2:<port>/octave-probe/private-lan`, or `refused-<code>` for an `OctaveHttpException`, or `failed-<ExceptionSimpleName>` (the class name only; Android's block is `failed-UnknownServiceException`) |
| `loopback` | the same for `GET http://127.0.0.1:<port>/octave-probe/loopback` |
| `public-total` | how many vectors of the bundled `host-classes.json` have class `public` |
| `public-refused` | how many of them made `SessionRegistry.open` throw `PUBLIC_HTTP` |
| `public-other` | how many opened (each is closed at once) or threw anything else |
| `https-open` | `ok` when `SessionRegistry.open("https://media.example", ...)` returns a session (closed at once; nothing is sent), else `failed` |
| `done` | `yes`, written last |

The header value is a made-up canary in the builder's five-field shape, the same constant in the probe and in `scripts/tv-cleartext.mjs`; no real token, address or name appears. Each section catches its own failure and writes its key, so one failure does not hide the others.

"Refused before it is sent" rests on where the refusal happens: `SessionRegistry.open` throws before any session entry, `Request` or `Call` exists, so there is nothing to send. The JVM test `HostClassTest` already shows no connection is accepted; the probe shows the same code path gives the same answer on ART for all 60 public vectors (the count is read from the fixture, never written down).

### The run inside `pnpm tv:e2e`

After the conformance run, `runCleartextProbe`:

1. Starts a Node `http` server on `127.0.0.1`, port 0. It records each request's path, `Host` and whether `Authorization` equals the canary header value, and answers 200 with a short fixed body.
2. `adb reverse tcp:<port> tcp:<port>`.
3. `adb install -r -t <probe apk>`, then `adb shell am instrument -w -e hostPort <port> dev.octave.session.test/dev.octave.session.devicecheck.CleartextProbe` (milestone 1 confirms the test package id), with a 60 second limit.
4. Always: `adb reverse --remove tcp:<port>`, `adb uninstall` the probe package, close the server.
5. Writes `release-evidence/tv/e2e-cleartext.txt`: the report keys and one line per served request (path and `header=yes|no` only). No port's meaning, serial or header value is written.
6. `judgeCleartext(report, served, { publicTotal, port })` (the frozen shapes: `report` is `Record<string, string>` as `am instrument` gives it, `served` is `{ path, host, header }[]`), where `publicTotal` is `expectedPublicCount()` from `packages/core/tests/fixtures/host-classes.json`. It passes only when: `done=yes`; `policy=permitted`; `target-sdk` is at least 28 (below that Android permits cleartext by default and the probe proves nothing); `private-lan=200` and `loopback=200`; the server saw exactly one request for each of the two paths, each with the header, the private-LAN one with `Host` `10.0.2.2:<port>` and the loopback one with `127.0.0.1:<port>`, and no other request; `public-total` equals `publicTotal` and `public-refused`, and `public-other=0`; `https-open=ok` (a smoke check; item 3 does not rest on it).

`parseInstrumentation(text)` turns the `am instrument -w` output into that report object. Its input format is recorded in milestone 1, so it is tested in the non-frozen parse test, and it fails closed: output with no result code, or with `INSTRUMENTATION_FAILED`, gives a report without `done`.

The script prints one summary line, `tv e2e: cleartext private-lan ok, loopback ok, public 60/60 refused`, after the existing conformance line. The serial is never printed (as today).
