## Goal

A viewer who has chosen a server signs in without typing:

1. The step shows a six-digit code and a QR code. The QR code opens the server's Quick Connect approval page on a phone with the code filled in. The viewer approves on the phone and presses nothing on the TV.
2. The TV polls until the code is approved, signs in through the native session module, and opens Home.
3. An expired or refused code says so in one sentence and gets a new code in one press. A server with Quick Connect off, or with no Quick Connect, goes straight to the password step.
4. `App.tsx` mounts the signed-out flow, and swaps to `SignedInApp` when a sign-in finishes, so a release build can reach Home and play from it. The password step of T4-04 uses the same swap.

## Facts this spec rests on

**The core already has Quick Connect**

- `quickConnectEnabled(signal)`: tokenless `GET /QuickConnect/Enabled`, true only for a JSON `true` (`packages/core/src/jellyfin/gateway.ts:310-317`).
- `initiateQuickConnect(signal)`: `POST /QuickConnect/Initiate` (POST because Jellyfin 12 removed the GET form), returns `{ secret, code }`, throws `unexpected-response` without both (`gateway.ts:320-330`).
- `pollQuickConnect(secret, signal)`: `GET /QuickConnect/Connect?secret=`, returns `{ authenticated }` (`gateway.ts:334-344`). The API takes the secret in the query string, and the secret is not the token (`:332-333`).
- `authenticateWithQuickConnect(secret, signal)`: the transport's `signIn` with `{ kind: "quick-connect", secret }`, then `startSession` (`gateway.ts:346-351`, `:362-379`).
- All three sign-in calls run `requireTransportConsent()` first, so an unconfirmed private-LAN plain-HTTP server gets no secret (`gateway.ts:294-300`).
- All three send one DeviceId, derived from the install id, the server id and the placeholder user `#quick-connect`, because Jellyfin binds the secret to the Initiate's DeviceId (`gateway.ts:71-75`, `:353-358`; decision 0005, `:238`).
- Every call takes an `AbortSignal` and the 15 s control timeout (`gateway.ts:47`).
- A transport failure reaches the caller as `TransportError` with a `code` and, for `status`, the HTTP status (`packages/core/src/ports/transport.ts:73-104`; `redactTransportError` keeps both, `docs/specs/T4-02.md:37`).
- `gateway-quick-connect-signed-in.test.ts` already proves that Initiate and the poll go tokenless with the sign-in DeviceId (`:34-42`). No core code runs Quick Connect end to end, and no app code calls any of these methods (grep of `apps/tv/src`, 2026-11-26).
- `logout()` ends the session through `transport.endSession` and clears local state first (`gateway.ts:392-406`). `sessionId()` throws when signed out (`:388-390`).
- The core may not use timers or the wall clock outside `adapters/`; it takes them through the `Clock` port (`DOMAINS.md`, dependency rules; `packages/core/src/ports/clock.ts:2-3`). The app's clock is `hostClock` (`apps/tv/src/host/clock.ts:5-15`).

**Jellyfin's Quick Connect (primary source: `jellyfin/jellyfin` at tags `v10.11.7` and `v12.4`, read 2026-11-26)**

- `GET /QuickConnect/Enabled` answers `_quickConnect.IsEnabled` (`Jellyfin.Api/Controllers/QuickConnectController.cs:41-46` at v12.4), which is `QuickConnectAvailable` (`Emby.Server.Implementations/QuickConnect/QuickConnectManager.cs:58`). Its default is `true` on both versions (`MediaBrowser.Model/Configuration/ServerConfiguration.cs:83`).
- `POST /QuickConnect/Initiate` answers **401** "Quick connect is disabled" when it is off (`QuickConnectController.cs:54-68`). 10.11.7 also keeps the obsolete GET form; 12.4 removed it (the two files differ only there and in one attribute).
- `GET /QuickConnect/Connect?secret=` answers **404** "Unknown secret" for a secret the server does not hold, expired ones included, and **401** when Quick Connect is off (`QuickConnectController.cs:77-94`; `QuickConnectManager.cs:98-110`).
- A code is 6 decimal digits (`QuickConnectManager.cs:26, 116-133`). A request expires **10 minutes** after Initiate (`Timeout = 10`, `:31`; `ExpireRequests`, `:198-218`, runs on every call). Approval moves its time one minute ahead "as otherwise some clients wouldn't ever see that they have been authenticated" (`:150-152`), and an authorized secret is kept for 10 minutes (`:163`, `:211-218`).
- **Jellyfin has no "deny".** `POST /QuickConnect/Authorize?code=` only approves (`QuickConnectController.cs:104-120`; `QuickConnectManager.cs:136-170`). On Jellyfin, a code is "refused" only when Quick Connect is turned off while the TV waits (Connect 401) or the sign-in is refused (D4).
- `POST /Users/AuthenticateWithQuickConnect` returns the stored result or throws `ResourceNotFoundException` (`Jellyfin.Api/Controllers/UserController.cs:245-259`; `QuickConnectManager.cs:173-185`). The exception middleware maps `ResourceNotFoundException` to 404, `AuthenticationException` to 401 and `SecurityException` to 403 (`Jellyfin.Api/Middleware/ExceptionMiddleware.cs:127-134`).
- **The approval page.** jellyfin-web has a Quick Connect page at the route `quickconnect` (`src/apps/stable/routes/asyncRoutes/user.ts:5` at web `v10.11.7`; `src/apps/legacy/routes/asyncRoutes/user.ts:5` at web `v12.4`). The page fills its field from the `code` query parameter: `useState(searchParams.get('code') ?? '')` (`src/apps/stable/routes/quickConnect/index.tsx:15-16` at v10.11.7; `src/apps/legacy/routes/quickConnect/index.tsx:23-25` at v12.4). The router is a hash router (`src/RootAppRouter.tsx`, `createHashRouter` at `:5, :24` on v10.11.7 and `:5, :22` on v12.4). So the page is `{server}/web/#/quickconnect?code={code}`. **The server does not send this link.** A client builds it from the web client's route, and Jellyfin cannot be asked before sign-in whether it hosts the web client (D5).

### D2. `QuickConnectSignIn`: the run, in the core

`packages/core/src/jellyfin/quick-connect-sign-in.ts`:

```ts
type QuickConnectState =
  | { phase: "starting" }
  | { phase: "unavailable" }
  | { phase: "waiting"; code: string; link?: string }
  | { phase: "signing-in"; code: string; link?: string }
  | { phase: "signed-in" }
  | { phase: "failed"; failure: QuickConnectFailure };
interface QuickConnectRun { newCode(): void; stop(): void }
function startQuickConnect(gateway: JellyfinGateway, clock: Clock, listener: (state: QuickConnectState) => void): QuickConnectRun;
```

In order:

1. `quickConnectEnabled(signal)`. `false` gives `unavailable`, and so does a `status` 404 (the route is not built). Anything else that fails maps through D4.
2. `initiateQuickConnect(signal)`. A `status` 401 gives `unavailable` (Quick Connect was turned off between the two calls; `QuickConnectController.cs:54-68`). On success: `waiting` with the code and `quickConnectApprovalLink({ serverUrl: gateway.serverUrl, hostClass: gateway.hostClass }, code)`. The run starts `clock.every(POLL_INTERVAL_MS, poll)` and records `startedAt = clock.now()`.
3. Each tick sends one `pollQuickConnect(secret, signal)`. A tick that comes while a poll is in flight is skipped. `authenticated: false` keeps waiting. `true` cancels the timer, emits `signing-in` and calls `authenticateWithQuickConnect(secret, signal)` once. Success emits `signed-in`.
4. **Expiry.** A Connect or sign-in 404 gives `expired`. So does reaching `startedAt + CODE_LIFETIME_MS` (10 min, `QuickConnectManager.cs:31`) without approval, so a server that never answers 404 is not polled for ever.
5. **Unreachable.** A poll that fails with `network` or `timeout` is retried on the next tick. The `UNREACHABLE_POLLS`-th (3) in a row gives `unreachable`. The 15 s request timeout means three failures take at least 15 s. A `network` or `timeout` on steps 1, 2 or the sign-in gives `unreachable` at once.
6. `newCode()` is allowed in `failed` only. It cancels nothing still running (there is nothing), and starts again at step 2, or at step 1 after `unreachable` or `other`.
7. `stop()` aborts the current call's signal, cancels the timer, and drops every later state. If a sign-in was in flight and later resolves with a session, the run calls `gateway.logout()` once, so no session is left in the native registry that no screen holds (`gateway.ts:392-406`). A rejected sign-in after `stop()` is swallowed. **`stop()` after `signed-in` ends nothing:** the step unmounts on every successful sign-in, when `AppRoot` swaps to `SignedInApp`, so `stop()` runs then too. It must leave the session alone; only a sign-in still in flight at `stop()` is logged out.

**The secret never leaves the run.** It is a local of the run's closure. No state carries it, the listener never sees it, and nothing logs it. React therefore never holds it in state or props (`AGENTS.md`, "Never put a token in … React state"; the secret is not the token, but it is the credential that becomes one, and `docs/security.md:15` treats it with the password). It crosses the JavaScript–Kotlin seam in three ways, all by the API's design:

1. **Kotlin to JavaScript, once per code**, in the body of the Initiate answer (`gateway.ts:320-330`). It arrives through `request` like any tokenless answer.
2. **JavaScript to Kotlin, in every poll**, as the `secret` query value of `GET /QuickConnect/Connect` (`gateway.ts:334-344`). That is up to 120 times per code at the 5 s interval.
3. **JavaScript to Kotlin, once**, as the `signIn` argument (`docs/security.md:15`).

`docs/security.md:15` today says the secret crosses "once, from JavaScript to Kotlin". This task is the first to run the path, so milestone 6 **corrects that line** to these three crossings, not only adds a paragraph. Inside JavaScript the secret stays in the run's closure in every case.

**Intervals.** `POLL_INTERVAL_MS = 5000`. It is chosen, not measured; no source gives jellyfin-web's own interval (**unverified**). Over the code's 10 minutes that is at most 120 polls. `CODE_LIFETIME_MS = 600_000`. `UNREACHABLE_POLLS = 3`.

**Native surface.** None of this needs a native change. The four tokenless routes are already allowed by the core and by Kotlin, and the Quick Connect sign-in is already a `signIn` kind (header). `docs/security.md:14-15` already describes them.

### D3. No native work

Checked against `docs/security.md` §1 and decision 0005's surface table: `signIn` takes `{ server, deviceId, kind: "quick-connect", secret, timeoutMs }` (`docs/decisions/0005-token-boundary.md:262`), and `request` takes the three Quick Connect routes as pre-sign-in targets (`RequestPolicy.kt:70-72`). No method, event, argument or route is added. So this is not an architecture change, and `touchesNative=false`.

### D4. Failures

`quickConnectFailure(error, step)` reads only `code` and `status` (as `serverChoiceFailure` does, `packages/core/src/domain/server-choice.ts:66`), never `message`:

| Step | Answer | Result |
|---|---|---|
| Enabled | `false`; `status` 404 | `unavailable` (not a failure; D7) |
| Initiate | `status` 401 | `unavailable` |
| Connect, sign-in | `status` 404 | `expired` |
| Connect, sign-in | `status` 401 or 403 | `refused` |
| any | `network`, `timeout` | `unreachable` (a poll only after D2's three in a row) |
| any | `SignInFailure("redirect")`, transport `redirect` | `redirect` |
| any | `cancelled` / `AbortError` | nothing (stopped) |
| any | anything else (`status` 5xx, `unexpected-response`, `refused`, `not-confirmed`) | `other` |

"Refused" on Jellyfin means the server stopped accepting the code: Quick Connect turned off while the TV waited, or the sign-in answered 401/403 (Facts: Jellyfin has no deny). A server that adds a deny later (Jellyscale #104 is not designed yet) maps through the same 401/403 rows.

### D5. The approval link: who builds it, and when there is none

`quickConnectApprovalLink({ serverUrl, hostClass }, code): string | undefined`, pure, in `domain/quick-connect.ts`:

- **Loopback servers get no link.** For `hostClass === "loopback"` it returns `undefined`: `127.0.0.1` or `localhost` on the TV is the TV itself, so a phone cannot open it. This is the case item 6 names: "the server gives no approval link".
- **Otherwise** it returns `${serverUrl}/web/#/quickconnect?code=${encodeURIComponent(code)}`. `serverUrl` keeps a base path such as `/jellyfin` (`gateway.ts:233-234`), so the link follows it.
- **Who builds it.** The client builds it, from jellyfin-web's route (Facts). No server sends a link: Jellyfin has none, and Jellyscale's is issue #118, still open. Detecting before sign-in whether a server hosts the web client would need a new tokenless route, such as `GET /web/`, on the native allowlist. That is an architecture change (`AGENTS.md`, "Treat every new native module method or event as an architecture change"; the route list is decision 0005's), so it is not done. Confirmed (R4).
- **If the link does not work on a phone** (R4): the task changes nothing more. The code and the sentence "or enter the code in Quick Connect" are the fallback, already on screen. It is judged at the owner's dogfooding (backlog line 393), and a failure there changes this one function, so that such a server gets the no-link form. It is not a real-TV gate: it opens no path into the home network and leaks nothing.
- **Jellyscale** cannot be told apart (it reports "Jellyfin Server", Facts). Today it never reaches this function: its Enabled answers `false` (item 7). When #104 lands, T10-06 decides whether Jellyscale's link is the same page (it serves jellyfin-web) or #118's. The function is the one place that changes.
- **What the QR code never holds.** Only the link string reaches the encoder. It holds the server address and the code. The code is the value the viewer is meant to carry to the phone and is already on screen (`DESIGN.md:352`). The secret, a token and a password are not in the core's state (D2), so the step has nothing else it could encode. Item 2's test proves the encoder's input and scans the whole render tree.

### D6. Drawing the code and the QR code

- **The code.** `groupCode("482913")` gives `"482 913"` (`DESIGN.md:352`); any code that is not six digits is shown as given. It is drawn in `typeCode`. `spokenCode` gives "4 8 2 9 1 3" for `accessibilityLabel`, so TalkBack reads digits, not "four hundred eighty-two thousand…".
- **The QR code.** `uqr`'s `encode(text, { ecc: "M", border: 0 })` returns `{ size, data: boolean[][] }` (`unjs/uqr` README, "encode"; `src/encode.ts:16-50`). `QrCode` draws each row as `View`s, one per run of equal modules, so a version-4 code (33 modules, enough for a 60-character link at level M) takes a few hundred views, not 1,089. Dark modules are `onLight` and the field is `text1`, so contrast is 17:1 (`DESIGN.md` §3.1). A quiet zone of 4 modules is padding in `text1` (ISO/IEC 18004 asks for four). The module size is a whole number of device pixels: `floor(px(sizes.qrSize) / (size + 8))`, so no module is blurred. The size is a new token, `qrSize` in `tokens.ts` and `DESIGN.md` §8, both written in milestone 2, **480** canvas px (R5, call C5; the refiner had 360). The QR view is `accessible={false}` and hidden from TalkBack. The code beside it carries the label.
- **Why a dependency.** A QR encoder is Reed–Solomon codes, masking and version tables. Writing one is several hundred lines of code that Octave would own and test. `uqr` is a dependency-free port of Nayuki's MIT generator (`src/qrcode.ts:4`). It needs no `TextEncoder`: it converts with `encodeURI` (`src/qrcode.ts:722-723`), so nothing it uses is in doubt under Hermes. The maintenance check and the alternatives are under Dependencies; adopted by R3.

- **It learns the secret.** When it relays a 2xx answer to `POST /QuickConnect/Initiate`, it reads `Secret` from the JSON body. It is also added to the recorder's own set of Quick Connect secrets.
- **It blanks only its own poll's value.** Before the URL scan (`:200`), a new helper beside `withoutOwnPlaySession` (`:176`) blanks the secret, defined tightly:
  - `withoutOwnQuickConnectSecret(method, rawUrl, ownSecrets)` acts only on `GET` whose raw path ends `/QuickConnect/Connect`; it matches only the raw parameter name `secret`; it decodes the value **once**, keeping a value that fails to decode; and it blanks it only on exact equality with a secret in `ownSecrets`.
  - It decodes once and matches exactly, unlike `findSecret`'s four rounds and "contains" matching, so it never blanks a value the server would not read as the secret.
  - `withoutOwnPlaySession` (`:176-187`) matches the raw name exactly, decodes the value once and blanks on exact equality, with no path guard; this helper adds the method and path guard.
- **Cases the new judge test must hold.** Blanked, so the run passes: the plain poll, and a secret written with a non-canonical hex escape (`%4X`). Kept, so `judgeRecords` fails: `GET /Items?secret=<secret>`, a `POST` carrying it, a double-encoded value, `x<secret>`, `Secret=`, and a value the recorder never learned.
- **So the run's judges catch it everywhere else.** `judgeLogcat` fails a logcat line that holds the secret in any form `findSecret` knows. The evidence writer replaces it in every file under `release-evidence/wire` and fails a pair if it finds it. `judgeRecords` still fails it in any other URL, any other query value and any query name.

The judge's cases (`scripts/tv-wire-quick-connect.test.ts`) include two that must **fail**:

- a request other than `GET /QuickConnect/Connect` whose URL holds it, and a `Connect` whose secret sits under another query name.

The helper's own cases: the poll's `secret` value is blanked only when learned; an unlearned value stays and fails.

This proves on both Jellyfin versions that the secret stays out of logcat and out of every URL except the poll's. **Settled: how the recorder matches the Quick Connect secret (R8)**

The spec's mechanism (D12, "It blanks only its own poll's value") is not tight enough. Two gaps:

- **No method or path guard.** The heading says "its own poll's value", but the sentence that defines the helper says "each `secret` query parameter whose decoded value is a secret in that own set", in any URL. Written that way, `GET /Items?secret=<S>` would be blanked and pass `judgeRecords`. The must-fail case "a request other than `GET /QuickConnect/Connect` whose URL holds it" would still pass if the test writer put the secret in the path, so the gap would not show.
- **"Decoded" is undefined.** `holdsSecret` (`tv-wire-judge.mjs:48-63`) tries the raw text and four decode rounds, and `findSecret` looks for four rounds of encoding and base64. If the helper used that wide matching, or matched by "contains", it would blank values the server never reads as the secret (`%2541…`, `xx<S>`, base64), so the scan would stop catching them. `withoutOwnPlaySession` (`tv-wire-proxy.mjs:176-187`) is the model, but it does not match raw values: it matches the **raw name** exactly (`[?&]PlaySessionId=`), decodes the value **once**, and blanks it only on **exact equality**; a value that fails to decode is kept. It has no path guard, which is right for a play session but not for this secret.

Jellyfin's secret is hex, so its percent-encoded form is the same as its raw form. One decode therefore covers non-canonical escapes such as `%41`, which the server also reads as the secret. A second duplicate `secret=<S>` on the poll is blanked too, but the judge's Connect rule (query names exactly `["secret"]`) already fails that request, so it needs nothing more.

**What the spec should add**, word for word, as the second bullet of D12's R8 list:

> **It blanks only its own poll's value.** Before the URL scan, a new helper `withoutOwnQuickConnectSecret(method, rawUrl, ownSecrets)` beside `withoutOwnPlaySession` returns `rawUrl` unchanged unless `method` is `GET` and the raw path (the text before the first `?`) ends with `/QuickConnect/Connect`. On that request it matches each parameter whose **raw** name is exactly `secret` (`/([?&]secret=)([^&#]*)/g`; case-sensitive; an encoded name such as `%73ecret` or `Secret` does not match). It decodes the value with **one** `decodeURIComponent` (no `+`-to-space; a value that fails to decode is kept), and it blanks the value only when the result **equals** a secret in `ownSecrets`. Every other form is kept and so fails the scan: a value that equals the secret only after a second decode, a value that only contains it, base64, another name, another method or another path.

- `GET /QuickConnect/Connect?secret=<S>` blanked.
