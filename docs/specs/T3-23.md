## Goal

`pnpm tv:apk:check` reads each attribute of the release manifest and of the data extraction rules file the way Android reads it, so no other attribute can stand in for the one Android uses.

Today `parseAttribute` in `scripts/tv-apk-manifest.mjs` (line 44) drops an attribute's namespace and keys it by its local name, and `parseXmlTree` (line 81) lets a later attribute replace an earlier one. T3-22's review reproduced two passes that should fail:

- A `uses-permission` with `android:name="android.permission.CAMERA"` followed by a `name` of `android.permission.INTERNET` in another namespace passes `judgeManifestSurface`.
- An `application` with `android:allowBackup=true` followed by an `allowBackup` of `false` in another namespace passes `judgeBackup`.

After this task:

1. Both reproductions fail the check.
2. The check takes a manifest attribute only when it carries a framework resource id, and a rules-file attribute only when it has no namespace.
3. An element with two attributes of one local name is an error that names the element and the attribute.
4. `docs/security.md` §6 says how the check reads attributes.

## Facts this spec rests on

Each fact names its source. AOSP files were read on 2026-11-21 from `https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/<path>`.

**How Android reads the manifest.**

- An element is found by its local name: `String tagName = parser.getName()` and `case TAG_USES_PERMISSION:` (`core/java/com/android/internal/pm/pkg/parsing/ParsingPackageUtils.java`, lines 781 and 1106). `getName()` returns the element's name string (`core/java/android/content/res/XmlBlock.java`, line 241), and the binary file holds an element's name and its namespace as two separate strings (`ResXMLParser::getElementNameID` and `getElementNamespaceID`, `libs/androidfw/ResourceTypes.cpp`, lines 1365 to 1397), so the namespace is not part of it.
- An attribute is found by its resource id, not by its name or namespace. `parseUsesPermission` calls `res.obtainAttributes(parser, R.styleable.AndroidManifestUsesPermission)` (same file, line 1382), and `allowBackup`, `fullBackupContent` and `dataExtractionRules` are read from the same kind of array (lines 2411, 2096, 2472). `obtainAttributes` ends in `RetrieveAttributes`, which compares `xml_parser->getAttributeNameResID(ix)` with the wanted ids (`libs/androidfw/AttributeResolution.cpp`, lines 352 to 383).

**How Android reads the data extraction rules file.**

- `domain` and `path` are read with no namespace: `parser.getAttributeValue(null, "domain")` and `parser.getAttributeValue(null, "path")` (`core/java/android/app/backup/FullBackup.java`, lines 720 and 731).
- A null namespace matches only an attribute that has no namespace (`ResXMLParser::indexOfAttribute`, `libs/androidfw/ResourceTypes.cpp`, lines 1611 to 1619).
- Elements are found by local name (`parser.getName()`, same file, lines 694, 857, 871, 879).

**How Android reads a network security configuration** (T3-15's file, for "Two bases" only): by local name in any namespace, with a later attribute replacing an earlier one. `XmlConfigSource.java` loops over `parser.getAttributeName(i)` and tests `"cleartextTrafficPermitted".equals(name)` (`core/java/android/security/net/config/XmlConfigSource.java`, lines 243 to 249).

**What `aapt2 dump xmltree` prints** (`tools/aapt2/Debug.cpp`, `XmlPrinter`, lines 491 to 534):

- An element: `E: ` then `<namespace uri>:` when the element has a namespace, then `<name> (line=N)`.
- An attribute: `A: ` then `<namespace uri>:` when it has one, then `<name>`, then `(0x<8 hex digits>)` only when the attribute has a resource id, then `=` and the value, then ` (Raw: "…")` when the raw string is not empty.
- The id it prints for an APK is the id in the binary file, which is the one Android compares: `uint32_t res_id = parser->getAttributeNameResID(i); if (res_id > 0) attr.compiled_attribute = …` (`tools/aapt2/xml/XmlDom.cpp`, lines 242 to 245).

**Which attributes get a framework id.**

- aapt2 gives an attribute an id only when its namespace names a package: `http://schemas.android.com/apk/res/<package>`, `http://schemas.android.com/apk/prv/res/<package>` or `http://schemas.android.com/apk/res-auto` (`ExtractPackageFromNamespace`, `tools/aapt2/xml/XmlUtil.cpp`, lines 36 to 59; the constants are in `XmlUtil.h`, lines 27 to 30; the lookup is in `tools/aapt2/link/XmlReferenceLinker.cpp`, lines 63 to 91).
- So a namespace other than `…/apk/res/android` can carry a framework id: the private form `…/apk/prv/res/android`. Android reads such an attribute, because it compares ids. That aapt2 accepts `prv/res/android:backupAgent` in an app's manifest is unverified (read from the code path, not run).
- An attribute in any other namespace, or in none, gets no id and is kept as a string (the `default_attribute` branch, same lines). Android does not read it from the manifest.

## Approach

### The reading rule

One reader, three reading modes. The caller names the mode; there is no default, and an unknown or missing mode throws, so a call site cannot pick the wrong one by omission.

| Mode | Used for | An attribute is taken when | Source |
|---|---|---|---|
| `"manifest"` | `AndroidManifest.xml` | its line prints a framework resource id, `(0x01` and six hex digits `)` | Android compares ids |
| `"no-namespace"` | the data extraction rules file | its line prints no namespace | `getAttributeValue(null, …)` |
| `"any-namespace"` | T3-15's network security configuration, only if PR #264 has merged | always | `getAttributeName(i)` |

In every mode:

- A taken attribute is stored under its local name in `attributes`, so the tree shape `{ name, attributes, children }` is unchanged.
- An attribute that is not taken is not stored. It still counts for the duplicate rule.
- **Duplicate rule.** When an element has a second attribute with a local name it already has, taken or not, in any namespace and in any order, the reader records a problem: `<element> (line=N) has two attributes named <name>`. The first taken attribute stays; nothing replaces it.
- An element is stored under its local name: the text after the last `:` of what follows `E: ` (D4).
- A line the reader cannot split is unreadable, as today, and the document fails closed. That covers a namespace URI holding `=`. Added by the review fixes (2026-11-22): a namespace holding `=`, a quote, `(` or whitespace, a quoted value holding a quote, a `(Raw: "…")` copy that differs from the value, any other text after the value, and a bare value holding `=`, a quote or whitespace are all unreadable.

Splitting an attribute line: take the text before the first `=`; strip a trailing `(0x<hex>)` and keep it as the id; the local name is the text after the last `:`, and the namespace is the text before it. The local name must match the pattern used today.

Why resource id and not the android namespace URI for the manifest: Android reads by id, and the private namespace `…/apk/prv/res/android` can carry a framework id (Facts). A reader keyed on the URI would miss an `android:backupAgent` written in the private namespace, which Android reads. A reader keyed on the id cannot.

### What stays

- `judgeManifestSurface(text)`, `judgeBackup(facts)` and `checkManifest(dump, apk)` keep their signatures and return `ERROR tv apk: …` lines.
- `judgeBackup` still takes hand-built trees keyed by local name. It does not see namespaces; the reader has already applied the mode.
- The tree has no new property, so `toEqual` against a hand-built tree still holds.
- `ALLOWED_*`, `resolveResourceFile`, `readBackup`'s three parameters and the command-line output are unchanged.

### How the problems reach the caller

- The reader returns `{ tree, problems }`. `tree` is null when a line is unreadable. `problems` holds the duplicate lines, without the `ERROR tv apk:` prefix.
- `parseXmlTree(text, mode)` stays exported and returns `tree` alone. It throws without a mode.
- `judgeManifestSurface(text)` reads in `"manifest"` mode and returns one error line per problem, for every element of the manifest, before its own findings. So a duplicate on `<application>` is reported once, here.
- `readBackup` reads the rules file in `"no-namespace"` mode and puts its problems in a new optional field, `rulesProblems`, on the facts. `judgeBackup` returns one error line per entry. Facts without the field behave as today, which is what the frozen tests pass.
- `checkManifest` and `main` read the manifest in `"manifest"` mode.

Names for the reader function and the mode strings are the implementer's to settle, since the frozen tests reach them only through the three judges.

### Decision log

- **D1. The manifest is read by framework resource id, not by the android namespace URI.** Why: that is the comparison Android makes, and the private namespace can carry a framework id (Facts). No table of expected ids is kept: aapt2 derives an android attribute's id from its name, so in an APK aapt2 built, a framework id and a local name agree. A forged binary manifest whose name string disagrees with its id is outside what this check guards; it checks the APK our build made.
- **D2. A duplicate local name is an error in every mode, across namespaces.** The acceptance asks for it. It also makes the result independent of attribute order, and it covers the network security file, where Android itself lets a later attribute win.
- **D3. The reading mode is a required argument.** A default would let a new call site read the manifest in the rules file's mode, where every android attribute is absent and `backupAgent` passes unseen.
- **D4. An element is read by its local name.** Android finds elements with `getName()`, which drops the namespace, and the dump prints a namespaced element as `E: <uri>:<name>`. Today such a `uses-permission` is skipped by `judgeManifestSurface`. This is the same reader and the same kind of gap, one line to fix, but no acceptance item names it. It is a scope choice for the Product Owner: its test is in the unfrozen extra file, and if it is struck the implementer appends a backlog line for it. Whether the merger and aapt2 keep a namespaced element is unverified (milestone 1's optional probe).
- **D5. New frozen tests go in a new file.** `scripts/tv-apk-manifest.test.ts` is frozen by T3-22 and stays byte-identical.
- **D6. The two unmarked §6 sentences are fixed here.** They are the second low of plan 006, the Product Owner log says this spec should read the plan, and item 5 edits the same paragraph. It is a marker on a claim in a document, not on-screen wording. Provisional under the Product Owner. The other four lows of plan 006 are gaps in T3-22's tests and stay out (Risks).

### Review fix: the Raw copy (2026-11-22)

`dd403a49` made `parseAttribute` fail closed on a namespace holding `=`, a quote, `(` or whitespace, but accepted any text inside `(Raw: "…")`. Two lines still read as an attribute Android never sees: `A: allowBackup(0x01010280)="false" (Raw: "x" y:foo="bar" (Raw: "bar")` (manifest mode, read as allowBackup false) and `A: path="." (Raw: "y" (Raw: "." (Raw: "y")` (no-namespace mode, read as path `.`). Now a quoted value may hold no quote and the Raw copy must be that same value; anything else is unreadable and fails closed. All 176 Raw lines in the recorded dumps and the built APK's manifest and configuration read as before (`pnpm tv:apk:check` above). Tests: `scripts/tv-apk-manifest-namespace-extra.test.ts`, "a Raw copy that is not the value itself is unreadable".

Not closed (plan 006): a namespace URI holding a line break could print as several whole attribute lines, which no reading of the text can tell from real ones. Whether the merger and aapt2 keep such a URI is unverified.
