## Goal

A React screen draws server artwork by naming it, never by addressing it. A new local Expo module, `@octave/artwork` (`modules/artwork`), has one native view, `OctaveArtworkView`, whose only props are `session`, `itemId`, `imageType`, `tag` and `width`, and whose only event is `onArtworkState` with `{ state: "loaded" | "failed" }`. Kotlin builds the request `GET {base}/Items/{itemId}/Images/{type}?tag=&maxWidth=&quality=90&format=Webp` (`ARCHITECTURE.md` §4, "Images"), sends it through the one OkHttp client with the session's header, decodes it off the main thread at the drawn size, and keeps it in a memory cache keyed by session, item, type, tag and width. The header, the token and the URL stay in `modules/session`'s HTTP package.

In React, `createNativeArtwork` fills T3-08's artwork slot (`apps/tv/src/design/rows/artwork.tsx`). A plain `surface2` shows until the image arrives, and a failed image calls the slot's `onFailed`, so the card shows its title, as T3-08 already draws it.

## Facts this spec rests on

- **The slot.** `ArtworkComponent = ComponentType<{ image: ImageRef; width: number; height: number; onFailed: () => void; testID?: string }>`. `MediaCard` passes `cardWidth(variant)` in canvas px: `sizes.posterW` 248 and `sizes.thumbW` 416 (`apps/tv/src/design/tokens.ts:71-72`). On `onFailed` it shows `surface2` with the title in `typeLabel` (`media-card.tsx`), and it resets the failure when `item.id` changes. `ImageRef` is `{ itemId, type: "Primary" | "Backdrop" | "Thumb" | "Logo", tag, blurHash? }` (`packages/core/src/domain/catalog.ts:17-26`).
- **The session module.** `OctaveHttp.newCall(request, authority)` is `internal`. `SessionRegistry.entry` is `internal`, and `SessionId.parse` and `SessionRegistry.holds` are public. `SessionInterceptor` adds the header, runs `RequestPolicy` (origin pin, base-path containment C2 with P1 to P7, credential names, the token in a URL) and refuses every 3xx. `ResponseCaps.SESSION_READ` is 8 MiB. `ServerAddress.url(path, query)` and `QueryEncoding.encode` build the URL (`SessionTransport.buildRequest`).
- **The dex check.** S1 counts an invoke on `okhttp3.Call$Factory` as a sink, and Octave's code may hold S1 only in `OctaveHttp` and `SessionCallFactory` (`scripts/tv-apk-dex-lists.mjs:131`). A class under `modules/artwork` that calls `callFactory(session).newCall(...)` would fail `pnpm tv:apk:check`. Rule D8 fails an Octave module outside the `dev.octave.` Java package.
- **The frozen surface test.** `scripts/tv-module-surfaces.test.ts` (frozen by T8-01) asserts `allowlist.views` is `[]` for the session module, and a planted `View(SessionView::class)` there fails. It reads only the player and session modules.
- **Expo 58.1.0's view DSL** (read from `node_modules/.pnpm/expo-modules-core@58.1.0_.../android/src/main/java/expo/modules/kotlin/views/ViewDefinitionBuilder.kt`): `Events(vararg)` at line 191, `OnViewDidUpdateProps` at line 104 and `OnViewDestroys` at line 86. `viewevent/ViewEventDelegate.kt` provides `EventDispatcher`.
- **Pinned Jellyscale** (`b920b193cd6f`, read with `git show` in the local clone): `GET /Items/{itemId}/Images/{imageType}` is `AccessAnyone` ("an <img> cannot send a token"). It serves `primary`, `thumb` and `chapter` and answers 404 for any other type. - **Jellyfin fixtures** carry `ImageTags.Primary` on items too (`packages/core/tests/fixtures/jellyfin/12.4.0/home-latest.json`). Both pinned servers can therefore draw a Primary for `GET /Items/Latest`.

## Approach

### The JavaScript surface

`modules/artwork/src/index.ts`:

```ts
export type ArtworkImageType = "Primary" | "Backdrop" | "Thumb" | "Logo";
export interface OctaveArtworkViewProps {
  readonly session: string;   // the opaque session id
  readonly itemId: string;
  readonly imageType: ArtworkImageType;
  readonly tag: string;
  readonly width: number;     // drawn width in canvas px
  readonly onArtworkState?: (event: { nativeEvent: ArtworkStateEvent }) => void;
  readonly style?: ViewStyle;
}
export interface ArtworkStateEvent { readonly state: "loaded" | "failed" }
```

`createNativeArtwork({ view, session })` takes the view component and a `() => string | undefined` session getter, so Jest injects a fake view and the composition root later passes `() => gateway.sessionId()` behind a guard. It returns a memoised component for the slot:

- With no session, it draws the placeholder and calls `onFailed` once in an effect, and draws no native view.
- Otherwise it draws `<View style={{ flex: 1, backgroundColor: colors.surface2 }}>` with the native view absolutely filling it. It passes `session`, `image.itemId`, `image.type`, `image.tag` and `Math.round(width)`. On `failed` it calls `onFailed`; `loaded` changes nothing in React.
- It passes no `blurHash`, `height` or `testID` to the native view (the `testID` goes on the wrapper).

### The native module

`OctaveArtworkModule` (`Name("OctaveArtwork")`) defines one `View(OctaveArtworkView::class)` holding five `Prop`s, `Events("onArtworkState")`, `OnViewDidUpdateProps` (start a load once a batch of props is in) and `OnViewDestroys` (cancel and drop the bitmap). It defines no function, module event, property or constant. The allowlist file:

```json
{ "module": "OctaveArtwork", "functions": [], "events": [],
  "views": [{ "name": "OctaveArtworkView", "props": ["session", "itemId", "imageType", "tag", "width"], "events": ["onArtworkState"] }],
  "pending": {} }
```

`OctaveArtworkView` is an `ExpoView` with one `ImageView` child (`CENTER_CROP`, no background, so `surface2` shows through). `val onArtworkState by EventDispatcher()` emits `mapOf("state" to "loaded" | "failed")`, at most once per key. When the props change, the view cancels its job, clears its bitmap and starts a load for the new key. A result whose key is no longer the view's current one is dropped. The bitmap is set on the main thread.

### The fetch (`modules/session`, HTTP package)

```kotlin
class ArtworkRequest(val itemId: String, val type: String, val tag: String, val width: Int) {
  companion object { fun cappedWidth(type: String, width: Int): Int? }   // the one cap
}
sealed class ArtworkAnswer { class Bytes(val bytes: ByteArray) : ArtworkAnswer(); object Failed : ArtworkAnswer() }
object ArtworkFetch {
  fun prepare(session: SessionId, request: ArtworkRequest): PreparedArtwork?   // null: refused, nothing sent
}
interface PreparedArtwork { fun execute(timeoutMs: Long): ArtworkAnswer; fun cancel() }   // internal implementation
```

- `PreparedArtwork` is a public interface with an internal implementation, and `ArtworkAnswer.Bytes` has a public constructor, so the artwork module's JVM tests fake both (spec check issue 1).
- `ArtworkRequest.cappedWidth(type, width)` is null for a type outside `Primary`, `Backdrop`, `Thumb` and `Logo` (exact case) or a width below 1; otherwise `min(width, 400)` for `Primary` and `min(width, 1920)` for the others. It is the only place the cap is computed: `ArtworkFetch` uses it for `maxWidth` and `ArtworkKey.of` for the cache key, and the shared vectors hold it (spec check issues 2 and 3).
- `prepare` returns null, and nothing is sent, when the registry holds no entry for the session, or when `itemId` or `tag` is not 1 to 64 or 1 to 128 characters of RFC 3986 unreserved (`[A-Za-z0-9._~-]`). It also returns null when `cappedWidth` refuses the type or the width, or when the path `/Items/{itemId}/Images/{type}` fails `RequestPath.isSafe`.
- The query is `tag`, `maxWidth`, `quality=90`, `format=Webp`, in that order, through `QueryEncoding.encode`. The URL is `entry.address.url(path, query)`.
- `execute` is one `GET` through `OctaveHttp.newCall(request, CallAuthority.Session(session))`, with an `Accept: image/*` header, `timeoutMs` as the call timeout, and no resend. A 2xx answer whose body is within `ResponseCaps.SESSION_READ` (8 MiB, read as `SessionTransport.readLimited` does) is `Bytes`. Every other outcome is `Failed`: a status, an `OctaveHttpException` refusal (3xx included), an `IOException`, a cancel, an oversized body, `OutOfMemoryError`. No exception, message, URL or header leaves `ArtworkFetch`.
- A 401 does not end the session here. Decision 0005's "a confirmed 401 ends the session" is T4-05's, and it applies to images then.
- `toString()` of every public type is redacted, as `SessionId`'s is.

### The loader (`modules/artwork`, `load/`, plain Kotlin)

`ArtworkLoader(source, decoder, holds, cacheBytes, parallelism = 4)`:

- `source` is `(SessionId, ArtworkRequest) -> PreparedArtwork?` (in production `ArtworkFetch::prepare`), `holds` is `SessionRegistry::holds`, and `decoder` is `ArtworkDecoder`, `decode(bytes, width): Decoded?`, where `Decoded` carries an opaque image and its byte size.
- `suspend fun load(key): Result` checks the cache first and serves a hit only while `holds(key.session)`. On a miss it fetches and decodes on a dispatcher limited to four, puts a success in the cache and returns it. A failure is returned and not cached. Cancelling the coroutine calls `PreparedArtwork.cancel()`.
- `ArtworkKey.of(session, itemId, type, tag, width: Double)` is the view's prop conversion: it rounds the drawn width, refuses a NaN, an infinite value or one that rounds below 1, and caps it with `ArtworkRequest.cappedWidth`, so 600 and 400 for a Primary share one entry. `toString()` is redacted.
- A hit for a session `holds` answers false for is `Failed`, fetches nothing and drops every cached entry of that session (spec check issue 9). Nothing recycles a bitmap: an evicted one may still be drawn by a mounted view, and the garbage collector frees it.
- `ByteBoundedLru` is a plain `LinkedHashMap` in access order with a byte budget, under one lock. The production budget is `min(memoryClass MiB / 8, 32 MiB)` (`ActivityManager.memoryClass`), read once in the module.
- `DecodeSize.sampleFor(sourceWidth, sourceHeight, width)` is the largest power of two that keeps the decoded width at or above `width`. The decoder refuses a source wider or taller than 8192 px, or with a zero side.

`BitmapArtworkDecoder` reads the bounds with `inJustDecodeBounds`, applies `sampleFor`, and decodes `ARGB_8888` with `BitmapFactory.decodeByteArray`. A `null` result or any `Throwable` is `null`. BitmapFactory reads the JPEG that Jellyscale sends and the WebP that Jellyfin sends.

### The wire tests

Both run in the e2e app after the T3-05 tests, in list order, against their pair's port.

- **`artwork-header-and-cache`** (targets `mock`, `jellyfin-10-11`, `jellyfin-12`, `jellyscale`): the test connects and signs in through the gateway, calls `gateway.latestItems()`, and takes the first three cards that have an `image` (Primary). It shows one poster-width (`cardWidth("poster")`) `createNativeArtwork` view per card and waits up to 20 s for each to report a state. Then it shows nothing, shows the same views again, waits again, and logs out. Line: `outcome=ok images=<k> first=<loaded>/<k> second=<loaded>/<k>`. The host judge `judgeArtworkCapture(records, { host, secrets, images })`:
  - runs `judgeRecords`, so every request has the MediaBrowser header and a token after sign-in, no secret is in a URL, the Host is the recorder's and no 3xx was relayed;
  - requires the non-image requests in order: `GET /System/Info/Public`, `POST /Users/AuthenticateByName`, `GET /Items/Latest`, `POST /Sessions/Logout`;
  - requires exactly `k` image requests, each `GET` to `^/Items/[^/]+/Images/Primary$` with the query names `tag,maxWidth,quality,format`, all with distinct paths, all after `/Items/Latest` and before the logout. A repeat is allowed only right after a 503 with `Retry-After: 0` (OkHttp's own, as `judgeCapture` allows); any other repeat fails (spec check issue 6);

### Decision log

- **D1. A module of its own, not a view on the session module.** The frozen `tv-module-surfaces.test.ts` pins the session's `views` to `[]`, and decision 0005's amendment gives each native module one allowlist. A separate module keeps the session's JavaScript surface at decision 0005's four methods and one event, and it follows the player's pattern (T8-01).
- **D2. The fetch lives in the session's HTTP package.** The URL needs the registry entry's address, which is `internal` there. The dex check forbids a `Call.Factory` invoke in any other Octave class. And the token stays in the package that holds it. `modules/artwork` sees only bytes or `Failed`.
- **D3. The props are `session`, `itemId`, `imageType`, `tag` and `width`.** "A size" is the drawn width in canvas px. Height is left to the layout (`CENTER_CROP`). `blurHash` is not passed, because item 1 says "only".
- **D4. One view event, `onArtworkState { state }`.** The slot needs `failed`. The wire test needs `loaded`, and so will T3-12's crossfade. The payload is a fixed word.
- **D5. Width in canvas px, capped at 400 for `Primary` and 1920 otherwise.** The cap makes item 3 hold for every Primary, an episode still drawn at thumb width included (416 becomes 400). On a 4K panel the art is drawn from a canvas-sized image; see Risks.
- **D6. A plain `surface2` placeholder**, the same surface as the missing-image frame, but without the title. It is within item 5's "or plain surface". The owner chose a blurred preview (BlurHash, decoded natively) on 2026-11-23 (`docs/specs/decisions-owner-inbox-2026-11-23b.md` §3). That needs a sixth view prop, which item 1 and decision 0005 forbid, so it is a task of its own (`tasks/backlog.jsonl` line 319). The plain surface here is a provisional stand-in, settled, not the owner's choice; no prop is added and no BlurHash path is built.
- **D7. A memory cache only.** It is keyed by session as well as item, type, tag and width, so two servers or two sign-ins never share an entry. It is served only while the registry holds the session, and it is bounded at `min(memoryClass/8, 32 MiB)`. No disk cache: OkHttp's cache stays `null` (`OctaveHttp.kt`), and the acceptance asks only for the second visit. T3-12 may tune the budget.
- **D8. No in-flight de-duplication.** Two views that mount the same key before the first load finishes make two requests. This is rare on Home and keeps the loader simple. The wire test waits for `loaded` before it mounts again.
- **D9. No resend, 15 s timeout, at most four loads at once,** each on a dispatcher off the main thread (`ARCHITECTURE.md` §1 item 4, T3-14). A failed image is tried again only when the card mounts again.
- **D10. The header goes even to Jellyscale's public image route.** `ARCHITECTURE.md` §4: every image request carries the header. The route's openness is Jellyscale's choice and changes nothing here.
