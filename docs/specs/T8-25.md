## Goal

Today the session state a screen will read (`PlaybackSessionState`, `packages/core/src/player/session-state.ts:6-17`) holds `error?: string`. For a failure that is not a transport error, `failureAction` (`packages/core/src/player/session-failure.ts:7-10`) fills it with `errorReason(error, …)`, the exception's message through `safeReason`, a lexical filter that T9-07 left with known holes: a single-label host (`connect to nas failed`), the last word of a spaced folder path (`/home/u/My Movies`), a code-namespace host (`java.home.lan`) and a MAC address (`tasks/backlog.jsonl:244-247`). The owner decided that no screen shows reason text at all.

After this task:

1. A failure in `PlaybackSessionState` is one code from a closed list, `PlaybackFailureCode`, and a reporting warning is one code from a closed list, `ReportingWarningCode`. The state has no string field that a failure can fill from an exception, the player, the system or the server.
2. Each code names exactly one row of `DESIGN.md` §10's copy table, and the core holds that row's title, body and actions as `PLAYBACK_FAILURE_COPY`. A test reads `DESIGN.md` and fails for a code with no row. No sentence is coined; where a row is missing, the question goes to the owner.
3. The code is chosen from the error's class and its typed code fields only, never from message text.
4. The filtered native reason (`errorReason`) goes only to a `FailureLog` sink that the caller of `failureAction` must pass. It never enters an action, the state, an event or a prop. `docs/security.md` says so.

No native method, event, port member, dependency or on-screen sentence is added. No screen reads the state yet (`git grep` finds no reader of `PlaybackSessionState`, `failureAction` or `errorReason` in `apps/tv/src`); T8-04 and T8-17 are the first, and both depend on this task.

## Approach

### The closed lists (`domain/playback-failure.ts`)

`PLAYBACK_FAILURE_CODES = ["server-unreachable", "server-error", "stop-failed", "unsafe-stream", "request-failed", "session-ended", "decoder-unavailable", "audio-output-failed"] as const`, one per `DESIGN.md` playback-error row (the last three are the owner's rows of 2026-11-23, option C). `REPORTING_WARNING_CODES = ["report-failed"] as const`, for the "Progress report failed" row. `FailureCopy = { row: string; title?: string; body: string; actions: readonly string[] }`, copied verbatim from the `DESIGN.md` §10 rows, found by their State cell.

### Which code for which error (`playbackFailureCode`)

Checked in this order, by `instanceof` and typed fields only:

| Error | Code |
|---|---|
| `PlayerStopError` | `stop-failed` |
| `LaunchRefusedError` | `unsafe-stream` |
| `PlaybackRefusedError` with `reason: "unsafe-transcoding-url"` | `unsafe-stream` |
| any other `PlaybackRefusedError` | `request-failed` (D3) |
| `PlayerEngineError` | `playbackFailureForPlayerError(playerErrorCode(error.code))` |
| `classifyTransportError(error)` is `network` / `server` / `request` | `server-unreachable` / `server-error` / `request-failed` |
| anything else (a string, a plain `Error`, `PlaybackCancelledError`, `SignInFailure`) | `request-failed` |

`playbackFailureForPlayerError`: `network` → `server-unreachable`, `server-error` → `server-error`, `unsafe-playlist` → `unsafe-stream`, `stop-failed` → `stop-failed`, `unknown` → `request-failed`, `session-ended` → `session-ended`, `decoder-unavailable` → `decoder-unavailable`, `audio-output-failed` → `audio-output-failed`, and `unsupported-request`, `malformed-media`, `decoder-failed` → `request-failed` (owner answer, D2).

A caller should not dispatch a `PlaybackCancelledError` (a cancelled attempt is not a failure to show); that is T8-04's and T8-17's wiring, and `failureAction` still gives a code for it rather than throwing.

### The log path

`failureAction(error, log)` returns `{ type: "failure", code: playbackFailureCode(error) }` and calls `log(errorReason(error, "Something went wrong."))` once. `reportingWarningAction(message, log)`: `undefined` gives `{ type: "reporting-warning" }` (clears); `"report-failed"` gives `{ type: "reporting-warning", code: "report-failed" }`; any other string goes to `log` and gives `{ type: "reporting-warning" }` with no code, leaving the state's warning as it was (D4). The core writes no log itself. Where the sink writes is the caller's: T8-04 wires it, and T9-06 decides whether diagnostics hold it. `pnpm lint:logs` forbids a value log call in `apps/tv/src/host`, so the sink cannot live there (Risks).

### Decision log

- D1. One code per `DESIGN.md` row, not per cause. The engine codes and transport kinds map onto rows, so "each code has one row" holds by construction and the screen needs no second lookup.
- D2. Option C (owner, 2026-11-23): `session-ended`, `decoder-unavailable` and `audio-output-failed` are failure codes with their own "Playback stopped" rows; `unsupported-request`, `malformed-media` and `decoder-failed` map to `request-failed`. The ruling's replacement assertions use `playbackFailureForPlayerError(...)`.
- D3. Refusals other than an unsafe URL map to `request-failed` here. T8-17 (which depends on this task) adds one code and one owner-approved row per refusal reason; adding them here would coin sentences.
- D4. A reporting warning becomes a code too, so item 1 holds for the whole state. The shutdown-deadline and conversion-stop sentences are Octave's own but are not on the copy table; they go to the log, which also keeps `coordinator.test.ts:444` (frozen) unchanged, since it reads the coordinator callback, not the state.
- D5. `FailureLog` is a required parameter, not optional, so no caller can drop the reason or keep it by accident.
- D6. `PLAYER_ERROR_MESSAGES` and `PlayerEngineError.message` stay (frozen T2-05 case; the port is not edited). They are an `Error`'s message, not state, and no screen reads them.
