## Goal

T3-15 lets every HTTP client in the app's process send plain HTTP to any host, and T3-04 fences those clients by reading source and name lists. This task checks the same fence on what ships:

1. `pnpm tv:apk:check` gains a third step, `scripts/tv-apk-dex.mjs`. It reads the release APK's dex files and R8's mapping file, finds every instruction that can open a connection, attributes each to its original class, and fails when one belongs to Octave's code outside the one client, when one belongs to a class that is not on a named list, or when Octave's code references a listed class.
2. The same step holds `DevSupportHttpClient` to four named callers, and `pnpm tv:smoke` shows that the release app opens no connection to the development server.
3. The Expo modules the app does not need are excluded from autolinking, the dex check fails if their classes come back, and `LINKED_NETWORK_PATHS` loses their rows.

## Approach

### Shape

`node scripts/tv-apk-dex.mjs [apk] [mapping]` (defaults: `RELEASE_APK` from `scripts/tv-apk-check.mjs:15` and the mapping path in Facts):

1. Read the APK's zip central directory in Node (no dependency): the `classes*.dex` entry names, and each dex's `~~R8{…}` marker, found by inflating the entry with `node:zlib`.
2. Read the mapping file as a stream: its `# pg_map_id`, the class lines, and the member lines.
3. Run `dexdump -d <apk>` (`newestBuildTool(androidSdk(), "dexdump")` from `scripts/tv-android-sdk.mjs`, as `aapt2` is found today) and read its output as a stream, not into one buffer.
4. Judge (D0 to D6) and print one `ERROR tv apk dex: …` line per finding, or one line `tv apk dex: <apk> passes (<n> classes in <d> dex files, <s> sink references in <e> listed entry points, 0 in Octave's code outside the one client)`.

`main(args, system)` takes what it reads and runs as a second argument with a default, as `buildTv` does (`scripts/tv-build.mjs`, `SYSTEM`): the `dexdump` path (default `newestBuildTool(androidSdk(), "dexdump")`), the two default paths, the output streams, and `lists` (default `PRODUCTION_LISTS`; "Why the frozen dex tests use their own lists"). The tests pass a fake `dexdump`, their own paths and their own lists, so they need no `ANDROID_HOME`. The command line cannot replace the lists: only a caller of `main` can.

Every message names what to do: send through `OctaveHttp.callFactory(session)`, or add a row with its reason, or remove the dependency. The check must finish in well under a minute on the probe build's sizes.

### Sinks

`NETWORK_SINKS`: an instruction is a sink reference when it names one of these. Framework classes are never renamed; OkHttp's are, and are found through their class lines.

| Id | Sink |
|---|---|
| S1 | Any reference (invoke, field, `new-instance`, `const-class`, `check-cast`, `instance-of`) to `okhttp3.OkHttpClient` or `okhttp3.OkHttpClient$Builder`; an invoke on `okhttp3.Call$Factory` or `okhttp3.WebSocket$Factory`. Read with decision log 14 (the one Octave invoke that is not judged) and 15 (a descriptor or a declaration that has the type is a reference) |
| S2 | `java.net.URL.openConnection`, `.openStream`, `.getContent` |
| S3 | Any reference to `java.net.URLConnection`, `HttpURLConnection`, `JarURLConnection` or `javax.net.ssl.HttpsURLConnection` |
| S4 | `<init>` of `java.net.Socket`, `ServerSocket`, `DatagramSocket`, `MulticastSocket`; `open` on `java.nio.channels.SocketChannel`, `ServerSocketChannel`, `DatagramChannel`, `AsynchronousSocketChannel`, `AsynchronousServerSocketChannel`; `createSocket` or `createServerSocket` on `javax.net.SocketFactory`, `javax.net.ServerSocketFactory` and their `javax.net.ssl` forms |
| S5 | `android.webkit.WebView`: `<init>`, `loadUrl`, `loadData`, `loadDataWithBaseURL`, `postUrl` |
| S6 | Any reference to `android.net.http.*` or `java.net.http.*`; `android.media.MediaPlayer.setDataSource`; `android.widget.VideoView.setVideoURI` and `.setVideoPath`; any reference to `android.app.DownloadManager`; `android.net.Network.openConnection`, `.getSocketFactory`, `.bindSocket` |

The implementer may add a sink with its reason; removing one needs the decision log. A listening socket is a sink on purpose: the owner's first worry is a way into the home network.

### Attribution

For an instruction in dex method `(class, name, descriptor)` at address `x`:

1. Its line is the last `positions` row at or before `x`.
2. Its frames are the member lines of that class's mapping section that map to `name` and whose `<a>:<b>` range holds the line, innermost first. A method with no position table, or a member line with no range, uses the range-less lines for `name`; when several originals share the name, the descriptor decides (a `residualsignature` comment when present, else the original signature with each type translated through the class lines).
3. A frame's holder is the qualified class before the method name, or the section's original class when the name is unqualified.
4. When no frame is found, the holder is `unresolved:<dex class>.<name>`, which matches no row, so a sink there fails D2. Nothing is skipped silently. Outline call sites and synthetic classes are attributed by their class line unless the implementer resolves them further; a row may name such a class only with a reason.

Frames whose holder starts with a `LIBRARY_INTERNAL` prefix (`okhttp3.`, `okio.`) are dropped: OkHttp's own sockets are reached only through a client, and S1 catches every holder of a client. A sink reference with no frame left is the library's own and is not judged.

"Octave's code" is every frame holder that starts with `dev.octave.`. T3-04's low follow-up applies here too: a later module in another Java package would not be seen (`docs/plans/active/005-t3-04-review-followups.md`, second bullet); D0 fails when no `dev.octave.` frame exists at all.

### Rules

Every rule reads its list from `lists`; the names below are the production defaults.

- **D0, the input is whole.** Fail when: the APK or the mapping is missing (the message says `pnpm tv:build`); the APK holds no `classes*.dex`; a dex has no R8 marker, or its `pg-map-id` differs from the mapping's `pg_map_id` (the message says the mapping is from another build, for example after `pnpm tv:e2e:build`); the number of `Opened` lines in the dump differs from the number of dex entries; the dump holds no class, no sink reference, or no `dev.octave.` frame; the mapping has `okhttp3.` class lines but none for `okhttp3.OkHttpClient`; `dexdump` exits non-zero.
- **D1, Octave holds a sink.** A sink reference with a `dev.octave.` frame fails, unless its innermost remaining frame is on `ONE_CLIENT_CLASSES` for that sink kind: `dev.octave.session.http.OctaveHttp` and `dev.octave.session.http.SessionCallFactory` for S1 (the names in `NetworkPathRules.kt:13`), `dev.octave.session.http.DirectSocketFactory` for S4. These rows may be absent from the dex (R8 removes `OctaveHttp` until T3-05 calls it). Decision log 14 adds one exemption (an Octave invoke of `Call$Factory.newCall`) and one more failure (an Octave instruction that takes a `Call$Factory` from a class outside `dev.octave.`); where it differs from this bullet, it wins.
- **D2, an entry point outside the named list.** Every other remaining frame holder of a sink reference must match a row of `APK_NETWORK_ENTRY_POINTS`, and the sink's id must be among the row's `sinks`. A holder matches a row class when it equals it or starts with it followed by `$`. Rows never name a package.
- **D3, a stale row.** A row no sink reference matched fails, so the list names only what the APK holds.
- **D4, Octave references an entry point.** In any instruction with a `dev.octave.` frame (the one-client classes included), the reference is resolved to original classes by member, never by the class line alone (Facts, `w63.m0`): a method reference to the outermost holders of that dex method's member lines (narrowed by descriptor when several originals share the name); a field reference to the holder on the field's member line; a type-only reference (`new-instance`, `const-class`, `check-cast`, `instance-of`, a descriptor) to every original the section holds, that is the class line's original and every outermost holder in it. If one matches an `APK_NETWORK_ENTRY_POINTS` row or `ENTRY_POINT_HOOKS` (the K7 names: `com.facebook.react.modules.network.OkHttpClientProvider`, `OkHttpClientFactory`, `CustomClientBuilder`, `com.facebook.react.devsupport.inspector.DevSupportHttpClient`), the check fails and names both ends. This is a direct reference, not a call graph (reading 1). D4 has no exception list.
- **D5, an unlinked package is back.** Fail when a class line that is not removed, or a frame holder in a kept section, starts with an `ABSENT_PACKAGES` prefix. The production list holds the Java package of every excluded module (Facts: `expo.modules.filesystem.`, `expo.modules.asset.`, `expo.modules.logbox.`, `expo.modules.webview.`, each only if its package is excluded) and the stacks T3-04's K4 names that R8 would rename (`org.chromium.net.`, `com.android.volley.`, `coil.`, `coil3.`, `com.bumptech.glide.`, `com.squareup.picasso.`).
- **D6, `DevSupportHttpClient`'s callers.** Every instruction that references the dex class of `com.facebook.react.devsupport.inspector.DevSupportHttpClient`, outside that class, must have its outermost frame holder on `DEV_SUPPORT_CLIENT_CALLERS`; a row nothing matched fails. If the class line is gone or removed, the list must be empty.

### The lists

Each `APK_NETWORK_ENTRY_POINTS` row: `{ id, classes, sinks, what, reason, linkedPath }`. `linkedPath` is the id of the `LINKED_NETWORK_PATHS` row whose path this is in the dex (`R1`, `E1`, …), also when the sink sits in a binary base class the source row's class works through (Fresco's `OkHttpNetworkFetcher` is R3's path: `ReactOkHttpNetworkFetcher` extends it). It is `null` only for a class no source row stands for (Fresco's `HttpUrlConnectionNetworkFetcher`, `kotlin.reflect`'s loader). The item's six names are each accounted for: React Native's Networking (`R1`) and WebSocket (`R2`) modules, Fresco's network fetcher (`R3`), `expo/fetch` (`E1`), `expo-file-system` (`E2`) and `@expo/dom-webview` (`E5`) each have a row, or a source-only entry saying why no class of theirs holds a sink in the dex, or (the last two) their package on `ABSENT_PACKAGES`. The frozen shape test holds exactly that; the PR says which state each name is in.

The implementer builds the production list from the check's own output on a build made after milestone 3, not from the refiner's probe, and writes each row's reason after reading the class's source. A row whose reason is "opens no connection" (for example `kotlin.reflect`'s `BuiltInsResourceLoader`, if it is still there) says what it opens instead and cites the file. The `guardian` reads every row and every `linkedPath`.

`SOURCE_ONLY_LINKED_PATHS` rows: `{ id, reason }`. An id goes here when its `LINKED_NETWORK_PATHS` row stays (the package is linked and its source file names a client) and no class with a sink stands for it in the release dex. The reason says why: R8 removed the class, the client is only stored and never built there, or the code is a development path. Expected from the probe, unverified: E7 and, if `@expo/log-box` stays linked, E4. The two-sided partition test (row 3) keeps the lists from drifting: a new `LINKED_NETWORK_PATHS` row must land on one side, and when a source-only path's class starts to hold a sink, D2 demands an entry-point row for it, whose `linkedPath` then puts the id on both sides and fails the test until the source-only row is removed.

`DEV_SUPPORT_CLIENT_CALLERS` rows: `{ class, offInRelease }`, the second being why the caller does not run in a release build. Expected, from the probe: `com.facebook.react.devsupport.CxxInspectorPackagerConnection$DelegateImpl`, `com.facebook.react.devsupport.DevServerHelper`, `com.facebook.react.devsupport.DevServerHelper$openInspectorConnection$1` (built only by a development or perf-test dev support manager; Facts), and `com.facebook.react.runtime.ReactHostImpl` (`loadNetworkResource` is called from C++ by the inspector target, which exists only when `getFuseboxEnabled()`; its `offInRelease` says "read from source, not tested").

`KEPT_EXPO_MODULES` rows: `{ package, reason, evidence }`. `evidence` is the log line or error the trial produced, quoted, and must not be empty: it is what shows the exclusion was tried.

### The development-server watch (item 2)

`scripts/tv-dev-server-watch.mjs`. The frozen test pins this API, so it is given in full:

- `await startDevServerWatch({ adb, serial, port = 8081 })` resolves once the listener is bound on `127.0.0.1:<port>` and `adb reverse tcp:<port> tcp:<port>` has succeeded (so the device's `localhost` reaches it too), and rejects otherwise. A port in use rejects with a message that says to stop Metro or wait for another smoke run on this host; it is never skipped. `adb` is `{ path, run }`-shaped or a path, the implementer's choice, as long as the test can pass a fake. The listener counts accepted connections and closes each at once.
- It resolves to `{ runControls, result, stop }`:
  - `await runControls()` opens one connection from the device to each address the app could use (`adb shell toybox nc -w 2 localhost <port> </dev/null`, and `10.0.2.2` when the serial starts with `emulator-`), with an asynchronous child process, never `spawnSync`. It resolves when the listener has counted each one or a few seconds have passed, and then closes the control phase: every connection accepted before it resolves is a control, every one after is the app's. That the TV image's toybox has `nc` is unverified; if it has none, the implementer stops and reports instead of dropping the control.
  - `result()` is synchronous and returns `{ controlsExpected, controlsSeen, appConnections }`.
  - `await stop()` removes the reverse (`adb reverse --remove tcp:<port>`) and closes the listener. It may be called twice and never rejects.
- **Counts are read only after the event loop has turned.** The smoke script's `adb` calls are `spawnSync`, which blocks the loop, so a connection made during one sits in the kernel's queue until the script next awaits. The script therefore awaits `runControls()` before `am start` (so no control can land late and be counted as the app's), and calls `result()` only after an awaited sleep that follows its last `spawnSync` (so no app connection is still queued).
- `judgeDevServerWatch({ controlsExpected, controlsSeen, appConnections })` returns `ERROR tv smoke: …` lines; empty only when every control was seen and the app opened none. A missing control connection fails the smoke test: a watch that cannot see the device proves nothing.
- **One run per host.** The listener cannot tell which emulator a connection came from: every emulator's `10.0.2.2` is the same host loopback. A second `pnpm tv:smoke` on the host fails to bind and says so; another emulator whose app reaches port 8081 during the run is counted as this run's app connection and fails it. So smoke runs are serial per host even when each agent has its own emulator, which `AGENTS.md:138` already asks of on-device work. `docs/commands.md` says so.
- **What the watch shows and does not.** It shows that the release app does not open the inspector connection to the development server while it starts, which is the only way a debugger reaches the inspector target. It does not watch a `loadNetworkResource` request, whose URL the inspector chooses, and it does not watch after start-up.

`scripts/tv-first-focus.mjs` starts the watch before installing, awaits `runControls()` before `am start`, and judges after the second tile has focus and an awaited `SETTLE_MS` has passed. The result goes to `release-evidence/tv/dev-server-watch.txt`. `judgeFirstFocus` and the key sequence do not change.

**The watch is stopped before every exit.** Today the script leaves through `process.exit(1)` in `fail()` (`:76-79`) and after the judge (`:139`), which skip a `finally`. From the moment the watch starts, no code path calls `process.exit`: `fail()` throws an error that carries the message, the judge path returns its errors, and the command's body runs in `try { … } finally { await watch.stop() }`; the entry point prints the errors and sets `process.exitCode = 1` after the `finally` has run. A `SIGINT` or `SIGTERM` handler awaits `watch.stop()` and then exits. The `fail()` calls before the watch starts (no APK, no device) may stay as they are. The implementer adds an unfrozen test that a failing run with a fake `adb` ends with `reverse --remove` called and the port free.

## Risks and out of scope

Risks:

- **Attribution through R8's mapping is the fragile part.** A new R8 version can change the mapping's comments or merge more classes. The check fails closed (an unresolved holder matches no row), so the cost is a red `tv` job after a toolchain bump, not a hole.
- **False positives in D4.** A method name shared by merged classes, or a type-only reference to a merge target, resolves to several originals, and D4 fails if any is listed. Whether one occurs today is unverified; milestone 1's real build shows it. If one appears, narrow the resolution (descriptor, then the instruction's own use). An exception list is not the implementer's to add: if narrowing does not make D4 green, the implementer stops and reading 1 returns to the Product Owner.
- **Item 2's gap is real, not minor.** If the C++ inspector gate were open in a release build, a connected debugger could make the TV fetch a home-network address. Two source-read gates stand before it and one is observed at start-up. The gap is stated in R5's reason, `docs/security.md` and the PR; backlog line 1 asks for the test, and the Product Owner recommends that the first real-TV install waits for it (the owner's to veto).
- **The lists drift into rubber stamps.** A new library class holding a client turns the check red, and the fix is one row. Each row needs a reason a reviewer can check against source, and `sinks` pins what the row may hold, so a row cannot quietly cover a new kind of connection. `linkedPath` and `SOURCE_ONLY_LINKED_PATHS` are written by hand; the partition test holds their shape and the `guardian` reads their content.
- **The production lists are not judged by a frozen test on a fixture.** They are held by the real-APK run, which needs the Android SDK and so runs in the `tv` job and locally, not in the `checks` job.
- **The watch uses port 8081 and is host-wide.** A developer with Metro running must stop it before `pnpm tv:smoke`, and two smoke runs on one host cannot overlap; the messages and `docs/commands.md` say so. On a real TV only the `adb reverse` control runs.
- **Excluding `@expo/log-box` may change the development error overlay.** The debug start-up trial covers "still starts"; the overlay's look in development is not checked.
- **A stale mapping.** After `pnpm tv:e2e:build`, `mapping.txt` belongs to the e2e build; `pnpm tv:apk:check` then fails D0 until `pnpm tv:build` runs again. CI runs the check before the e2e build.
- **A top-level `exclude` also applies to other platforms.** There is no Apple TV app yet; when one exists, its task re-reads the list.

Out of scope:

- `release_build_has_no_inspector` and Expo's inspector interceptors (T3-16 item 5).
- Any request through the one client, the wire capture, and a run-time proof that no other origin is contacted (T3-05, T10-01).
- Refusing a name that resolves outside the private LAN (T3-20).
- Media3's data sources in the dex (T8-02 adds them to `NETWORK_SINKS` and the lists when it adopts Media3).
- Native libraries, the Hermes bundle, reflection (named in `docs/security.md` as not seen).
- Patching React Native to remove dev support from release builds.
- Shortening `ALLOWED_PERMISSIONS` or `ALLOWED_QUERIES` (backlog line 6, below).
- A call-graph or taint analysis of the dex.
- Changing `depends_on` of T3-17, T3-12, T3-13 or T3-14 for the C++ gate (a Product Owner pass, after backlog line 1 is on `main`).
