## Goal

Every later screen (T3-07 to T3-11, then T4 onwards) builds from one set of design tokens and nine shared controls, so DESIGN.md's look, focus and motion rules live in one place and a lint stops drift.

1. The tokens of `DESIGN.md` §8 (with §4's type table and §5's depth and motion tables) exist once, as TypeScript constants in canvas pixels. A test compares them with DESIGN.md in both directions.
2. One conversion turns canvas px into React Native dp for the running device.
3. An ESLint rule fails a hard-coded colour, size, radius or duration in app code outside the tokens file.
4. Nine controls are built: `Button`, `IconButton`, `TextField`, `Switch`, `Dialog`, `Toast`, `Notice`, `EmptyState` and `Skeleton`. Each is built on one shared focus primitive that draws the ring and the lift and honours reduced motion.
5. Jest and React Native Testing Library come into `apps/tv` and run inside `pnpm test`, so `pnpm check` and CI's `checks` job run the component tests.
6. Atkinson Hyperlegible Next and Mono are bundled with the app (DESIGN.md §4, `docs/specs/T3-01.md:112`).
7. The placeholder first screen moves onto the tokens, and `placeholder-values.ts` is deleted.

## Approach

### Tokens

`tokens.ts` exports `const` objects named after DESIGN.md's groups: `colors`, `artDefaults`, `type`, `textLayout`, `space`, `sizes`, `radii`, `depth`, `motion`, `focus`, `reducedMotion` and `faces`. Within each, the keys are DESIGN.md's token names exactly (`surface0`, `space5`, `radiusControl`, `durQuick`, `focusRingWidth` and so on), so the parity test can join them by name. Every name is unique across groups except in `reducedMotion`, which the test joins to §8's Reduced motion row only.

- Values are canvas px, ms or unitless, as DESIGN.md writes them. Colours are DESIGN.md's strings (for example `"rgb(242 239 233 / .10)"`), which React Native parses (Facts).
- `type` holds exactly the rows of §4's "Scale" table (with `typeDialogTitle`, below). Entries are `{ size, lineHeight, weight, tracking?, face: "ui" | "mono" }`. `lineHeight` is the ratio, as in §4, and the builder multiplies it. `tracking` is in em (`typeHero`: `-0.02`).
- `textLayout` is `{ measure: 62 }`. It is a count of characters, so it is never passed to `px()`.
- `easeOut` and `easeInOut` are four-number tuples. `lift` is `1.08`.
- `shadowLift` and `shadowSheet` are `{ offsetX, offsetY, blur, spread, color, alpha }`: `shadowLift` is `{ offsetX: 0, offsetY: 14, blur: 32, spread: -10, color: "black", alpha: 0.65 }` and `shadowSheet` is `{ offsetX: 0, offsetY: 28, blur: 72, spread: -16, color: "black", alpha: 0.75 }`.
- Scrims are `{ direction, color, stops, height? }`. `color` is a `colors` key or `"black"`. Each stop is `{ at, alpha }`, where `at` is the fraction of the scrim's length from its solid edge. `height` names a `sizes` token. The four values are:
  - `scrimHero`: `{ direction: "horizontal", color: "surface0", stops: [{ at: 0, alpha: 0.94 }, { at: 0.38, alpha: 0.72 }, { at: 0.72, alpha: 0 }] }`.
  - `scrimFloor`: `{ direction: "vertical", color: "surface0", stops: [{ at: 0, alpha: 1 }, { at: 0.4, alpha: 0 }] }`.
  - `scrimPlayerTop`: `{ direction: "vertical", color: "black", stops: [{ at: 0, alpha: 0.85 }, { at: 0.55, alpha: 0.85 }, { at: 1, alpha: 0 }], height: "scrimPlayerTopH" }`.
  - `scrimPlayerBottom`: the same stops, `height: "scrimPlayerBottomH"`.
  - "Black at .85 to 55%, then to 0" is read as a flat .85 from the solid edge to 55% of the height, then a fade to 0 at the far edge. Which edge is solid (top for the top scrim, bottom for the bottom scrim and the floor, the text side for the hero) belongs to the screen that draws it, not to the token.
- `reducedMotion` is `{ durQuick: 0, durBase: 0, durSlow: 120, lift: null }`.
- `faces` maps `ui` and `mono` to the registered family names. The parity test does not compare it, because DESIGN.md names the faces in prose.

`tokens.ts` imports nothing, so Vitest in Node can read it without React Native.

### How the parity test reads DESIGN.md

These rules are for the test writer, so `tokens.ts` and the item 1 test agree on one shape:

- **§8 rows.** Each entry is a backticked name followed by its value. A trailing unit (`ms`, `characters`) and a parenthesised note (`(a third of the canvas)`) are dropped. `Mono` after a type size sets `face: "mono"`.
- **Minus signs.** Read `−` (U+2212) as a minus sign everywhere, in §4's tracking as in §5's spreads.
- **Colours.** Compared after trimming, lower-casing and collapsing whitespace. No other normalisation.
- **Type.** Names come from §8's Type row. Values come from §4's "Scale" table: `size / lineHeight`, an optional `tracking −0.02em`, an optional `Mono`, and the weight column. `measure` is joined to `textLayout.measure`.
- **Depth.** The §8 Depth row names six tokens. Values come from §5's elevation table:
  - A shadow cell is `offset X Y, blur B, spread S, black at A`.
  - A scrim cell is one of three patterns: "`<direction>` gradient, `<colour>` at a1 (p1%), a2 (p2%), a3 (p3%)" (the hero); "`<direction>` gradient, `<colour>` (p1%) to transparent (p2%)" (the floor, where the first stop's alpha is 1); and "black at A to P%, then to 0; H px tall" (the player scrims, `direction` `"vertical"`, whose `H` must equal the value of the `sizes` token their `height` names).
- **Motion.** `durInstant` 80 ms and the like are numbers; `easeOut` and `easeInOut` take the four numbers of their §5 `cubic-bezier(...)`; `lift` takes the number in §5's `scale 1.08` and §8's `1.08`, which must agree.
- **Reduced motion.** §8's Reduced motion row repeats `durQuick`, `durBase`, `durSlow` and `lift` with other values. Parse it as its own group, compared with `reducedMotion`, and never merge it into `motion`. `lift` none is `null`.

### The canvas-to-dp conversion

`canvasScale()` is `Dimensions.get("window").width / 1920`, read once. `px(n)` is `PixelRatio.roundToNearestPixel(n * canvasScale())`. On a 1080p Android TV the window is 960 dp, so the scale is 0.5, the value T3-01 hard-coded. A 4K panel that reports the same window gets the same layout. This follows DESIGN.md §6, which marks per-device density **[unverified per device]**. The owner's Shield check of the tokens (DESIGN.md line 5) will show whether a device differs. Styles are built once with `StyleSheet.create` at module load. Item 5 tests canvas px, not dp.

### Text

`textStyle(token)` returns:

- `fontFamily` from `faces`, `fontSize: px(size)`, `lineHeight: px(size * lineHeight)` and `letterSpacing: px(size * tracking)` (typeHero's −0.02em is −1.44 px).
- The weight: weights 400, 500, 600 and 700 use `fontWeight`, which matches the expo-font definitions. Weight 650 (`typeTitle`, `typeDialogTitle`) uses `fontWeight: "600"` plus `fontVariationSettings: "'wght' 650"`.

Whether Android draws that at 650 and not a synthetic bold is **unverified**. Milestone 4 checks it with an emulator screenshot of `typeTitle` beside `typeHeading`. If the setting is not honoured, the fallback is a separate family, `AtkinsonHyperlegibleNextTitle`, from the same file with one definition `weight: 400, axes: { wght: 650 }`. The 650 tokens then use that family with `fontWeight: "400"`. It must be a separate family because the plugin refuses two definitions of one weight and style in a family (`withFontsAndroid.js:159`), and `AtkinsonHyperlegibleNext` already declares 700. The decision log records which path works. Text keeps `allowFontScaling` at its default.

### Fonts

The two variable TTFs and their OFL texts go in `apps/tv/assets/fonts/`, and the `expo-font` config plugin registers them on Android (Files to touch). Nothing calls `expo-font` at run time. `loadAsync` can take a remote URI through `expo-asset`, so the design lint refuses an `expo-font` import in app code (item 2). `expo-font` is already linked through `expo` (Facts), so this adds no native module and no network path. `pnpm tv:apk:check` and the dex check must still pass (milestone 4).

### Motion

`ReducedMotionProvider` reads `AccessibilityInfo.isReduceMotionEnabled()` once and subscribes to `reduceMotionChanged`. Tests can pass `value` to override it. `useReducedMotion()` returns a boolean, and it starts as `false` until the first read resolves.

Animations use React Native's own `Animated` with `useNativeDriver: true` on `transform` and `opacity` only. No Reanimated: the controls need nothing it adds, and the Jest preset needs no extra mock.

- **Lift.** `Animated.timing` to `motion.lift` over `motion.durQuick` with `Easing.bezier(...motion.easeOut)` on focus, and back on blur. With reduced motion on, no transform is applied at all.
- **Press.** Scale to `pressScale` over `durInstant` on `pressIn`, and back on `pressOut`. Under reduced motion there is none.
- **Where the transform lives.** Both scales apply to one `Animated.View` inside the `Pressable`, with `testID` `<testID>-scale`. It carries no `transform` while the control is at rest (not focused, not pressed, no animation running), so an idle control has no transform and a pressed one has one. The implementer chooses how to combine the two scales.
- **Dialog and Toast.** Opacity 0 to 1 over `durBase` with `easeOut` on show, and the reverse on hide. Under reduced motion there is no fade: they appear at opacity 1 and are removed at once. Acceptance item 4 says "nothing scales or fades", which is stricter than §5's "≤120 ms crossfade or instant", so instant is chosen.
- **Skeleton.** No shimmer, under any setting (owner decision 2).

### The focus primitive

`FocusFrame` is a `Pressable`. It takes `onPress`, `onFocus`, `disabled`, `hasTVPreferredFocus`, `accessibilityLabel`, `accessibilityRole`, `radius` (a `radii` key), `testID` and children.

- It tracks `focused` and `pressed` from `onFocus`, `onBlur`, `onPressIn` and `onPressOut`.
- It draws the ring as two absolutely positioned overlay `View`s, rendered only while focused, with `testID` `<testID>-focus-ring` on the inner ring:
  - The inner ring: `focus` colour, `focusRingWidth`, inset `-(focusOffset + focusRingWidth)`.
  - The outer edge: `focusEdge`, `focusEdgeWidth`, outside the ring.
  - Each radius is the control's radius plus its insets.
- Rendering the ring only while focused keeps the layout from shifting and needs no `"transparent"` colour.
- The `-scale` element holds the children ("Motion").
- Disabled sets `focusable={false}` and `disabled`, and sets `accessibilityState.disabled`. A disabled control takes no focus (DESIGN.md §7.18: "Rows for features not built yet ... take no focus").
- Every control above is built on it. Buttons and fields get no other focus handling.

**Props and `testID` contract.** The frozen helper `apps/tv/src/design/test-support/harness.tsx` fixes it, and the controls follow it. Every export is a named export of the module of the same name under `controls/`.

`testID` rules, with `T` the control's `testID`:

On the fallback path TextField draws the same overlay under `T-focus-ring`, driven by the input's own focus, so `pressSelect(getByTestId(T))` and the ring assertions hold on either path.
- A container passes its actions' ids as `T-<action id>`. Toast's Dismiss is `T-dismiss`. EmptyState's action is `T-action`.
- Dialog and Toast put their opacity on one element, `T-fade`, rendered only while visible.
- TextField's native input is `T-input`.

- **Dialog.** A React Native `Modal`: `transparent`, `animationType="none"` (the opacity animation is ours) and `onRequestClose` for Back. The panel sits inside a `TVFocusGuideView` with all four `trapFocus*` props, so focus cannot leave the panel. The `Modal` is chosen over an overlay because Back and window focus come with it. DESIGN.md §7.16 requires focus to be restored on close. Whether the `Modal` does that by itself is **unverified**; milestone 5 checks it on the emulator. If it does not, the Dialog takes a `restoreFocusRef` and the decision log says so.
- **TextField.** A `FocusFrame` holding a `TextInput` with `focusable={false}`. Select calls the input's `focus()`, which opens the system keyboard. The props are `label`, `value`, `onChangeText`, `onFocus`, `helper`, `error`, `secureTextEntry`, `disabled` and `hasTVPreferredFocus`. Whether the keyboard opens this way on Android TV is **unverified** (milestone 5). The fallback is a focusable `TextInput` with the ring driven by its own `onFocus`, and item 6's frozen assertion (ring shown, `onFocus` called) holds on both paths.
- **Switch.** The colours in the State matrix, from existing colour tokens. The thumb is `switchThumb` and sits at the track's start when off and its end when on, moved over `durQuick` (instantly under reduced motion). The words "On" and "Off" sit beside the track.

### The lint

`scripts/eslint-design-tokens.mjs` exports a rule with one message per kind. Each message ends with the token group to use:

- **Colour.** It reports:
  - Any string or template-literal part anywhere that is colour syntax: `#` followed by 3, 4, 6 or 8 hex digits, or `rgb(`, `rgba(`, `hsl(`, `hsla(`, `hwb(`, `lab(`, `lch(`, `oklab(`, `oklch(` or `color(`.
  - Any string value of a property or JSX attribute whose name ends in `color` or `Color` (this catches `"transparent"` and named colours).
- **Size and radius.** It reports a numeric literal other than `0` as, or as a `+` or `-` operand within, the value of these keys:
  - `width`, `height`, `min*`, `max*`, `top`, `right`, `bottom`, `left`, `start`, `end` and `inset*`.
  - `margin*`, `padding*`, `gap`, `rowGap` and `columnGap`.
  - `border*Width`, `outlineWidth`, `outlineOffset`, `*Radius`, `fontSize`, `lineHeight`, `letterSpacing`, `shadowRadius`, `shadowOffset` members, `elevation`, `translateX` and `translateY`.
  - `scale`, `scaleX` and `scaleY`, where `1` is also allowed.
  - Any literal argument to `px(...)` other than `0`. The rule "`0` is allowed" wins, so `px(0)` is accepted and `px(24)` is reported.
- **Duration.** It reports a numeric literal other than `0` as the value of `duration` or `delay`, or of a JSX attribute starting `delay`, or as the second argument of `setTimeout` or `setInterval`.
- **Font loading.** It reports an import, `require` or `import()` of `expo-font`.
- **Image requests.** The size keys of an object literal that also has an `imageType` key are request pixels, not layout, and are not reported. The frozen T3-04 sample (`scripts/network-lint.test.ts`) passes `{ session, itemId, imageType, tag, width: 300 }` on `apps/tv/src/probe.tsx`, and the frozen item 2 test refuses `width: 248` on the same path, so only this difference tells them apart.
- **Allowed.** `0`, the keys not listed (`flex`, `flexGrow`, `opacity`, `zIndex`, `aspectRatio`), percentage strings, and literals as `*` or `/` operands (`posterW * 1.5`).

The rule's scope is in item 2. The existing network-lint tests (`scripts/network-lint*.test.ts`) must stay green, and item 2's test checks one network sample on the same path.
