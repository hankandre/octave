# T3-28: Test that a release build's inspector cannot fetch a debugger-supplied URL

Task: `pnpm task show T3-28`. Domain: Security & Redaction. Depends on T3-19 (done, PR #267). Takes backlog entries 204 and 200 (`tasks/product-owner-log.md`, "Added T3-28").

Implementer: `implementer` (Node scripts, Vitest tests and documents; no Kotlin, no native module, nothing under `modules/` or `apps/tv/android/`).

Spec written on `origin/main` at `1c3b428c`; revised on 2026-11-22 after the spec check at `ea333f94`.

## Goal

`ReactHostImpl.loadNetworkResource` fetches whatever URL a connected debugger passes, a home-network address included (R5 in `scripts/linked-network-paths.mjs`). T3-19 left the C++ gate that keeps it from running in a release build as a source read. This task replaces the part of that read a built APK can show with a test:

1. A new step of `pnpm tv:apk:check` reads the native libraries (`lib/<abi>/*.so`) of the release APK and fails when the C++ inspector's CDP network dispatcher is wired to a caller, which is what a build compiled with `REACT_NATIVE_DEBUGGER_ENABLED` has and a release build lacks.
2. A test runs the existing `scripts/tv-apk-inspector.mjs` command on a recorded APK and asserts its summary line (entry 200).
3. `docs/security.md`, R5's reason and the two `ReactHostImpl` texts in `scripts/tv-apk-dex-lists.mjs` say what is now tested and what is still read from source.

Item 3 of the acceptance (no test can tell the builds apart) does **not** apply: a reading was found and shown on built libraries (Facts). One candidate reading was tried and refused because it is false; it is recorded below so nobody adopts it later.

## Approach

### The reader, `scripts/tv-elf.mjs`

`readElf(bytes)` returns `{ problems, symbols, relocations, packedRelocations }` or throws nothing: an unreadable file is a `problems` entry, never an exception that a caller could swallow.

- Accepts ELF64 little-endian only (`\x7fELF`, class 2, data 1). Anything else is a problem ("not ELF64 little-endian"). The release APK holds only arm64-v8a and x86_64; a 32-bit ABI appearing is a build change the check should stop on, not read past.
- Reads the section header table; every offset and size is bounds-checked against the buffer, and an out-of-range one is a problem.
- `symbols`: every entry of `.dynsym` (section type `SHT_DYNSYM`, 11) with its name from the linked string table, as `{ name, defined, type, bind, visibility }`, where `defined` is `st_shndx !== 0`, and `type`, `bind` and `visibility` are the ELF names (`FUNC`, `OBJECT`, `NOTYPE`, …; `GLOBAL`, `WEAK`, `LOCAL`; `DEFAULT`, `HIDDEN`, `PROTECTED`, `INTERNAL`). A library with no `SHT_DYNSYM` section is a problem.
- `relocations`: for every section of type `SHT_RELA` (4) and `SHT_REL` (9) whose linked symbol table is the `.dynsym`, the symbol name of each entry whose symbol index is not 0, as `{ section, name }`. Relocation types are not interpreted: any relocation naming a symbol counts.
- `packedRelocations`: true when a section of type `SHT_ANDROID_REL` (0x60000001), `SHT_ANDROID_RELA` (0x60000002) or `SHT_CREL` (0x40000014) exists. Their entries are not decoded. `SHT_RELR` (19) holds relative relocations only, which name no symbol, and is ignored.
- `hasBytes(bytes, text)`: whether the file holds the UTF-8 bytes of `text`.

No tool is run: `llvm-readelf` on the CI runner is unverified, and the zip reader set the precedent of reading the format with `node:fs` and `node:zlib` only.

### The rules

Names, exported from `scripts/tv-apk-native-inspector.mjs`:

- `DISPATCHER = "_ZN8facebook5react18jsinspector_modern14NetworkIOAgent13handleRequestE"`, matched as a prefix of a symbol name (any overload is a dispatcher).
- `LOADER = "_ZN8facebook5react18jsinspector_modern14NetworkIOAgent25handleLoadNetworkResourceE"`, a prefix.
- `DEBUGGER_ONLY_MARKERS = ["React Native DevTools"]`.
- `ALWAYS_PRESENT_MARKER = "is not implemented by this host target delegate"`.

`readLibraryFacts(entryName, bytes)` returns `{ entry, abi, name, problems, packedRelocations, symbols, relocations, markers }`, with `symbols` and `relocations` cut to names that start with `DISPATCHER` or `LOADER`, and `markers` the subset of the two marker lists the bytes hold. `judgeNativeInspector({ libraries })` returns `ERROR tv native inspector: <rule> …` lines, empty on a pass.

- **L0, readable.** The APK holds at least one `lib/<abi>/<name>.so` entry, and `lib/arm64-v8a/` is among the ABIs. No library has a `problems` entry. A library whose symbols name `DISPATCHER`, defined or not, has `packedRelocations` false (a packed section there could hide the relocation L2 looks for; elsewhere it cannot, because a relocation needs the name in that library's `.dynsym`).
- **L1, anchors.** In each ABI exactly one library defines `DISPATCHER`; call it the inspector library. Its `DISPATCHER` and `LOADER` symbols are each `defined`, `FUNC`, `GLOBAL`, `DEFAULT`. It holds at least one relocation naming `LOADER`. It holds `ALWAYS_PRESENT_MARKER`. Why each: the defined symbols show the check is looking at the library that holds the inspector and can read its symbol table; the `LOADER` relocation shows that this library binds calls between its exported functions through relocations, so a call to the dispatcher would show as one (a build linked with `-Bsymbolic` or with hidden visibility loses this anchor and fails, instead of passing with L2 blind); the string shows the marker search reads this library's strings.
- **L2, no caller.** No library of the APK holds a relocation naming `DISPATCHER`, and no library has an undefined `DISPATCHER` symbol (an import from another library).
- **L3, no debugger-only marker.** No library of the APK holds a string of `DEBUGGER_ONLY_MARKERS`.

L2 is the reading of the gate itself. L3 is independent of it (a string, not a relocation) and is kept so that one linker or compiler change cannot blind the whole check. L1 turns symbolic binding and a visibility change into a failure. It does not catch link-time inlining of the dispatcher into its caller: the exported copy would keep its `LOADER` relocation while the caller's relocation disappeared. Against that, L3 is the only guard, and the documents say so.

L1's `LOADER` anchor is also the standing test of the real reader on a real library: on every `tv` job run it must find, in the release APK's `libreactnative.so`, a relocation in the same `.rela.plt` section where a `DISPATCHER` relocation would sit. A reader that cannot read that section fails the job instead of passing L2 blind.

Errors name the rule, the entry (`lib/x86_64/libreactnative.so`) and, for L2, the relocation section. At most 20 lines per rule, then "and N more", as the inspector check does.

### The command

`node scripts/tv-apk-native-inspector.mjs [apk]`; no argument reads `RELEASE_APK` from `scripts/tv-apk-check.mjs`. T3-31 will pass the e2e APK, so the argument is part of the contract.

1. No file at the path: `ERROR tv native inspector: no APK at <path>; run pnpm tv:prebuild and pnpm tv:build first`, exit 1.
2. `readZipEntries(apk, (name) => /^lib\/[^/]+\/[^/]+\.so$/.test(name))`; a zip that cannot be read is an `ERROR` line and exit 1, never a stack trace.
3. `readLibraryFacts` on each, `judgeNativeInspector`, errors to stderr, exit 1 on any.
4. On a pass, one line to stdout:
   `tv native inspector: <apk> passes (<n> libraries in <n> ABIs; <name> defines the C++ inspector's network dispatcher in each and nothing calls it; no debugger-only string)`.

`main(args)` returns the exit code and the file ends with the same run-when-invoked guard as `scripts/tv-apk-dex.mjs` (`import.meta.url === pathToFileURL(process.argv[1]).href`). The item 2 test spawns the file, so a guard that stops matching fails a test instead of passing silently, which is the worry entry 200 raised for the older command.

### The recorded APK for item 4

`scripts/tv-apk-inspector.mjs` is not changed, so the test meets it where it reads the world. One helper in the test turns a recording (`release-build.json` or `debug-build.json`) into three things in a temporary directory:

- **The APK.** A zip with one stored entry per object of the recording's `markers`: the entry's name is that object's `dex` (`classes.dex`, `classes2.dex`, …) and its bytes are that object's `marker` string, or bytes holding no `~~` marker when `marker` is `null`. The command reads markers from the bytes and does not parse the dex. Release: 1 entry. Debug: 21 entries, two without a marker.
- **The replay file.** A text file holding one line `Opened '<entry name>', DEX version '039'` **per dex entry zipped** (the command throws unless the two counts are equal), then one `Class descriptor  : '<descriptor>'` line per recorded descriptor. Release: 1 `Opened` line and 33 descriptor lines. Debug: 21 and 60.
- **`dexdump`.** `<tmp>/sdk/build-tools/1.0.0/dexdump`, mode 0755, whose whole text is `#!/bin/sh`, `cat '<replay file>'`, `exit 0`, as `scripts/tv-apk-manifest.test.ts:266-275` does for `aapt2`. No `node` on the spawned `PATH` is needed. The command is spawned with `process.execPath`, `ANDROID_HOME=<tmp>/sdk` and `ANDROID_SDK_ROOT` deleted.

The mapping, where the recording has one, is its `mapping` text written to a file and passed as the second argument. This is a replay of a recording, in the test only (T3-22's way); the product command still runs the real `dexdump`.

Cases:

- Release recording with its mapping: exit 0, empty stderr, stdout exactly one line matching `^tv inspector: .* passes \(1 dex, 33 classes, R8 release with its mapping; no class of expo\.modules\.kotlin\.devtools, .* kept or renamed\)$`. The test takes 33 from `descriptors.length` of the recording, so the number asserted is the sample size.
- Debug recording, APK argument only (its `mapping` is `null`): exit non-zero, no stdout, stderr holds an `N1`, an `N2` and an `N3` line.
- Release recording with one `Lexpo/modules/kotlin/devtools/…;` descriptor added to the replay file: exit non-zero with an `N3` line.
- Release recording with one mapping line naming `expo.modules.kotlin.devtools` added: exit non-zero with an `N4` line.

The real APK stays covered where it already is: the `tv` job runs `pnpm tv:apk:check`, which runs the command on the APK it built and fails on a non-zero exit.

1. 2026-11-22 (refiner). **The string `Network.loadNetworkResource` is not the test.** It is absent from the release library and present in the debug one, which looks like the answer; it is also absent from the debugOptimized library, which has the inspector on. ## Risks and out of scope

Risks:

- **A React Native upgrade changes the names or the linking.** L1 fails and the check must be re-derived on three variants. Intended (decision log 4); the error text should say so: "re-derive the reading as docs/specs/T3-28.md does".
- **The reader misreads a real library.** The fixtures come from `llvm-readelf`, so a wrong reader would still pass the judge's tests. Guards: the reader's own tests on a built ELF; L1 on the real APK in the `tv` job (a reader that finds no symbols or no `.rela.plt` relocation fails closed); milestone 3's required comparison and debug APK run.
- **L2 reads one edge.** A second route to `loadNetworkResource` in a later React Native is the first remaining source read. L3 would catch it only if it came with the debugger-only `HostAgent`.
- **Link-time inlining would blind L2 without failing L1.** React Native's published libraries are not built that way today (the relocation is present in debugOptimized, an optimised build). If a later one is, L3 is the one rule left, and it rests on one string.
- **The debugOptimized sample is a library from the published AAR, not from an APK built here.** The byte-identity of APK and AAR libraries is shown for release and debug, and assumed for debugOptimized.
- **The source citations have one reader.** The call chain was read by the spec author only (Facts). If the implementer's reread differs, the binary readings still stand, but the wording of the three source reads in the documents must follow what the source says, and the difference goes to the Product Owner.
- **Time.** 44 libraries, about 50 MB inflated in memory once; the dex step already reads more. Unmeasured.
- **The item 4 replay needs `/bin/sh`.** CI and the development machines are Linux, and `scripts/tv-apk-manifest.test.ts` already depends on it; a Windows run of `pnpm check` is not supported today either (unverified, no Windows job exists).

Out of scope:

- Removing `DevSupportHttpClient` or `loadNetworkResource` from the APK (needs a patched React Native; ruled out of proportion in T3-19).
- Running the check on the e2e APK (T3-31), narrowing the dex check's socket exemption (T3-29), device addresses in script output (T3-30).
- Hermes's own debugger build flag, the debug build's inspector (backlog entry 176), and any check of JavaScript in the bundle.
- A CI job that builds a debug or debugOptimized APK to run the check against.
- Changing `scripts/tv-apk-inspector.mjs`.
