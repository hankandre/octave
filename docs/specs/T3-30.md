### The adb module

`scripts/tv-adb.mjs` is the one place that starts adb. Redaction happens there, where the output is read, so no caller can skip it and no sink has to remember it.

```
export const DEVICE_STAND_IN = "[device]";
export function serialForms(serial): string[];          // pure; longest first
export function redactSerial(text, serial): string;     // pure
export function openAdb({ adbPath, serial }): {
  run(args, options?): { status, stdout, stderr };           // spawnSync, text
  runAsync(args, options?): Promise<{ code, stdout, stderr, killed }>;  // spawn; the event loop keeps running
  bytes(args): { status, stdout: Buffer, stderr };           // exec-out screencap only
  stream(args): { stdout, on(event, listener), kill() };     // logcat
  redact(text): string;
};
```

- Every function runs `<adbPath> -s <serial> <args…>`; `args` never holds the serial.
- `stdout` and `stderr` of `run` and `runAsync` are redacted before they are returned.
- A failure to start, a timeout or a full buffer becomes `status` or `code` `-1` and a redacted `stderr`; no function returns or throws a Node error object, so no `Command failed: … -s <serial> …` text exists outside the module. `runAsync` reports a timeout as `killed: true`, which is all the probes read.
- `options` holds `timeoutMs` and `maxBuffer`; the callers keep today's values (64 MB in smoke and e2e, 256 MB in wire, 16 MB and the two probe timeouts, 15 s in the watch).
- `stream` redacts per complete line, never per chunk: it buffers the partial last line, emits whole redacted lines each ending in a newline, and flushes the rest when the child's stdout ends. A serial split across two chunks is therefore still replaced. The returned object has what `startLogKeeper` uses (`stdout.setEncoding`, `stdout.on("data")`, `on("exit")`, `on("error")`, `kill()`); `scripts/tv-wire-logcat.mjs` does not change.
- `bytes` is the one exemption: its stdout is a PNG and is returned as it is, because a text replacement would corrupt it and it is not adb's text. Its `stderr` is redacted. The screenshot is of the app's first screen; what a screen shows is outside this task.
- `openAdb` refuses a serial shorter than four characters with an `Error` that does not quote it: replacing so short a text everywhere would shred the output. No real serial is that short (an emulator's is `emulator-<port>`). The floor applies to every form `serialForms` derives as well: a form shorter than four characters (the bare host `tv` of `tv:5555`; `octave` of `octave:5555` has six and stays a form) is dropped, so a short name never rewrites the resolved component, a logcat line or an instrumentation value that a script parses.
- Redaction runs before the scripts parse adb's output, so a judged value that held a form of the serial reads `[device]` to its judge. Every judge fails on such a value and none passes on it: the resolved component must start with the application id, a focus line must match `OCTAVE_FOCUS tile-<n>` exactly, the probes' values are compared with exact words or counts (`200`, `ok`, `0`, `permitted`), `missingReverses` reads only `tcp:<port>`, and the one prefix test (`https-call` must start with `failed-`) expects a failure text whatever follows. `scripts/tv-adb-judges.test.ts` holds the cases. A new judge that reads a value must do the same.
- Redaction is silent: unlike a known secret in the wire evidence, a replaced serial is not an error and fails nothing. The serial is not added to the wire run's `secrets` set, where a hit fails every pair; a real TV's log may name its own address.

### The forms of a serial

`serialForms(serial)` returns the texts to replace, matched case-insensitively as plain substrings, longest first, each replaced by `[device]`. Plain substrings on purpose: a boundary rule would miss `192.0.2.44.` at the end of a sentence, and too much replaced is the safe side.

- The serial as given, always.
- When the serial reads as a host with an optional port (`<IPv4>`, `<IPv4>:<port>`, `[<IPv6>]:<port>`, `<name>:<port>`):
  - `<host>:<port>`, with port 5555 when the serial has none (adb's default for `adb connect`);
  - `[<host>]:<port>` and the unbracketed `<host>` for IPv6, with and without a zone id (`%wlan0`);
  - the bare host. Not for a loopback host (`localhost`, `127.0.0.0/8`, `::1`): it is no home-network address, and replacing every `127.0.0.1` would rewrite lines the judges and the wire evidence rely on.
- When the serial is an mDNS name (`adb-<id>._adb-tls-connect._tcp`, with or without a final dot): the name with and without the final dot, and the instance part before `._adb-tls-`.
- A USB or emulator serial (no host part): only the serial as given.

What this does not cover is under Risks: an address the serial does not contain.

### The check

`scripts/check-adb-output.mjs` exports `adbOutputFindings(files)`, where `files` is `[{ path, source }]`, and returns `ERROR adb output: <path>: <reason>` lines. `scripts/check-adb-output.test.ts` runs it over every tracked JavaScript and TypeScript file (`.mjs`, `.js`, `.cjs`, `.ts`) under `scripts/` and `tests/integration/`, except `fixtures/` directories, `.test.` files and type declarations (tests and fixtures start fake adbs on purpose), and over synthetic sources. Files outside those two directories (`apps/tv/src` holds no adb; `modules/`, `packages/` and `apps/tv/plugins` run no adb) and shell scripts are not scanned; see "What the check does not see".

Rules, on the code with comments removed:

1. A file "knows adb" when its code holds the word `adb` at the start of a name or a text (`adb`, `adbPath`, `"platform-tools/adb"`; the match is `/\badb/i`, so `readBackup` is none) or calls `platformTool(`. In a file that knows adb, other than `scripts/tv-adb.mjs`, the first argument of each `spawn`, `spawnSync`, `execFile`, `execFileSync`, `exec`, `execSync` and `fork` call is a string literal or `process.execPath`. A literal can never be the SDK's adb path, which a script gets at run time. A literal and `process.execPath` pass in every file, whether or not it knows adb, and a call split over several lines is read as one call (`scripts/lint-boundaries.mjs:64-65` is `spawnSync(` then `process.execPath,` and is no finding). A file that does not know adb may start any other program held in a variable only if it is pinned: today `scripts/tv-apk-check.mjs`, `tv-apk-manifest.mjs`, `tv-apk-inspector.mjs` and `tv-apk-dex.mjs` (aapt2 and dexdump) and `scripts/check-red.mjs:54` (a manifest's command). Those five files are pinned in the check: a sixth file that starts a program held in a variable is a finding until it is added to the pin, which is a reviewed change. This closes the path of a new helper that does not know adb and is handed the adb path by its caller.
2. A literal first argument is not `adb` and does not end in `/adb`, in any file but `scripts/tv-adb.mjs`.
3. In a file that knows adb, `child_process` (the specifier with or without `node:`) is imported only by a static named import without `as`. A namespace import, a default import, a renamed name, a re-export, `require(` and a dynamic `import(` of it are findings, because rule 1 could not read the calls. So is a use of an imported function as a value (`const run = spawnSync; run(adbPath, …)`, or passing it on): rule 1 reads calls by the imported name. `scripts/tv-wire.mjs` keeps `spawnSync("pnpm", …)`, which rule 1 allows.
4. `scripts/tv-adb.mjs` exists and exports `openAdb`, and each of `tv-first-focus.mjs`, `tv-dev-server-watch.mjs`, `tv-e2e.mjs`, `tv-cleartext.mjs`, `tv-resolved-address.mjs` and `tv-wire.mjs` imports it (so a pass cannot come from a scan that read nothing: T3-26 item 5's lesson). The test also asserts the number of files scanned is at least today's count.

How a new place is caught: a new script that runs adb must either start it itself (rule 1 or 3 fails `pnpm check`) or go through `openAdb`, whose output is already redacted. The check does not follow a value once it is redacted text; that is the point of redacting at the source.

What the check does not see: a file outside `scripts/` and `tests/integration/` (a new top-level directory); a shell script (`scripts/*.sh`, `tests/integration/*.sh`) that runs adb itself; `createRequire`, `process.binding` or a program name built at run time inside a pinned file; a script that prints its own `serial` variable. That is not adb's output and no rule here reads for it; the header comments ("the serial chooses the device; it is never printed or written") and review hold it, and the smoke CLI's test reads its whole console. The documents claim only what is enforced.

Synthetic cases the test holds: `spawnSync(adbPath, …)`; `execFile(adb, …)`; `const tool = platformTool(sdk, name); spawn(tool, …)`; `spawnSync(aapt2, …)` in a pinned file that does not know adb (no finding); `spawnSync(tool, …)` in an unpinned file that does not know adb (a finding); `spawn("adb", …)`; `spawn("/sdk/platform-tools/adb", …)`; `import * as cp from "node:child_process"`; `import { spawn as run }`; `require("node:child_process")`; `await import("node:child_process")`; the bare specifier `"child_process"` as a namespace import and as a named import; `const run = spawnSync; run(adbPath, …)`; a call split over lines with `process.execPath`; a call inside a comment (no finding); `spawnSync("pnpm", …)` (no finding).

### The control window

The watch has three phases instead of two:

| Phase | From | A connection counts as |
|---|---|---|
| before | the bind | a stray |
| controls | the call of `runControls()` | a control |
| app | `runControls()` resolving, as today | the app's |

- `result()` is unchanged: `{ controlsExpected, controlsSeen, appConnections }`. The stray count is a new method, `strays()`, because the frozen test compares `result()` with exactly three keys.
- `runControls()` still resolves to the control commands' failure lines and still closes the window when every control was counted or `CONTROL_WAIT_MS` passed. A control that lands after the window is the app's and fails the run, as today.
- `judgeDevServerWatch(result, controlFailures = [])`:
  - today's two errors, unchanged;
  - one `ERROR tv smoke: <line>` per control failure, whether or not the control was seen. This is the item's second half: a control command that failed cannot be covered by any connection;
  - new: `controlsSeen > controlsExpected` fails with "more connections than controls arrived while the controls ran, so a control cannot be told from another connection; run it again". This catches a stray in the window beside controls that all connected. It does not catch a stray beside a real control and a control that exits 0 without connecting: that gives 2 of 2 and no failure line. Only the control command's exit status closes that path, by meaning "connected": the command must exit non-zero when it cannot connect. Milestone 2 showed that on the emulator (API 36 image, 2026-11-22; the plan holds the output). `toybox nc -w 2 <host> <port> </dev/null` exits 0 when the listener accepts, and exits 1 with `nc: connect: Connection refused` when nothing listens: the 10.0.2.2 control, and the localhost control without an `adb reverse`. The localhost control through the reverse exits 0 even when the host side has no listener, because the device-side forwarder accepts the connection first; that control is therefore counted by the watch's own listener (which holds the reverse's target), not by its exit status. The documents claim no more than that: a failed control command fails the run, and the 10.0.2.2 control's exit status means "connected".
- `runSmoke` passes `controlFailures` to the judge and drops its own `missed` rule (`tv-first-focus.mjs:145-146`).
- A stray before the controls does not fail the run by itself: it cannot stand in for a control any more, and a noisy port can only make the run fail later (an app connection), never pass. It is written to the evidence.
- `dev-server-watch.txt`: the first line becomes `port <port>: <seen> of <expected> control connections seen, <n> app connections, <m> connections before the controls (not counted)`, then the control failure lines and the judge's errors as today.

Why not recognise a control by its content (a nonce the control sends): the frozen fake adb sends no byte and expects to be counted, and the app's own connections, the ones the watch exists to count, could never carry a nonce anyway.

### Two runs on one host

**Choice: the host-wide lock.** Telling emulators apart is not possible at the listener: every emulator reaches the host through its own `10.0.2.2`, which arrives from `127.0.0.1` like any host process, and the app's connections carry nothing that names their emulator.

- The lock is the bind of `127.0.0.1:<port>`, which the kernel grants to one process per host and frees when the process dies, so it cannot go stale. It is already taken before anything touches the device (`tv-dev-server-watch.mjs:57-75` runs before `adb reverse`, and `runSmoke` starts the watch before `adb install`).
- New: the holder writes an owner file, `<os.tmpdir()>/octave-tv-smoke-port-<port>.json`, holding `{ "pid": <its process id> }` and nothing else (never the serial), right after the bind. `stop()` removes it when it still names this process, and so does the failed-reverse path. It lies outside the repository because each agent works in its own worktree, and is keyed by port because the tests run in parallel on free ports.
- A run that gets `EADDRINUSE` reads the owner file:
  - a process id that is alive (`process.kill(pid, 0)` succeeds, or fails with `EPERM`): reject with `another pnpm tv:smoke run on this host (process <pid>) holds port <port>; wait for it to finish: the watch cannot tell two emulators' connections apart, so one run per host at a time (if no smoke run is running, the process id was reused: stop whatever holds the port)`;
  - no file, an unreadable one or a dead process: today's message, reworded to `port <port> is in use on this host by a program that is not a smoke run this one can see: stop Metro; if another smoke run has just started, wait for it`.
  - Both match the frozen `/Metro|smoke/i`; the second matches the unfrozen `/Metro/`.
- A stale owner file (the holder was killed with SIGKILL) is overwritten by the next run that binds, and is ignored by a run that cannot bind because its process is dead.
- The owner file is a hint and never decides a run. Its name is predictable in a shared temporary directory, so it is created without following a link: the path is unlinked, then written with an exclusive create (`wx`), and the reader and the remover use `lstat` and act on a regular file only. A write, a read or a removal that fails (another user's file or link in a sticky `/tmp`, a full disk) is swallowed: it neither fails nor passes a run, and the bind stays the lock. A run that holds no owner file shows the Metro wording to a second run.
- What the lock does not cover: a connection from another emulator or host process that is not a smoke run is still counted (as a stray, a control-window excess or an app connection). Each of those can only fail a run, never pass one.

That rewrites the resolved component (`component.startsWith(...)` in `tv-first-focus.mjs:109`, `tv-e2e.mjs:172`, `tv-wire.mjs:312`), logcat lines the judges parse and instrumentation values. It fails closed, but with a misleading failure. Fix: apply the floor to every form (drop or refuse a derived form that is too short, or match a bare unqualified name on boundaries), and add the case to `scripts/tv-adb.test.ts`.
3. **Medium. The check reads only `.mjs` files under `scripts/`.** Item 2 asks that a new place that skips the redaction is caught. A new script that starts adb from `tests/integration/*.mjs` (two such files exist today), from a `.js`, `.cjs` or `.ts` file, or from a shell script (`scripts/*.sh`, `tests/integration/*.sh`) is not scanned. Fix: either widen the scan to the tracked JavaScript and TypeScript files outside `apps/tv/src`, test files and fixtures, or state the boundary under "What the check does not see" and in the `docs/security.md` row, so the document claims only what is enforced.
4. **Low. Rule 1 for a file that does not know adb must also allow `process.execPath` and a call split over lines.** `scripts/lint-boundaries.mjs:64-65` is `spawnSync(` then `process.execPath,` on the next line, and is not one of the five pinned files. As worded ("a sixth file that starts a program held in a variable is a finding") a naive reading flags it. Say that a literal and `process.execPath` pass in every file, and add the multi-line call to the synthetic cases.
5. **Low. Rule 3 names only `node:child_process`.** The bare specifier `"child_process"` loads the same module, and an alias of an imported name (`const run = spawnSync; run(adbPath, …)`) or passing the function on is not read by rule 1. Add the bare specifier to rule 3 and a synthetic case for each, or list the alias under "What the check does not see".
6. **Low. Redaction runs before the scripts parse adb's output.** Besides issue 2, a form of the serial inside a judged value (a logcat field, an instrumentation value, `reverse --list`) becomes `[device]` before a judge reads it. `missingReverses` reads only `tcp:<port>` after the first field (`tv-wire.mjs:140`), so it is safe; the others were not traced. Say in the spec that a judge must fail, never pass, on a value holding the stand-in, or that the case is accepted, and note it under Risks.
7. **Low. The owner file.** (a) Its name is predictable in a shared temporary directory: on a multi-user host another user can leave a file or a symbolic link at that path, and a sticky `/tmp` then refuses the overwrite and the removal. Say that a failed write or removal of the owner file never fails or passes a run, and create it without following a link (exclusive create after an unlink, or write-and-rename). (b) A stale file whose process id was reused by a live process makes the message name "another pnpm tv:smoke run" when Metro holds the port; it still matches the frozen `/Metro|smoke/i` but not the unfrozen `/Metro/`. Accept it under Risks or name both causes in that message.
8. **Low. IPv6 spellings.** `serialForms` lists the address as written; the same address in another spelling (expanded, or upper case inside brackets beyond the case-insensitive match, or an IPv4-mapped form of an IPv6 serial) is not a form. Add it to "An address the serial does not contain" under Risks and to the `docs/security.md` row's not-covered list.
9. **Low. Unverified facts the implementer should settle first.** The spec itself marks these unverified: Node's `Command failed: …` message text, adb's wording for a missing network device, and the control command's exit status on the CI image. The first no longer matters once `adbRunner` is gone; the other two are covered by the several wordings in the tests and by milestone 2. Record the observed values in the plan.

Verdict: **Approved.** No critical or high issue. The implementer resolves issues 1 to 3 (medium) and logs or fixes 4 to 9.
