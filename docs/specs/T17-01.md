# T17-01: Scaffold apps/web and packages/web-host with their lints, boundaries and a CI job

Plan: `docs/plans/active/017-octave-web-client.md` (milestone 8's first build, and the base every later T17 task builds on). Domain: App Shell & Presentation. Lane: `web`. Implementer: `implementer` (TypeScript only; no Kotlin, no native module). Refined 2026-11-26 on `task/T17-01`, which sits on PR #368.

## Goal

An empty web form that is built, served and linted the way every later web task will be: `apps/web` (React DOM 19.3.0 with Vite) builds into one static build with relative asset URLs, which draws its root in Chromium and Firefox at `/` and at a second prefix under the plan's CSP, with no request outside the prefix; `packages/web-host` exists as the one place the web form may name a network or storage API; the import and API boundaries fail a bad file; and CI runs it. Nothing else: no screens, no sign-in, no storage, no hls.js, no token. Decision 0006 is not accepted, so nothing here holds, sends or names a token.

## Approach

1. **apps/web.** `react` 19.3.0 and `react-dom` 19.3.0 exact (the TV's `react`), `@types/react` ~19.3.0, `@types/react-dom` 19.3.0, `vite` 8.3.8, `@playwright/test` 1.65.1, `vitest` 5.1.1 (the repo's version). No `@vitejs/plugin-react`: Vite 8 transforms JSX itself; if the build needs the automatic runtime named, set it in `vite.config.ts` (`oxc.jsx`). Adopting the plugin anyway needs no new check (data in "Dependencies") but must be justified in the PR. `tsconfig.json`: `lib` ES2023 + DOM, `jsx: react-jsx`, strict, `noEmit`. `@octave/core` is not imported yet (nothing needs it), so its resolution is left to T17-10/T17-11.
2. **The root placeholder.** `<main><h1>Octave</h1></main>`, `lang="en"`, no CSS, no colours, no font. React draws the heading, so its presence proves the script ran under the CSP. The icon link is `./favicon.ico` with no file: browsers then ask for it inside the prefix (a 404 inside the prefix), not at `/favicon.ico`; the real icon from the D1 bars mark is a later design task (backlog line).
3. **packages/web-host.** A package with `src/index.ts` holding `export {};` and no test script until T17-11 gives it code. It exists so the lint and boundary rules have their allowed place and are tested against it.
4. **Boundaries (`.dependency-cruiser-web.cjs`, cruising `apps/web/src` and `packages/web-host/src`):** `web-not-from-tv` (to `^(apps/tv|modules)/`); `web-no-native-platform` (to `(^|node_modules/)(react-native|@react-native|expo|@expo)([-/]|$)`, which also matches the unresolved specifier); `web-host-not-from-app` (from `packages/web-host` to `apps/web`: adapters never import screens, DOMAINS rule 3); `no-circular`. `scripts/lint-web-boundaries.mjs` takes `--root`, fails a run that read nothing or skipped a source file (via `findLintGaps`), and prints `N/N source files under apps/web/src and packages/web-host/src`. `packages/core` importing `packages/web-host` is already refused by `core-is-platform-free` and stays so; no core rule is edited.
5. **API lint (`eslint.web.config.js`)**, files `apps/web/**` and `packages/web-host/**`, parser `@typescript-eslint/parser` (already in the repo). Outside `packages/web-host/**`: `no-restricted-globals` for `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `localStorage`, `sessionStorage`, `indexedDB`; `no-restricted-properties` for those names on `window`, `globalThis`, `self`, plus `document.cookie` and `navigator.serviceWorker`; `no-restricted-syntax` for `MemberExpression[property.name=/^(fetch|XMLHttpRequest|WebSocket|EventSource|localStorage|sessionStorage|indexedDB|cookie|serviceWorker)$/]` and the computed-string forms (the TV's alias-proof pattern, `eslint.config.js:126`); `no-restricted-imports` for `react-native*`, `@react-native/*`, `expo*`, `@expo/*`. Every message names the alternative: "Only packages/web-host may reach the network or browser storage (plan 017, milestone 3). Take it through a port the host supplies." `web:lint` runs ESLint with `--config eslint.web.config.js --max-warnings 0 apps/web packages/web-host` (ESLint's docs: with `--config`, patterns are relative to the working directory). `apps/web/dist/**` is ignored.
6. **web:test.** `web:test` = `pnpm web:build && pnpm --filter @octave/web exec playwright test`. `e2e/serve.mjs` is a `node:http` server on `127.0.0.1:0` serving `dist/` at `/` and `/second/prefix/` with the CSP header, `X-Content-Type-Options: nosniff`, and 404 for anything else; started by Playwright's `webServer` or a global setup. Two projects: `chromium`, `firefox`. The page URL always ends in `/` (a missing trailing slash is the server's to redirect, Jellyscale's handler in milestone 8, not this build's).
7. **Unit tests (`web:unit`).** `pnpm --filter @octave/web test` (Vitest, `environment: node`): the root renders its heading through `react-dom/server`'s `renderToStaticMarkup`. No jsdom.
8. **CI `web` job.** `runs-on: ubuntu-22.04`, `timeout-minutes: 15`, no `needs`, no `if` (it runs on every event, like `checks`); checkout, pnpm 11.3.0, setup-node from `.node-version` with the pnpm cache, `pnpm install --frozen-lockfile`, cache `~/.cache/ms-playwright` keyed on the Playwright version, `pnpm --filter @octave/web exec playwright install --with-deps chromium firefox`, `pnpm web:test`, upload the Playwright report on failure. Actions pinned by SHA as the other jobs are. **The skip rule is not loosened**: `scripts/ci-device-jobs.mjs` and the three device jobs are untouched, so web PRs still run the TV's device jobs (plan 017, Risks). The job is not made a required check here (see Open questions).

**Cost to the TV session's CI.** One more Ubuntu job per push and per pull request, in parallel with the others, estimated 4 to 6 minutes (install, about 250 MB of browsers on a cold cache, two builds' worth of Playwright runs; unverified until the first run). It does not lengthen a TV PR's wall-clock time (the `tv` and `wire` jobs take up to 60 minutes), but it takes one more runner slot from the account's concurrent-job limit. The `checks` job gains three steps, measured in seconds (ESLint on a few files, two `tsc` runs, one Vitest file). TV PRs touch no web file, but still pay the web job; skipping it on TV-only changes would be a new skip rule, not part of this task.

## Test plan

**Item 3, proven without testing the harness.** As T2-02 (`scripts/core-boundaries.test.ts`) and T3-04 (`scripts/network-lint.test.ts`) do: each test runs the real lint on a real file and asserts what the lint refuses or accepts. No test reads a config file, counts rules, compares lists or checks a script's wording; a test would still pass if the config were rewritten with the same behaviour.

- `scripts/web-boundaries.test.ts` builds a temporary tree (`tsconfig.json`, `apps/web/src/ok.tsx`, `packages/web-host/src/index.ts`) and runs `node scripts/lint-web-boundaries.mjs --root <tmp>`. Refused (non-zero exit, rule name in output): `apps/web` imports `../../tv/src/x`; `apps/web` imports `../../../modules/session/src`; `packages/web-host` imports `apps/tv`; `apps/web` imports `react-native`; `apps/web` imports `expo`; `packages/web-host` imports `apps/web`; a type-only import of `apps/tv` from `apps/web`; a cycle inside `apps/web`. Accepted: the clean tree, with "2/2 source files". A tree whose `apps/web/src` is missing fails (the lint read nothing). The core case runs the existing `scripts/lint-boundaries.mjs --root <tmp>` on a tree where `packages/core/src/x.ts` imports `../../web-host/src` and asserts `core-is-platform-free`.
- `scripts/web-lint.test.ts` runs ESLint with `--config eslint.web.config.js --stdin --stdin-filename <path>`, as `network-lint.test.ts` does. For each of the nine names, on `apps/web/src/probe.tsx` and `apps/web/src/probe.ts`: a bare use, a `window.`/`globalThis.`/`self.` member, an alias (`const g = globalThis; g.fetch`) and a computed string (`window["localStorage"]`) are refused with the rule's message. `document.cookie` read and written, `navigator.serviceWorker.register` and `navigator["serviceWorker"]` are refused. Imports of `react-native` and `expo-crypto` are refused. The same uses on `packages/web-host/src/probe.ts` are accepted, and so is a plain component in `apps/web`.

**Items 1 and 2.** `apps/web/e2e/build.spec.ts` (four runs: two browsers × two prefixes), as in the table. These are the behavioural proof; no test asserts the build's file layout.

**Unit.** `apps/web/src/app.test.tsx`: the root's markup holds a level-one heading "Octave".

All of these fail before implementation (the files they spawn or import do not exist), which is the failing-tests step.
