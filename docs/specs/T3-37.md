## Goal

T3-30 put every adb call behind `scripts/tv-adb.mjs`, which writes `[device]` for the serial and for each host-and-port form of it. Three leaks are left, and the owner's Shield hits the first one: the owner reaches it "by name or pairing, or is not sure" (owner answer 4).

1. A serial given as a host name (`shield.example:5555`), an mDNS name from pairing (`adb-<id>._adb-tls-connect._tcp`) or a USB-style serial holds no address. The device's addresses still reach the output: in logcat lines, instrumentation values and adb's own text. T3-30 does not replace them.
2. The serial's own IPv6 address, written another way (`2001:0db8:0:0:0:0:0:7` for `[2001:db8::7]:5555`, or `::ffff:c000:22c` for `192.0.2.44`), is not replaced.
3. The SDK path in `scripts/tv-android-sdk.mjs`'s errors, and the APK path in the apk checks' and device scripts' lines, are printed whole, so the console and CI logs show `/home/<name>/…`.

After this task the scripts learn a named serial's addresses before they use the device, and replace them in every spelling. They print every SDK and APK path with the home directory written as `~`.

## Approach

### The kinds of serial

`serialKind(serial)` in `scripts/tv-adb-addresses.mjs`. The rules for telling an address from a name are the ones `serialForms` already uses:

| Kind | Example | What is learned | Refused when nothing is learned |
|---|---|---|---|
| `emulator` | `emulator-5554` (`/^emulator-\d+$/`) | nothing | no |
| `address` | `192.0.2.44:5555`, `192.0.2.44`, `[2001:db8::7]:5555`, a bare IPv6 address | nothing: the address is the serial's own, matched in every spelling (item 2) | no |
| `mdns` | `adb-<id>._adb-tls-connect._tcp`, with or without a final dot | the device's interfaces; adb's mDNS list for the instance | yes |
| `host` | `shield.example:5555`, `tv.local`, any name with a port | the device's interfaces; the host resolver's answers for the name | yes |
| `other` | a USB serial, `tv-serial-1` | the device's interfaces, best effort | no |

`other` is never refused. It has no network path, and the frozen T3-19 test starts the watch with `tv-serial-1` against a fake that answers nothing.

### Learning a named serial's addresses

```
export async function openDeviceAdb({ adbPath, serial, lookup = dnsLookupAll }): Promise<AdbRunner>;
export function openAdb({ adbPath, serial, addresses }): AdbRunner;   // sync, as today
```

- For `emulator` and `address`, `openDeviceAdb` learns nothing and returns `openAdb({ adbPath, serial, addresses: [] })`. It makes no extra adb call, so every frozen test that uses those serials sees the same calls as today.
- For `host`, `mdns` and `other`, it gathers addresses from up to three places and puts them in a set:
  - **The device's interfaces.** It runs `<adb> -s <serial> shell ip -o addr show` with a 15 s timeout and keeps every address that follows `inet ` or `inet6 `, with its prefix length and any `%zone` cut off. A failed call adds nothing.
  - **adb's mDNS list** (`mdns` only). It runs `<adb> mdns services` (no `-s`, as `adb help` lists it) and keeps the address of each line whose first field is the serial's instance part (`adb-<id>`). The line format is under Facts.
  - **The host resolver** (`host` only). It calls `lookup(name)`, which defaults to `dns.promises.lookup(name, { all: true })` from `node:dns`, the resolver adb's host process also uses (unverified from adb's source). A failure adds nothing. `lookup` can be passed in, for tests only; no environment variable sets it.
- It drops a loopback address (`127.0.0.0/8`, `::1`) and an unspecified one (`0.0.0.0`, `::`). T3-30 keeps loopback text because the judges and the wire evidence read `127.0.0.1` (`docs/specs/T3-30.md`, "The forms of a serial"). It keeps link-local addresses (`fe80::…`), which can be built from the device's MAC address.
- For `host` and `mdns`, an empty set rejects with `Error("the network addresses of the device ANDROID_SERIAL names could not be learned from the device, adb's mDNS list or this host's resolver, so they cannot be kept out of the output; connect the device and run again, or set ANDROID_SERIAL to <address>:<port>")`. The message holds no form of the serial. Each caller prints it after its own `ERROR tv <area>:` prefix, as it prints any other failure. That is the one ERROR line, and no further adb call follows it.
- The learning reads adb's raw output inside `tv-adb.mjs` and never returns it, logs it or writes it. Only the learned set leaves the function, and only as `openAdb`'s `addresses`.
- `openAdb` without `addresses`, for a `host` or `mdns` serial, throws an `Error` that does not name the serial and says to use `openDeviceAdb`. A caller that skips the learning therefore fails closed, and the static check needs no new rule. `openAdb` without `addresses` for the other kinds behaves as today, which keeps the frozen synchronous calls working.
- **Order in the watch.** `startDevServerWatch` calls `openDeviceAdb` after the bind and the owner file, and before `adb reverse`. A second run that cannot bind still touches no device (the frozen lock test). If the open rejects, the watch closes the listener and removes the owner file, as on a failed reverse, and then rejects.
- Each caller learns once per runner it opens. The smoke run opens a runner in `runSmoke`, in the watch and in `smokeCli`: up to three `ip` calls on a named serial, each well under a second. That cost is accepted to keep the signatures as they are.

### Matching an address in any spelling

The new `redactAddresses(text, addresses)` lives in `scripts/tv-adb-addresses.mjs`. `openAdb`'s `redact` runs, in order:

1. T3-30's substring pass (`redactSerial`), unchanged. The frozen exact outputs stay as they are, because this pass runs first.
2. The address pass, over the set made of the serial's own address (kind `address`, unless loopback) and the learned addresses:
   - **IPv6 tokens.** A run of hex digits, colons and dots holding at least two colons, with an optional `%zone` and optional enclosing brackets. It must not sit next to another hex digit or colon. The zone is cut off, and the rest is parsed with `new URL("http://[" + token + "]/").hostname`. A token that does not parse is left alone, which is why a logcat time such as `10:22:33` is safe. A token whose canonical form is in the set is replaced by `[device]`, together with its brackets and zone. A `:<port>` after it stays.
   - **IPv4 tokens.** Four dot-separated runs of one to three digits, not next to another digit or dot. A token whose four numbers equal a set member's is replaced.
   - **For each IPv4 address in the set**, its IPv4-mapped forms (`::ffff:a.b.c.d` and `::ffff:xxxx:xxxx`, compared in canonical form) are in the set too.
3. `hideHostPaths` (below).

`redactSerial(text, serial)` also runs the address pass with the serial's own address, so item 2 holds for the pure function that `scripts/tv-adb.test.ts` and `scripts/tv-adb-judges.test.ts` already use. The frozen cases still give their exact outputs:

- the bracketed T3-30 case is already `[device]` after the substring pass;
- the loopback case keeps `127.0.0.1`;
- `::ffff:192.0.2.44 refused` still holds `[device]` and not the address.

Judges fail closed on a value that now holds `[device]`, as T3-30 showed (`scripts/tv-adb-judges.test.ts`). An extra replacement can make a run fail, never pass.

### Host paths

`scripts/tv-host-paths.mjs`:

```
export function shownPath(path, { repo = REPO, home = os.homedir() } = {}): string;
export function hideHostPaths(text, { repo = REPO, home = os.homedir() } = {}): string;
```

- `shownPath` resolves the path. Inside `repo` (at a segment boundary) it gives the repository-relative path with `/` separators. Otherwise, inside `home`, it gives `~/<rest>`. Otherwise it gives the path as it is: `/tmp/…` and `/opt/android-sdk` hold no home directory name.
- `REPO` is the checkout root, from `import.meta.url`. The CI runner's checkout (`/home/runner/work/octave/octave`) is shown repository-relative.
- `home` is used only when it is absolute and is not `/`.
- `hideHostPaths` replaces, longest first, every occurrence of `repo` followed by a separator with nothing (the rest reads as a relative path), and every occurrence of `home` followed by a separator, or at the end of the text or before a quote, with `~` (with the separator kept).
- `scripts/tv-android-sdk.mjs` keeps each message's words and changes only the path:
  - `ANDROID_HOME is ${shownPath(dir)}, which does not exist`;
  - `no ${tool} under ${shownPath(root)}; …`;
  - `no ${tool} under ${shownPath(join(sdk, "platform-tools"))}; …`.

## Risks and out of scope

- **A USB-style serial (`other`) whose `ip` call fails** learns nothing and is not refused, so a USB-connected TV's LAN address in logcat is printed as it is. Refusing it would contradict the frozen test "a USB-style serial that learns nothing is not refused" (its fake exits 1 for `ip`), so the case is named here and in the new `docs/security.md` row's "Not covered" list, which therefore says that a USB serial is covered only when `ip` answers.
- **`ip -o addr show` on a TV image.** Whether the shell user can run it on the Shield's Android version is unverified. If it cannot, a `host` serial still learns from the resolver and an `mdns` serial from adb's list. If none of them answers, the run is refused, which fails closed. Milestone 1 checks the emulator image. The Shield is the T3-17 device gate.
- **An address no source reports** is not replaced. Examples:
  - a host-side NAT or VPN address the resolver does not return;
  - a second interface of a device given as `<address>:<port>`, where nothing is learned;
  - the TV's own host name in its log lines.

  The documents say so. Append a backlog line: "Learn the device's interface addresses for a serial given as an address with a port too, and replace the device's host name" (source T3-37, size S).
- **Too much replaced.** Only exact address matches are replaced, so the cost is a `[device]` in place of the device's own address in a line a judge reads. The judge then fails closed (T3-30). On the emulator path (`emulator-…`) nothing new is replaced, so CI's smoke, e2e and wire runs see no change in the text the judges read.
- **The frozen T3-31 mapping case** relies on `os.tmpdir()` lying outside the home directory. On a host whose `TMPDIR` is under `$HOME`, `no R8 mapping at` would print `~/…` and that frozen test would fail there. It holds on this host (`/tmp`) and on CI (unverified for CI, but the runner's default `TMPDIR` is `/tmp`). If it is wrong, it is a frozen-test problem for the Product Owner, not a reason to keep full paths.
- **Another user's home** (`sudo`, a shared SDK under `/home/<other>/…`) is not `os.homedir()` and is printed as it is. A path outside the repository and the home directory that holds a name is out of scope. The documents say so.
- **The resolver** can be slow for a name that does not answer. `dns.promises.lookup` has no timeout option (unverified for Node 26). Wrap it in a 5 s race, after which nothing is learned from it.
- **Several learnings per run** on a named serial: accepted. Sharing one runner would change frozen signatures.
- Out of scope:
  - the screenshot (unchanged since T3-30);
  - the Shield and any real TV (T3-17);
  - network adb set-up;
  - the check in `scripts/check-adb-output.mjs` and its listed lows (plan 011);

## Decisions

- **Canonical comparison through the WHATWG URL parser**, a Node built-in, verified on this host for the spellings the tests use.
- **`~` for the home directory and repository-relative paths**, not file names alone. A full path outside both, such as `/tmp/…`, is kept, so the frozen T3-31 assertion holds and an error still says where to look.
- **Paths are hidden in adb's runner output too**, because adb names the APK it was asked to install.
