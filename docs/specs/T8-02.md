## Goal

Behind T8-01's seam, an Android engine plays an original file with Media3: one ExoPlayer per launch, built only with Octave's media source factory, whose only data source is Media3's OkHttp data source over `OctaveHttp.callFactory(session)`, drawing on the player view's `SurfaceView`. The engine reports `first-frame` when a frame is presented, the decoder's name and hardware or software as Media3 reports them, maps every failure to a port code natively, and on stop releases the player and lets go of the surface. A refused redirect on the media request is a typed error and the other origin receives nothing. On the CI emulator the H.264, HEVC and AV1 samples reach the first frame where the emulator has a decoder, and a sample no decoder can play ends in `decoder-unavailable`. A wire capture against the pinned Jellyscale shows the header on every request, range requests included, no credential parameter, and only original-file media URLs. The build fences of T3-04 are re-proven on compiled Media3 classes, and Media3's OkHttp data source is proven on the one client's OkHttp.

The capability probe stays "cannot tell" (`Capabilities.Failed`): reporting decoders is T8-07. HLS launches stay `unsupported-request` until T8-08.

### Threading

- The ExoPlayer's application looper is the main looper. Every `PlaybackEngine` method runs its work on the main thread: inline when the caller is already on the main looper (`Looper.myLooper() == Looper.getMainLooper()`), otherwise posted to a main-thread `Handler` and waited for, at most 10 s; a timeout answers `PlayerEngineException(UNKNOWN)` (the seam maps it). `CommandQueue`'s thread takes the posted path. `OnDestroy` calls the engine's `stop()`: which thread Expo calls it on is unverified, and the inline rule means a main-thread destroy neither blocks the main thread nor waits out the timeout (spec check issue 3). `scripts/tv-player-media3-engine.test.ts` holds the inline check and `OnDestroy`'s stop as source facts. `EngineCore` runs only on the main thread, so it needs no lock.
- The `VideoSurfaceSlot` listener runs on the UI thread, which is the main thread: it calls the handle's `setSurface` directly and never waits, as `SurfaceSlot`'s contract asks. `surfaceDestroyed` therefore clears the player's surface before it returns.
- No thread that the main thread waits on calls into the slot, so no deadlock.
- Events go out from the main thread through the seam's `emit`, which calls Expo's `sendEvent`.
- The engine needs a `Context`: `Media3Engine` takes a provider (`{ appContext.reactContext?.applicationContext }`) and reads it at the first launch, so the module needs no `OnCreate`. No context answers `unsupported-request`.

### The engine core (plain Kotlin, JVM-tested)

```kotlin
interface PlayerHandle {                       // one ExoPlayer; Media3Handle implements it
  fun prepare(url: String, startPositionMs: Long)
  fun setPlayWhenReady(play: Boolean)
  fun seekTo(positionMs: Long)
  fun setSurface(surface: Any?)
  fun stop()
  fun release()
  fun facts(): HandleFacts                     // position, duration, play-when-ready, buffering, dropped frames, video size
}
sealed class EngineSignal {
  object Buffering; object Ready; object Ended; object FirstFrameRendered; object SeekProcessed
  class TracksKnown(val videoPresent: Boolean, val videoSupported: Boolean, val audioPresent: Boolean, val audioSupported: Boolean)
  class DecoderInitialized(val name: String, val hardwareAccelerated: Boolean?, val softwareOnly: Boolean?, val sdkInt: Int)
  class Failed(val mediaCode: Int, val causes: List<Throwable>)
}
class EngineCore(newHandle: (LaunchRequest.Original) -> PlayerHandle, emit: (PlayerEvent) -> Unit) {
  fun launch(request: LaunchRequest); fun setPaused(paused: Boolean); fun seek(positionSeconds: Double)
  fun selectTrack(type: TrackType, playerId: Int?); fun stop(); fun surface(surface: Any?); fun signal(signal: EngineSignal)
}
```

Rules:

- **E1 launch.** An `Original` request: stop any current handle first (as `stop`, without a second `ended`), build a new handle, give it the current surface, `prepare(url, start)`, play when ready. An `Hls` request throws `PlayerEngineException(UNSUPPORTED_REQUEST)`.
- **E2 loaded.** The first `Ready` of a launch emits `loaded` with a snapshot.
- **E3 first frame.** `FirstFrameRendered` emits `first-frame` once per launch. `Buffering`, `Ready`, `TracksKnown`, `SeekProcessed` and preparing never do.
- **E3a stale signals.** `EngineCore.signal` emits nothing when no launch is active (before the first launch, after stop) or after the launch failed (E8), so an empty-tracks report on stop or error cannot read as a missing decoder. `Media3Engine` passes a handle's signal to the core only while that handle is the core's current one (`EngineCore.isCurrent(handle)`), so a stopped or replaced player says nothing. `EngineCoreTest`'s `stop_drops_every_later_signal_of_the_stopped_handle`, `no_decoder_judgement_after_stop` and `no_decoder_judgement_after_the_launch_failed` hold it (spec check issue 7).
- **E4 pause and seek.** `setPaused(p)` calls `setPlayWhenReady(!p)` and emits `state` with cause `pause`. `seek(s)` needs a finite `s >= 0`, calls `seekTo`, and emits `state` with cause `seek` on the next `SeekProcessed`.
- **E5 decoder facts.** `DecoderInitialized` updates the diagnostics through `DecoderFacts.read` and emits `state` with cause `property`.
- **E6 no decoder.** On `TracksKnown`, while the launch is active and has not failed: when the request lists a `Video` track that is not `external` and `videoPresent && videoSupported` is false, or lists a non-external `Audio` track and `audioPresent && audioSupported` is false, the launch fails with `decoder-unavailable` (E8). Media3 skips an unsupported track and would otherwise play without picture or sound (D5).
- **E7 end.** `Ended` emits `ended` with reason `eof` and a snapshot.
- **E8 failure.** `Failed` emits `error` with `PlaybackErrors.codeFor(mediaCode, causes)`, then `ended` with reason `error`. The handle stays until the coordinator's `stop` (it calls `stop` on `ended`).
- **E9 stop.** `setSurface(null)`, `stop()`, `release()` on the handle, in that order, once; drop the handle; emit `ended` with reason `stopped` when a launch was active. With no handle, `{}` and no event. After a stop, `setPaused`, `seek` and `selectTrack` throw `UNSUPPORTED_REQUEST`.
- **E10 tracks.** `selectTrack` throws `UNSUPPORTED_REQUEST` (track mapping is T8-10). Snapshots carry `tracks: []`, no `audioTrack` or `subtitleTrack`, `volume: 100`, `muted: false`.
- **E11 snapshot.** `positionSeconds`, `durationSeconds` when known, `paused`, `buffering`, and `diagnostics { decodeMode, decodeLabel, droppedFrames, width?, height? }` from `HandleFacts` and `DecoderFacts`. `video`, `audio`, `bufferedSeconds`, `diagnostics.videoCodec` and `diagnostics.bitDepth` are `null` until T8-06 (spec check issue 9). No string comes from a Media3 message (T2-05 L7); `decodeLabel` is the decoder's name, and the seam cuts it to 256 characters.

`Media3Engine` adds: `capabilities()` answers `Capabilities.Failed` ("cannot tell"; T8-07 builds the probe); `setListener` stores the seam's listener; the slot listener is set on the first launch and removed on stop; `Media3Handle` turns `onPlaybackStateChanged`, `onRenderedFirstFrame`, `onTracksChanged` (`Tracks.containsType` and `isTypeSupported(type, true)`), `onPositionDiscontinuity` with a seek reason, `onVideoDecoderInitialized` (with Media3's `MediaCodecInfo` for that name from `MediaCodecUtil.getDecoderInfos(mime, false, false)`) and `onPlayerError` (its `errorCode` and the cause chain) into signals. The engine logs nothing.

### Error codes (items 5 and 6)

`PlaybackErrors.codeFor(mediaCode, causes)`: the first `OctaveHttpException` in the cause chain wins: `REDIRECT` → `server-error`; `NO_SESSION` → `session-ended`; `RESOLVED_PUBLIC` → `network`; every other refusal → `unsupported-request`, written as the `else` branch of the `when`, naming no other constant (the frozen `SessionAuthorityTest` fails the word "header" in the module's main Kotlin; spec check issue 8). Otherwise by Media3's code:

| Media3 codes | Port code |
|---|---|
| 2000, 2001, 2002 | `network` |
| 2003, 2004, 2005, 2006, 2008 | `server-error` |
| 2007 | `network` |
| 3001, 3002, 3003, 3004 | `malformed-media` |
| 4001, 4002, 4003, 4006 | `decoder-failed` |
| 4004, 4005 | `decoder-unavailable` |
| 5001, 5002, 5003, 5004 | `audio-output-failed` |
| 6000 to 6008 | `unsupported-request` |
| anything else (1000 to 1004, 7000, 7001, the session codes, an unknown number) | `unknown` |

The table holds the numbers as literals in `engine/` (plain Kotlin); `PlaybackErrorsTest` checks each literal against `PlaybackException.ERROR_CODE_*` (compile-time constants, so the test needs Media3 only to compile), so a Media3 upgrade that renumbers fails the test. `OctaveHttpException` comes from the session module, which `engine/` may import (it is plain Kotlin). Nothing of a throwable but its class and refusal is read.

### Decision log

- **D1. Media3 1.11.1, the newest stable.** 1.12.0 is at beta01 (2026-11-11); Octave adopts no pre-release.
- **D2. Octave's media source factory is `ProgressiveMediaSource.Factory`, not `DefaultMediaSourceFactory`.** It plays only progressive files, loads no other factory by reflection, and never builds `DefaultDataSource`. T8-08 adds the HLS factory with the validating parser.
- **D3. One ExoPlayer per launch, released on stop.** It makes "stop releases the player" literal and binds the data source factory to the launch's session. The cost is building a player per play, which is small next to the network start.
- **D4. The main looper is the player's.** The surface callbacks arrive there; no thread hop sits between `surfaceDestroyed` and clearing the surface.
- **D5. A missing decoder is an error, not a silent play.** Media3 skips a track it cannot decode; the engine ends the launch in `decoder-unavailable` when the request listed an embedded video or audio stream that cannot play. Playing without picture or sound would hide what I1 and T8-07 need to see (the forced conversion). This holds for audio as for video.
- **D6. The capability probe stays "cannot tell".** T8-07 owns reporting the device's decoders; T8-01 D1's answer stays.
- **D7. Errors are mapped from the cause chain first, then Media3's code.** A refusal of the one client is more exact than Media3's generic `2001`. A redirect is `server-error`, as the port's comment for that code says.
- **D8. No retry of a refusal.** `RefusalRetryPolicy` extends `DefaultLoadErrorHandlingPolicy` and answers `C.TIME_UNSET` for an error whose cause chain holds an `OctaveHttpException`, so a refused redirect or an ended session fails at once and the server is not asked again.
- **D9. Media3's two permissions are removed, not allowed.** Octave needs neither.
- **D10. Item 8's play is the wire test.** On the JVM, `DataSpec` and `OkHttpDataSource.getUri` need `android.net.Uri`, which the unit-test `android.jar` stubs throw on, and Robolectric is refused in the player's Gradle file by a frozen T8-01 test; so the JVM test proves the linking and the reads, and the e2e APK plays through it on the device.
- **D11. Item 10 is a gate, met by this spec.** It is a record, not a behaviour.
- **D12. Media3's logging is off.** `Log.setLogLevel(Log.LOG_LEVEL_OFF)` before the first player: defence in depth for "Never log ... play-session IDs", since Media3's messages are not Octave's to check. It is not a log call, and neither frozen scan nor `pnpm lint:logs` reads it as one (Facts).
- **D13. The ruled D4 exception, as the real release APK shows it** (2026-11-23, local `pnpm tv:build` then `pnpm tv:apk:check`, exit 0). R8 merged `OkHttpDataSource$Factory` horizontally into a dex class (`w62` in that build) that holds about thirty unrelated originals, and kept its constructor as a member line with residual signature `(Lbr;)V` (`br` is `okhttp3.Call$Factory`). The engine's constructor (`Media3Handle.<init>`, source line 41) holds `new-instance` of the merged class, which D4 cannot attribute and counts among the references left to `NetworkPathsBytecodeTest` (the count went from 1 to 2), and `invoke-direct` of the factory's constructor, whose member line names only the factory: that is the shape E1 allows, and E1 is used. `ProgressiveMediaSource.Factory`'s constructor takes the merged class in the dex, but its member line's original signature names `DataSource$Factory`, which no row lists. No other Media3 class holds a sink, no other shape appears, and D7 passes.
- **D15. Decoder facts wait for the input format.** ExoPlayer reports `onVideoDecoderInitialized` before `onVideoInputFormatChanged` for the format that made the decoder, so `Media3Handle` sends `DecoderInitialized` once it has both the name and the format's MIME type (found on the emulator: the first run read `decode-h264=unknown`).
- **D16. A seek is pending before `seekTo`.** ExoPlayer reports the seek's position discontinuity on its own looper while `seekTo` runs, so `EngineCore` marks the seek pending first (found on the emulator: the first run read `seek=timeout`; `EngineCoreSyncSignalTest` holds it).
