A native validator (Kotlin, T8-08) must see the master URLs that a forced conversion produces: the plan Playback Negotiation builds when the server offers direct play, no engine on the device can play the video, and the second PlaybackInfo (`EnableDirectPlay` false, `AllowVideoStreamCopy` false) comes back as an HLS conversion. Today those plans are in no shared file (`packages/core/tests/fixtures/README.md:19`: "the T2-07 `device-conversion-*` answers are not vectors"), and the AV1 answer is checked live only (`docs/specs/T2-09.md:207`).

After this task:

2. `packages/core/tests/fixtures/hls-master-urls-device-conversion.json` holds 12 plans: three samples, two servers, a server address with and without a base path.
3. A core test builds the same 12 plans through the gateway, compares them with the file, and checks each master URL with `rebuildMasterUrl`.
4. `packages/core/tests/fixtures/hls-master-urls.json` is unchanged, byte for byte.

## Approach

### The vectors

12 vectors, in this order: version (`10.11.7`, `12.4.0`), then sample, then server address.

| Sample | Item id | First answer | Forced answer | Capability list |
|---|---|---|---|---|
| `h264` | `item-h264` | `conversion-h264.json` | `device-conversion-h264.json` | every video codec but `h264` |
| `hevc-hdr10` | `item-hevc` | `conversion-hevc-hdr10.json` | `device-conversion-hevc-hdr10.json` | every video codec but `hevc` |
| `av1` | `item-av1` | `conversion-av1.json` | `device-conversion-av1.json` | every video codec but `av1` |

- Server addresses: `http://127.0.0.1:8096` and `https://media.test/jellyfin`, the two of `hls-master-url-vectors.test.ts:22`.
- Capability lists are T2-09's `no-h264`, `no-hevc` and `no-av1` shapes: `listOf` with `h264`, `hevc`, `av1`, `vp9` less one, and the audio list `aac`, `ac3`, `eac3`, `opus`, `flac`, `mp3`.
- Each plan comes from `negotiate(itemId, [first, forced], capabilities, { server })`: the real two-request flow, so the plan is what a device hands its native validator. The test also asserts two PlaybackInfo requests were sent and that the plan has `delivery: "hls"`, `playMethod: "Transcode"` and `clientConversionReason: "DeviceCannotPlay"`.
- Name: `<version> device-conversion-<sample> <server address>`, for example `12.4.0 device-conversion-av1 https://media.test/jellyfin`.
- File shape: `{ "description": "…", "vectors": [{ "name", "plan" }] }`, two-space JSON with a final newline. It is the `vectors` shape of the frozen file, so T8-08 reads both with one deserializer. There is no `refusals` key: the refusal rules do not depend on how the conversion was asked for, and the 64 refusals of the frozen file cover them.
- "Expected verdict" in item 3 is therefore "accepted" for all 12: the rebuild returns the URL unchanged.

### The scrub checks (item 4)

Over the file's text and each plan:

- Hosts are checked by an allowlist, not by scanning the text for address shapes (every 10.11.7 vector name starts with `10.`): `serverUrl` is exactly one of the two addresses above, and the parsed `host` of every `serverUrl` and `streamUrl` is exactly `127.0.0.1:8096` or `media.test`, with the `streamUrl` origin equal to its `serverUrl` origin.
- The file's text matches none of: a credential name followed by `=` or `%3D` (`ApiKey`, `api_key`, `access_token`, `Token`, `X-Emby-Token`, `ApiToken`, `AccessToken`, any case, at a name boundary); `REDACTED`; `test-token`; `/media/` (a server file path).
- No string value in a plan other than `serverUrl` and `streamUrl` holds `://`. This holds only while the samples have no subtitle track: a plan with an external subtitle carries `tracks[].deliveryUrl` (eight plans of the frozen file do). A later sample with a subtitle track must change this check on purpose.
- Every `playSessionId` and every `PlaySessionId` in a URL is `play-session-1`; every `DeviceId` in a URL is `octave-fixtures`.
- Every `itemId` and `mediaSourceId` is `item-h264`, `item-hevc` or `item-av1`; every `title` is `Fixture`; every track `displayTitle` holds no `/`.
