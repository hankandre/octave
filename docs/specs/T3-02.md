## Goal

The TV app gives the core its host through the ports: a `Clock` and a `Crypto` adapter in the app, and Expo's own `URL`. A device test runs the core's conformance suite inside the app, under Hermes, on the Android TV emulator in CI: all 202 vectors of the two shared URL files, and a new shared DeviceId vector file that Node and the device must both derive identically. `pnpm tv:e2e` runs it, the `tv` job runs `pnpm tv:e2e`, and the `tv` job becomes a required check.

## Approach

### The host adapters

- `apps/tv/src/host/clock.ts`: `hostClock`, the same twelve lines as the core's `systemClock` (`now` from `Date.now()`, `after` from `setTimeout`, `every` from `setInterval`, each returning its cancel). The core's file says "Apps supply their own", and `host-globals.d.ts` reserves the timer globals for the reference adapters, so the app does not import `systemClock`.
- `apps/tv/src/host/crypto.ts`: `hostCrypto`. `sha256Hex(text)` returns `digestStringAsync(CryptoDigestAlgorithm.SHA256, text, { encoding: CryptoEncoding.HEX })`; `randomId()` returns `randomUUID()`. No `TextEncoder`, no `crypto.subtle`, nothing written to a global.
- `apps/tv/src/host/url.ts`: `urlIsExpoBuiltin()` returns whether both the global `URL` and the global `URLSearchParams` carry `Symbol.for("expo.builtin")` set to `true` (Expo installs them separately, `winter/runtime.native.ts:16-18`; spec check note 5). It is how the device test knows the URL under test is Expo's and not React Native's regex-based one (decision 0003, Finding 3).
- Nothing constructs a gateway yet: there is no Transport until T3-05. The adapters are used today by the e2e root only, and by T3-05 and T4 after it.
- Imports of the core are `@octave/core/src/...` through the workspace dependency. No `exports` map and no barrel file is added (decision log).

### The DeviceId vectors (item 3)

`packages/core/tests/fixtures/device-ids.json`:

```json
{
  "description": "DeviceId = SHA-256 hex of installId:serverId:lowercased username (ARCHITECTURE.md section 3). Every host must derive each value.",
  "vectors": [
    { "name": "ascii mixed case", "installId": "install-1", "serverId": "server-1", "username": "Louise", "deviceId": "07bce1a97d44b7008418adc02ad74694142287bef4bd4007377574dc451aaf78" }
  ]
}
```

The vectors, each with a unique `name`:

1. `Louise` and `ZOË Ångström` with `install-1` and `server-1`: the two values `device-id.test.ts` already pins (`07bce1a9…`, `53ec1803…`).
2. An already-lowercase ASCII name, and the same name in upper case with the same expected value.
3. A UUID install id (the shape `randomId()` gives) with a server id that is a server URL (`http://192.168.1.10:8096`), because the gateway falls back to the server URL (`gateway.ts:270`).
4. The Quick Connect stand-in user `#quick-connect` (`gateway.ts:70`).
5. A username with a colon (`a:b`).
6. Lowercasing that is not one-to-one or is context-sensitive: `İREM` (U+0130 lowercases to `i` and U+0307 in Node), `ΟΔΥΣΣΕΥΣ` (the final sigma becomes `ς` in Node), `STRAẞE` (U+1E9E).
7. Multi-byte text: a CJK username, and one with an emoji outside the Basic Multilingual Plane.

At least ten vectors. No vector holds a lone surrogate: Kotlin's `toByteArray()` and WebCrypto's `TextEncoder` replace it differently, and a server user name cannot hold one. For orientation, Node gives `0ac8f353…f1d3bc` for install id `3f2c8a1e-0b7d-4c55-9a1e-6d2f4b8c7e10`, server `server-1`, user `Alice`.

`runDeviceIdConformance(crypto: Crypto): Promise<DeviceIdConformanceReport>` mirrors the URL suite: it imports the fixture and `deriveDeviceId`, no test runner and no Node module; it never throws; it reports `{ total, passed, failures: { vector: <name>, actual: "different" | "threw" }[] }`. It never reports a derived value or an error message.

**If a vector fails on the device, stop and report.** Do not delete or soften the vector and do not change `deriveDeviceId`: a Hermes that lowercases differently from Node is a product finding (the server would see two devices for one viewer), and the fix is the Product Owner's and the owner's to place.

### The e2e build

One app, two bundles. The e2e bundle is the release bundle plus the modules under `apps/tv/src/e2e/` and what only they import (the core's conformance modules and the three fixture files, about 125 kB of JSON). The release bundle must not contain them.

- `apps/tv/e2e-gate.js` exports `isE2eOnly(filePath, appDir)` (true for a path under `<appDir>/src/e2e/`) and `gateResolution(resolution, { e2e, appDir })`, which returns `{ type: "empty" }` for a `sourceFile` resolution that `isE2eOnly` when `e2e` is false, and the resolution unchanged otherwise.
- `apps/tv/metro.config.js` sets `config.resolver.resolveRequest` to call the default resolution (`context.resolveRequest`) and pass the result through `gateResolution`, with `e2e` being `process.env.OCTAVE_E2E === "1"`.
- `apps/tv/index.js` imports `App` and the default export of `./src/e2e/root`, and registers the e2e root only when it is a function (`typeof E2eRoot === "function" ? E2eRoot : App`). In a release bundle the e2e root resolves to Metro's empty module (`metro-runtime/src/modules/empty-module.js` holds only `"use strict"`, so it exports `{}`, and a default import of it is an empty object, not `undefined`). Do not write `E2eRoot ?? App`: it would register `{}` in the release app. `pnpm tv:smoke` on the release APK is what proves the release root still mounts.
- So nothing under `src/e2e/` can reach a release bundle, whatever imports it, and the release app has no test hook, no launch flag and no deep link. This does not rely on dead-code elimination or on Expo's environment-variable inlining.

`scripts/tv-build.mjs` (`pnpm tv:build`; `--e2e` for `pnpm tv:e2e:build`):

1. Prebuild when `apps/tv/android` is missing or its stamp is stale (`prebuildIsCurrent()`, as `tv-native-test.mjs` does).
2. Run `./gradlew :app:createBundleReleaseJsAndAssets --rerun :app:assembleRelease` in `apps/tv/android`. The environment has `OCTAVE_E2E=1` for `--e2e` and has the variable **removed** otherwise. The bundle task is forced every time because Gradle tracks neither the flag nor `packages/core` (Facts); this also fixes the stale-bundle case after a core-only edit. `--rerun` is Gradle's built-in task option (7.6 and later; the project uses 9.4.1); that it applies to the bundle task alone in this command line is **[unverified]**. If it does not, delete the bundle task's output directory before Gradle runs, and record which was used.
3. Find the bundle (`app/build/generated/assets/react/release/index.android.bundle`; if absent, the single `index.android.bundle` under `app/build/generated/assets/`; zero or several is an error) and apply `judgeBundle(bytes, flavour)`: a release bundle that contains the bytes `OCTAVE_E2E` fails with `ERROR tv build: the release bundle contains the e2e harness`; an e2e bundle without them fails with `ERROR tv build: the e2e bundle lacks the harness (was OCTAVE_E2E seen by Metro?)`. This is the proof both ways, on every build. That Gradle hands the caller's environment to the Metro process it starts is **[unverified]** (a Gradle daemon is involved); this check is what catches it. The hash covers what the e2e bundle is made from, in the style of `prebuildHash()`: every file under `apps/tv` outside `android/`, `ios/`, `dist/`, `.expo/` and `node_modules/`; `packages/core/src/**` without `*.test.ts`; the three fixture files; `pnpm-lock.yaml`. ### The device test (items 1 to 3)

`apps/tv/src/e2e/conformance-run.ts` exports `runConformance(host, log)`, with `host = { clock: Clock, crypto: Crypto, urlSource: "expo-builtin" | "other", engine: "hermes" | "other" }` and `log` a function taking one line. It writes, in order:

```
OCTAVE_E2E start conformance
OCTAVE_E2E host url=expo-builtin engine=hermes
OCTAVE_E2E url total=202 passed=202
OCTAVE_E2E device-id total=<n> passed=<n>
OCTAVE_E2E crypto random-id=ok
OCTAVE_E2E clock now=ok after=ok every=ok
OCTAVE_E2E done
```

- A URL failure adds `OCTAVE_E2E url-fail file=<file> expected=<word> actual=<word> vector=<JSON string of the report's vector>`; a DeviceId failure adds `OCTAVE_E2E device-id-fail actual=<different|threw> vector=<JSON string of the name>`. Both hold fixture text and fixed words only (T2-06's rule for the report). No derived DeviceId, no error message and no stack is ever logged.
- `random-id=ok` when two `randomId()` calls differ and both match the version 4 pattern of `web-crypto.test.ts`; else `bad`.
- Clock: `now=ok` when `now()` is an integer within a minute of `Date.now()`; `after=ok` when `after(50, …)` runs once and a cancelled `after` never runs; `every=ok` when `every(20, …)` runs at least twice and stops after its cancel. Each check has a two-second limit and reports `bad` or `timeout`, never hanging.
- Any throw inside a section writes `<section> threw` in place of that section's line, and `done` is still written.
- `apps/tv/src/e2e/root.tsx` renders an empty `View` and calls `runConformance({ clock: hostClock, crypto: hostCrypto, urlSource: urlIsExpoBuiltin() ? "expo-builtin" : "other", engine: typeof HermesInternal === "object" ? "hermes" : "other" }, console.info)` once on mount (spec check note 2: the acceptance item says "under Hermes", and this is what asserts it). No text, no colour, no design decision.

`scripts/tv-e2e.mjs` (`pnpm tv:e2e`), in the pattern of `tv-first-focus.mjs`:

1. Require `ANDROID_SERIAL`; never pick a device, and never print or write the serial.
2. Use the e2e APK at `apps/tv/dist/e2e/octave-tv-e2e.apk`. **When it is missing or its stamp differs from `e2eSourceHash()`, build it first** (the same function `pnpm tv:e2e:build` runs), so the task's `verify` line (`pnpm check && pnpm tv:e2e`, which eight later tasks share) never passes on an APK built from older sources and never fails on a clean tree. A path given as the first argument is used as it is, with no stamp check. In CI the stamp is current, because `pnpm tv:e2e:build` ran in the step before, so the emulator step does not build.
3. `adb install -r`, force-stop, clear logcat, resolve the leanback activity and start it as `tv-first-focus.mjs` does. The application ID comes from the core's identity file.
4. Poll logcat (`ReactNativeJS:I *:S`) up to 60 s for `OCTAVE_E2E done`. Write the `OCTAVE_E2E` lines to `release-evidence/tv/e2e-conformance.txt`. Force-stop the app.
5. `judgeConformance(lines, expectedCounts())`. `expectedCounts()` reads the three fixture files in Node: `{ url: 202, deviceId: <n> }`. The judge returns `ERROR tv e2e: <reason>` lines and is empty only when: there is exactly one `start` and one `done`; the host line says `url=expo-builtin engine=hermes`; the `url` and `device-id` totals equal the expected counts and `passed` equals `total`; there is no `url-fail`, `device-id-fail` or `threw` line; `random-id=ok`; all three clock parts are `ok`.
6. On failure print the transcript and the errors and exit 1. On success print `tv e2e: url 202/202, device-id <n>/<n>, host ok`.

The script is a runner with one device test today. T3-10 adds its focus test to the same command; how the e2e build then chooses a screen is T3-10's to design.

**If a URL vector fails on the device, stop and report.** Item 1 says "from Expo's implementations": do not add a URL polyfill, do not patch the vector files (frozen by T2-06) and do not loosen the judge. If the host line reads `url=other`, find out which module replaced Expo's URL and report it; do not drop the check.
