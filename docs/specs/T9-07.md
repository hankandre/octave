## Rules (the behaviour to build)

The implementer writes the patterns. These rules and the test table fix the outcome. Where a rule and a table row disagree, report it; do not pick one.

**R1. A status code after a key word (`redact.ts`).** In the whitespace branch of `CREDENTIAL` only, a value that is exactly `(` + three digits + `)` is not a credential when the `)` is followed by the end of the text, whitespace, or one of `. , ; :` that is itself followed by whitespace or the end. The `:` and `=` branches do not change. Nothing else about `CREDENTIAL` or `AUTHORIZATION` changes.

**R2. A single-label host with a port.** A single label (a letter, then letters, digits or `-`) followed by `:` and a port of **two to five** digits is an address, unless the label is one of the label words. The port's last digit is not followed by a letter, a digit, or a `.` and a digit. The label words, compared without case, are a fixed list in `safe-reason.ts`, cut to words with a known player-text form and none that reads as a host name: `status`, `code`, `line`, `pts`, `dts`, `bitrate`, `fps`, `errno`, `aid`, `sid`, `vid`. An unknown word is hidden. This narrows today's hiding for the listed words: any single label with a four- or five-digit port is `[address]` today, so `pts:12345` is hidden now and readable after this task. Dotted hosts, IPv4 addresses, `localhost` and bracketed IPv6 with a port keep today's one-to-five-digit port. R5 runs before R2: the `eth0:8096` of `fe80::1%eth0:8096` is a zone and a port, not a host.

**R3. A bare host or IP address.** Each becomes `[address]`:
- an IPv4 address: four groups of one to three digits, not touching another digit, letter or `.digit` on either side;
- a dotted name of two or more labels whose last label is two or more letters, unless it has three or more labels and its first labels are a code namespace: `java.`, `javax.`, `kotlin.`, `kotlinx.`, `android.`, `androidx.`, `dalvik.`, `com.google.`, `dev.octave.`, `c2.` or `omx.` (compared without case). A two-label name is never exempt, so `android.lan`, `c2.lan` and `omx.local` are hidden (spec check 3: a host name is local information);
- a bare IPv6 address: groups of one to four hex digits that hold a `::`, or exactly eight groups; it starts and ends at a token edge (no letter, digit, `:` or `.` beside it); a bare `::` with no group is not an address;
- a bracketed IPv6 address with no port, only when the text inside the brackets holds a `::`, has exactly eight groups, or carries a zone (R5). `[00:01:02] decode error` is a timestamp and stays.

A single label with no port (`connect to nas failed`) cannot be told from a word and stays out of scope.

**R4. What a host carries with it.** Any host form (R2, R3, today's forms) also takes a path glued to it: `/` and everything up to the next whitespace or `"` `'` `)` `,` `;`. `media.local:8096/web/index.html` becomes `[address]`, not `[address]/web/index.html`.

**R5. IPv6 with a zone id.** An IPv6 address followed by `%` and a zone (letters, digits, `.`, `_`, `~`, `-`; `%25` also opens a zone) is an address, bracketed or bare, with or without a `:port` after it. The whole of it, zone and port included, becomes one `[address]`. Every bracket rule requires hex digits and at least one `:` before any `%`, so none matches `[address]`, `[redacted]` or `[path]`.

**R6. Scheme-less user info.** `user:pass@host` becomes one `[address]`, whatever the host looks like and with or without a port or a glued path. The user info runs to the **last** `@` before whitespace, so `user:p@ss@host` is one address. `user@host` with no password becomes `[address]` only when the host is a form R2, R3 or R5 already hides, so `1920x1080@60` stays readable.

**R7. A path after a colon.** A `/` directly after a `:` starts a POSIX path when the next character is not `/`. `scheme://` text is still the address rule's.

**R8. A path that holds a space.** After a path starts (POSIX, `~/`, Windows drive, UNC), it runs on over following words separated by single spaces or tabs, up to and including the **last** word that either holds a `/` or `\`, or ends in `.` + a letter + up to four letters or digits (a file extension), with at most one `:` or `.` after the extension (`Night.mkv:` and a sentence's last `Movie.mkv.` both count, and that last character is part of the path, as it is for a path with no space today). The run stops at a newline, at `"` `'` `)` `,` `;`, and at a fixed bound the implementer sets (no more than 260 characters past the path's start). Words after that last word stay. A path whose last segment holds a space and has no extension (`/home/u/My Movies`) still shows its last word; see Risks.

**Order.** Path rules run before the bare dotted-name rule of R3, or `Movie.mkv` inside a spaced path would become `[address]` first. R6 runs before the host rules, or the host is replaced and the user and password stay. R5 runs before R2 and the other host rules, or the `eth0:8096` of `fe80::1%eth0:8096` is hidden as a host and the address stays.

**Idempotence.** No rule may match `[address]`, `[path]` or `[redacted]`, or text next to them. Every rewrite row is checked with a second pass.

**Linear time.** Each new pattern starts only at a token start and scans a bounded distance, so 1 MB of any adversarial input stays inside today's bounds.

## Decision log

- **The label list, and unknown words fail closed.** No lexical rule separates `nas:8096` (must be hidden, `safe-reason.test.ts:8`) from `pts:12345` (must stay). A fixed list of measurement words stays readable and every other word is hidden, because showing a host is the worse error. The list is cut to the words the tests need (`pts`, `bitrate`, `status`, `code`, `line`) plus words with a known player-text form; host-like words (`stream`, `time`, `track`) are not on it. This narrows today's hiding for a listed word: today any single label with a four- or five-digit port is hidden, so a host named like a label word (`pts:8096`) is shown after this task. The backlog line and the `docs/security.md` row say so.
- **Short ports need two digits.** A one-digit port is not used in practice, and one digit after a colon is common in player text (`aid:1`, `Stream #0:1`).
- **A dotted name is hidden unless it is a code namespace.** A host name and a file or class name cannot be told apart. Hiding wins; the namespace list keeps Android decoder and exception names readable, which is what a player failure is read for. A name with two labels is never exempt (`android.lan` is a host). A file name outside a path (`libmpv.so`) is hidden as `[address]`.
- **Bare IPv6 covers `::` and the eight-group form only.** Item 1 says "IP address"; these two forms cannot collide with `12:30`, `16:9` or `01:02:03`.
- **The spaced-path rule ends at the last word with a separator or an extension.** Running to the end of the line would break the four existing ` now` rows.
- **R1 holds for every key word, not only `token`.** A password or token written as three digits in brackets after a space is not a real case, and `Wrong password (401)` is as useful to read as `Invalid token (401)`.
- **R4 is in scope.** Without it R3 would turn a bare `host/path` into `[address]/path` and show the path.
- **No new canary case.** The canary file is frozen; the item 2 rows assert on the user and password instead.
