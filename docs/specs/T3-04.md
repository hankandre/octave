## Goal

A mistake that opens a network path around the one authenticated client fails a check before it merges. Three fences do it:

1. `pnpm lint:network` (new, in `pnpm check` and CI's `checks` job) reads Octave's Kotlin and Java source and fails on Media3's default data sources, another `OkHttpClient`, `HttpURLConnection`, an ExoPlayer or media source factory without a stated factory, and any use of React Native's or Expo's client hooks. It also compares the HTTP clients inside the linked libraries with a named allowlist.
2. `pnpm lint` (ESLint, already in `pnpm check` and CI) fails TypeScript and JavaScript in `apps/tv` that calls `fetch`, `XMLHttpRequest` or `WebSocket`, passes a header or token to anything, gives React Native's `Image` a network source, or imports an Expo HTTP path.
3. A JVM test in `pnpm tv:native:test` reads the compiled classes of Octave's own code and fails on the same references by resolved type, which a text scan cannot see.

Every message names the allowed alternative.

## Approach

### Shape

`scripts/check-network-paths.mjs` exports pure functions and data, and runs them as a command, in the style of `scripts/check-ghost-terms.mjs`:

- `KOTLIN_RULES`: the rule table below, each `{ id, alternative, names }`, where `names` is `{ re, what }[]`, the patterns that fail the rule wherever they stand. The ids are exactly K1 to K10 (the frozen item 4 test compares them with its sample table, so no rule id can be added after the freeze; a new name goes into an existing rule).
- `NETWORK_OPENERS`: the one name list of forms that open a connection or name a network stack (`{ rule, re, what }[]`). K1, K2, K4, K5, K7 and K9 take their opening forms from it, and the inventory matches exactly it (spec check issue 4). The K rules add, on top, names that open nothing by themselves: a bare `OkHttpClient` type outside `OctaveHttp.kt`, a `.client` read, a `WebView` type, the K7 hook classes and packages, K8 and K10.
- `findSourceViolations(files)`, where `files` is `{ path, text }[]`: returns `ERROR network: <path>:<line>: <what>. <alternative>` lines, with `<path>` as given. A path under `apps/tv/plugins/` is read as plain JavaScript text.
- `LINKED_NETWORK_PATHS`: the allowlist, `{ id, package, file, what, verdict, reason, refusedBy }[]`. `package` is the name the app depends on (`react-native`, not the fork's name); `file` is relative to the package folder, forward slashes, no line number. A path with several library files has one entry per file, all with its id.
- `findLinkedClients(packages)`, where `packages` is `{ name, dir }[]`: returns `{ package, file }[]`, each `.kt` and `.java` file under the package's `android/src/main` or `ReactAndroid/src/main` (never `build/`) that matches `NETWORK_OPENERS` in code (comments removed, strings set aside; a dotted full name inside a string counts).
- `judgeLinkedClients(found, allowlist)`: returns the two `ERROR network:` messages under "The inventory".
- `main()`: takes `--root <dir>` (default: the repository) and reads the trees relative to it; an `ERROR` line names the file relative to that root, with forward slashes. It prints one summary line to stdout (`network: N Octave files, M linked files, V violations`), prints each `ERROR` line to stderr, and exits 1 on any. It also exits 1, with an `ERROR network:` line counted in `V`, when it read no Octave Kotlin or Java file, did not read `OctaveHttp.kt`, or found no linked package: a run with nothing to read never passes, and never prints `0 violations`. The item 5 tests run it on temporary trees with `--root` and assert the `ERROR network: <path>:<line>:` line, not only the exit code; a temporary tree fails for several of these reasons at once, which is fine because every error is collected before the exit.
- The T rules' ids and alternative texts are not exported: `eslint.config.js` keeps them in its own constants, and the frozen `scripts/network-lint.test.ts` holds the texts from this spec and matches ESLint's output against them.

The command reads:

- Octave's Kotlin and Java: every `.kt` and `.java` under `modules/*/android/src/` and `apps/tv/native/` whose path holds no `/src/test/` and no `/build/`.
- `apps/tv/plugins/**/*.js` as plain text, because a config plugin can write Kotlin into the generated project. Only the distinctive type names are matched there (`OkHttpClient`, `HttpURLConnection`, `URLConnection`, `DefaultHttpDataSource`, `DefaultDataSource`, `DefaultMediaSourceFactory`, `ExoPlayer.Builder`, and the K7 and K8 names). The patterns that are ordinary JavaScript (`URL(`, `.client`, `Socket(`, `WebView`) are not.

### Kotlin and Java rules

The scan tokenizes first: it removes block and line comments and sets string and character literals aside, so a `//` inside `"http://…"` is not a comment. It matches a forbidden name as an identifier outside string literals (`$` and `_` count as identifier characters, so `CREDENTIAL_URL(` is not `URL(` and `hasWebView(` is not `WebView`) and as a dotted or slashed full name inside them, so `Class.forName("okhttp3.OkHttpClient")` is caught and an error message that says "client" is not. K10 alone matches inside a string as a plain word (`@Suppress("INVISIBLE_MEMBER")`). An import alias or a `typealias` cannot hide a name, because the name has to be written once in Octave's source and that line fails. The same tokenizer and the same identifier boundary serve the inventory.

**The inventory.** `pnpm lint:network` also walks the app's installed dependencies: from `apps/tv/package.json`'s `dependencies`, following each package's `dependencies` and installed `peerDependencies`, each found as Node finds it from the requiring package's real folder (`<ancestor>/node_modules/<name>`, which is how pnpm lays out a package's own dependencies), deduplicated by real path, with the name the app depends on kept (`react-native`, not `react-native-tvos`). A regular dependency that is not installed is an error, never skipped; a peer that is not installed is skipped. It skips workspace packages (a real path outside `node_modules`: `@octave/session` and later `modules/*`), because the K rules read those; without the skip it would list `OctaveHttp.kt`. In each package with an `android/` or `ReactAndroid/` folder it reads the `.kt` and `.java` files of every source set under `src/` that ships (`main`, and also `debug`, `fabric`, `paper`, `compose`, `jsi` and the like; not `test*` or `androidTest*`), never `build/`, and lists every file that matches `NETWORK_OPENERS`, the same list the K rules use (spec check issue 4): `OkHttpClient(`, `OkHttpClient.Builder(`, `OkHttpClientProvider`, `java.net.http`, `HttpClient`, `Cronet…`, `Volley…`, `DownloadManager`, `Socket(`, `SSLSocket(`, `SocketChannel`, `DatagramSocket`, `AsynchronousSocketChannel`, `HttpURLConnection`, `HttpsURLConnection`, `URLConnection`, `URL(`, `.toURL(`, `openConnection(`, `openStream(`, `WebView(`, and Media3's K1 and K2 names. The match uses the K rules' tokenizer and identifier boundary, so `hasWebView(` and a comment are not listed. A type mention alone (`CustomClientBuilder.kt`'s `builder: OkHttpClient.Builder` parameter) opens nothing and is not listed. It fails when:

- a listed file is not on the allowlist: `ERROR network: <package>/<file> opens its own HTTP path and is not on LINKED_NETWORK_PATHS. Add an entry with its reason, and a rule that refuses it in Octave's code, or remove the dependency.`
- an allowlist entry's file no longer matches: `ERROR network: LINKED_NETWORK_PATHS entry <id> names <file>, which no longer opens an HTTP path. Remove or correct the entry.`

### Source, not dex

The `OkHttpClient` rule reads Octave's source (`pnpm lint:network`) and Octave's compiled classes (the JVM test). It does not read the built dex:

- The `checks` job has no Android SDK, and item 5 puts the check in `pnpm check`.
- A release dex is renamed by R8, so a name scan needs the mapping file from a release build, which only the `tv` job has, after a build of several minutes.
- The linked libraries are read as source instead (the inventory). Libraries that ship only as binaries (OkHttp itself, Fresco's `imagepipeline-okhttp3`) are not read; they are reached only through the files the inventory lists.

### The JVM test (by type)

`NetworkPathsBytecodeTest` runs in `:app`'s unit tests. It needs no new dependency: `ClassReferences.kt` reads a class file's constant pool with `DataInputStream` and returns its class references and its member references as `(owner, name, descriptor)`, plus every UTF-8 constant.

- **What it reads.** Every class file under `dev/octave/` on the test runtime classpath, except the test package `dev/octave/buildcheck/`. That covers `modules/session`, every later module, and the generated `MainActivity` and `MainApplication`, which a config plugin can change. The test first asserts that it read `dev/octave/session/http/OctaveHttp.class` and `dev/octave/tv/MainApplication.class`, so a classpath that hides the classes fails instead of passing. How the classpath is listed (`java.class.path`, or the code source of a known class) is the implementer's to verify; that Gradle's test worker exposes it in `java.class.path` is unverified.
- **Rules** (`NetworkPathRules.kt`, a pure function from one class's references to violations):

## Risks and out of scope

- **A text scan is not a type check.** K3, K4 and K6 can be passed by code that hides a type behind inference in a file the rule does not name. The JVM test closes that for compiled Octave code, but it runs in `pnpm tv:native:test`, not in `pnpm check`. Both run in CI on every pull request.
- **The Media3 descriptor rules have no compiled sample** until Media3 is a dependency. They are tested on hand-written reference lists taken from the 1.11.1 jar. Backlog line for T8-02: add compiled samples, and re-read the constructors at the version it adopts.
- **K3 and K6 work per file** (source) and per class (bytecode), not per call. A file with two builders and one setter passes. Accepted: T8-02 has one builder, and the wire test is the end proof.
- **The generated `MainApplication` references no K7 class today** (Facts). A later Expo template might. If the JVM test then finds one, do not weaken the rule: report it, and allowlist that one generated class by name with its reason only after the `guardian` agrees.
- **T2 is syntactic** (spec check issue 11). It reads object keys, class fields, destructured names and JSX attributes. A TypeScript member (`interface Props { token: string }`), a member read (`props.token`) and a computed key pass.
