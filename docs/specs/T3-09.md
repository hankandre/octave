## Goal

One `AppShell` holds every screen of the TV app. It gives the browse screens the collapsed side rail of `DESIGN.md` §7.1 with decision 0004's measured focus fixes, owns Back for the whole app, and builds and parses every route in one module:

1. The rail is a column of entries inside the left safe inset: Search, Home, one per library in the server's order, Settings and the account. It opens over the content when focus enters it with Left from a screen's first column, and closes when focus leaves.
2. Left, Up past the top and Down past the bottom never leave the rail. Right, or select on the current entry, returns focus to the content element that had it, even after the rows' router pointed the rows' guides elsewhere.
3. Opening a screen focuses its primary action. Back returns to the previous screen with the same card focused, by `DESIGN.md` §9's rule for a card that is gone.
4. Back follows `DESIGN.md` §6 and §9 (Product Owner ruling): on a root screen it opens the rail on that screen's entry; with the rail open, Back on Home leaves the app without a question and Back on another root screen goes Home.
5. The player and sign-in have no rail.
6. `routes.ts` is the only place a route is built or parsed. An unknown route shows the not-found state with the owner's copy.

Real screens arrive with their own tasks (T4-02 sign-in, T5-03 Home, T6-01 the libraries in the rail, T8 the player, T9 Settings). Until then each route shows the existing placeholder screen, so the release APK's first-focus smoke test (`pnpm tv:smoke`, T3-01 item 4) still passes unchanged.

## Approach

### Routes (`routes.ts`)

One module owns the strings. `parsePath` splits on `/`, accepts only the nine shapes above, and refuses a query, a fragment, an empty or doubled segment, a percent sign, and an id outside `[A-Za-z0-9_-]{1,128}`; everything refused is `notFound`. `buildPath` throws on an id that `parsePath` would refuse, so a bad id is a programming error, not a silent not-found. The stack's screen names are the route kinds, so `toScreen` and `fromScreen` are one-line maps; `fromScreen` gives `notFound` for an unknown name or a missing id. A route holds ids only: never a URL, a session id, a play-session id or a token (hard rules, Tokens and network).

### The shell (`AppShell`)

- **`ShellBack`** wraps `NavigationContainer` and registers the one Back listener in a `useEffect` with an empty dependency list, so it registers once per mount and removes it on unmount. The listener reads the rail's open state, the top route and the depth from refs that the shell updates on every render and navigation state change, then calls `decideBack` and acts. Because `ShellBack` is the container's parent, its listener is registered after React Navigation's and runs first; it always returns `true`, so React Navigation's listener never runs.
- The navigation state is the container's (`createNavigationContainerRef`). `open(route)` dispatches `CommonActions.reset` to `[route]` for a root and `StackActions.push` otherwise. `go-home` resets to `[home]`.
- The layout: a full-screen `View` (`surface0`). When the top route's chrome is `"rail"`, `SideRail` is absolutely placed at the left (`zIndex` above the content), the content area (`shell-content`) starts at `px(sizes.railCollapsedW)`, the edge guide `shell-edge` is a 1 px-wide full-height `TVFocusGuideView` at the content's left edge, and the `LeftEdgeContext` gives `"open"`. With chrome `"none"`, there is no rail, no edge guide, no offset and no context.
- The edge guide is pointed with `pointGuide(edgeGuideRef.current, [currentEntryView])` in an effect that runs once the current entry has registered its view and whenever the current entry changes. It is not given a `destinations` prop, so there is one path a test can see.

### The rail (`SideRail`)

- `rail` is a `View` with `role="navigation"` and `accessibilityLabel` "Main", holding `rail-guide`, a `TVFocusGuideView` with `trapFocusLeft`, `trapFocusUp` and `trapFocusDown` (spike defect 2).
- Layout: `safeY` from the top. Search, then a `ScrollView` holding Home and the libraries, then Settings and the account pinned at the bottom (`DESIGN.md` §7.1: "Many libraries scroll within the rail; Search, Settings, and the account stay in place").
- Each entry is a `FocusFrame` (the shared ring and lift, `radiusControl`) around a `Pressable` that carries the entry's testID and ref, `sizes.hitMin` tall. It shows the icon from the slot at `space.space6` in `text2` (`text1` when focused or current). The account shows its initial in `typeLabel` instead. The current entry has a `space.space1`-wide `text1` bar at its left. Open, the label shows beside the icon in `typeLabel`, one line.
- Open and close: the rail holds `open` state. An entry's `onFocus` sets it true and calls `onOpenChange(true)`. Its `onBlur` schedules a zero-delay check, which another entry's `onFocus` cancels. This is the same collapse as `useFocusEnterLeave`, driven by props that Jest can fire. The width animates between `railCollapsedW` and `railOpenW` over `durQuick` with `easeOut` (`Animated.timing`, as `FocusFrame` does), and jumps under reduced motion. Open, the background is `surface1`.
- `nextFocusRight` on every entry is `returnTag` while the rail is open, and `undefined` while it is closed (spike).
- Select: on the current entry, close and `focusView(lastContentView)`; on another entry, `open(entry.route)`. The new screen's primary action takes focus through its `hasTVPreferredFocus`, and the rail closes when its entry blurs.
- Focus callbacks pass the entry key only, never a library name, to anything outside the rail.

### Focus place, return and restore

- `FocusPlace` is a `Map` from the stack route key to `{ key, view, card?, opening?, rows? }`, held in a ref by `AppShell` (shell state, not module state, so two shells in a test never share it).
- **The route key comes from the shell, not from React Navigation's hooks.** The shell's per-screen wrapper (the component each stack screen renders) receives `route.key` in its screen props and renders `<FocusPlaceContext.Provider value={reporterFor(route.key)}>` around the screen. `useFocusPlace()` is `useContext(FocusPlaceContext)`; its default is a no-op reporter. It never calls `useRoute()`, which throws outside a navigator (Facts), so T3-08's frozen `RowList` tests, which render with no navigator and no shell, run unchanged. `reporterFor` is memoized per key so the provider value is stable.
- `RowList` calls `focused("card:<rowId>:<itemId>", router.viewOf(rowId, itemId), { rowId, itemId, index })` from its card focus handler, and `rows(handle)` on mount (`rows(null)` on unmount). A screen's other controls call `focused(<their id>, view)`. The screen calls `opening(view)` for its primary action.
- `returnTag` is `tagOf(place.view)` for the top route, computed when the rail opens, from the latest `focused` report (so after A-card-3 then B-card-5 it is B-card-5's; item 8).
- On a pop, the screen that becomes top runs a `useFocusEffect` from the shell's screen wrapper. If it was left by a push (not a fresh mount), the shell runs `restoreTarget(saved.card, handle.rows())` and calls `focusView` on `handle.viewOf(...)` for the target card, on the saved view for a non-card control, or on the opening view. A fresh mount does nothing: the primary action's `hasTVPreferredFocus` does it.
- When any rail entry takes focus, the shell calls `handle.clear()` on the rows handle registered for the top route (backlog line 290, item 8), so a later Right that falls back to the native search is not sent to a stale card.

### Back (`back.ts`)

`decideBack` is the table in item 5. The shell maps: `open-rail` → `focusView(currentEntryView)`; `close-rail` → `focusView(place.view)` or the opening view; `pop` → `StackActions.pop()`; `go-home` → reset to `[home]`; `exit` → `BackHandler.exitApp()`, called directly inside the listener with nothing shown first. A dialog's Back is its `Modal`'s `onRequestClose` (T3-06), which Android delivers before `BackHandler`, so the topmost-layer order of `DESIGN.md` §9 holds.

### Not found

`NotFoundScreen` is the T3-06 `Notice` with no item title, the owner's settled copy ("This page isn't available" / "It may have moved, or this account can't see it."), and one primary action, "Go home", with `hasTVPreferredFocus`. It shows the rail with Home as the current entry. Back on it follows item 5 (`go-home` at depth 1). `DESIGN.md` §10 gains the row in the same PR.
