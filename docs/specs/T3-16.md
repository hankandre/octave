## Approach

### The path rule (item 7)

`RequestPath.isSafe(path: String): Boolean`, pure, called first in `SessionTransport.request`. A path is refused (`{ error: "refused" }`, nothing built, nothing sent) unless all hold:

- P1. It starts with `/` and not with `//`, and holds no `?` or `#` (today's rule, moved here).
- P2. It holds no backslash. OkHttp reads `\` as a separator.
- P3. It holds no character below U+0020 and no U+007F.
- P4. No segment is `.` or `..`, as written or after percent-decoding. The path is split on `/`; then, up to four times (`RequestPolicy`'s `DECODING_ROUNDS`), it is percent-decoded once more and split on `/` and `\`. A segment equal to `.` or `..` in any round refuses the path. So `%2e%2e`, `%2E.`, `%252e%252e` and `..%2f..%2fx` are refused. Whole segments only: `/Items/a..b`, `/Items/.hidden`, `/Items/...` and `/Items/a%2Fb` pass.
- P5. Every `%` begins two hex digits, and the escapes of the path as written decode to UTF-8 (no overlong form, no encoded surrogate, nothing above U+10FFFF), as `decodeURIComponent` requires. Spec-check note 5: a malformed escape is sent unchanged by OkHttp 5.5.1 and makes `decodeURIComponent` throw, so without P5 the two sides and a server could read it three ways. P5 applies to the path as written only; the later rounds of P4 decode leniently (a `%` that does not begin an escape stays, bytes that are not UTF-8 become U+FFFD), so `/Items/100%25` is accepted on both sides. Kotlin checks P5 with a reporting `CharsetDecoder`, TypeScript with `decodeURIComponent`.

Containment, which holds whatever P1 to P4 miss:

- C1. In `ServerAddress.url`: the built URL's `encodedPath` must equal `basePath + path` exactly, or the call is refused. OkHttp may rewrite nothing. The gateway's paths are fixed ASCII text plus `encodeURIComponent(id)` (`gateway.ts`), which OkHttp's path encoding leaves alone (unverified for every character; `RequestPathTest`'s accepted vectors include `!'()*` and a percent-encoded non-ASCII id).
  `ServerAddress.url` throws `IllegalArgumentException` on a mismatch, which `buildRequest` already turns into `refused`.
- C2. In `RequestPolicy`, for a `Session` and a `Closing` authority: the URL's `encodedPath` must equal the entry's base path or start with it followed by `/`, else `HttpRefusal.OUTSIDE_BASE_PATH`. It runs after the origin check (for a `Closing` authority after its route check, which implies it). An empty base path accepts every path, so T3-03's frozen tests are unaffected. This holds every caller of `OctaveHttp.callFactory(session)`, the player and the image loader to come, to the base path. `TransportCodes` maps it to `refused` with no change.

The vectors live in `packages/core/tests/fixtures/request-paths.json` as `{ "refused": [{ "name", "path" }], "accepted": [{ "name", "path" }] }`. Refused, at least: `/Items/../x`, `/Items/./x`, `/..`, `/.`, `/Items/..`, `/Items/.`, `/../other`, `/Items/%2e%2e/x`, `/Items/%2E%2E/x`, `/Items/%2e/x`, `/Items/%2E/x`, `/Items/.%2e/x`, `/Items/%2e./x`, `/Items/.%2E/x`, `/Items/%2E./x`, `/Items/%252e%252e/x`, `/Items/..%2f..%2fx`, `/Items/..%2Fx`, `/Items/..%5cx`, `/Items\..\..\x`, and `/Items/.<tab>./x`, `/Items/.<LF>./x`. Accepted: `/Items`, `/Items/a..b`, `/Items/.hidden`, `/Items/...`, `/Items/a.b/c`, `/Items/a%2Fb`, `/Items/!'()*`, `/Items/%C3%BC`. Spec-check note 5 adds, each with its `why` in the file: refused `/Items/%`, `/Items/%2`, `/Items/%zz` (malformed escapes, P5) and `/Items/%c0%ae%c0%ae/x` (the overlong form of `..`, P5); accepted `/Items/a%2eb` (an escaped dot inside a segment) and `/Items/a~b` (`~` is unreserved). Beyond the shared file, `RequestPathRuleTest.kt` and `request-path.test.ts` hold the same further decisions: refused `/Items/%ed%a0%80`, `/Items/%f4%90%80%80`, `/Items/%80`, a raw U+007F, and four rounds of encoding around `..`; accepted `/Items/100%25`, `/Items/%e2%82%ac`, `/Items//x`, `/Items/`.

`RequestPathTest` (parameterised from the file through `octave.repoRoot`, as `MediaBrowserHeaderTest` reads its fixture) sends each refused path through `TransportTestSupport.sessionRequest` on a session with base path `/jf` and on one with none: the result is `{ error: "refused" }` and `PathServer` recorded no request after the sign-in. Each accepted path reaches the server as `/jf` + the path, byte for byte. Two more cases: a call through `OctaveHttp.callFactory(session)` to a URL outside `/jf` is refused with `OUTSIDE_BASE_PATH` and sends nothing; a `/jf2/x` URL is refused for a `/jf` session (the prefix needs the `/`).

The reference transport applies P1 to P5 through `isSafeRequestPath` in `packages/core/src/adapters/request-path.ts`, and `request-path.test.ts` runs the same fixture, so the two implementations agree on every shared vector. They do not agree on everything (spec-check note 6): the reference transport has no C1, so a path with a raw space or a raw non-ASCII character, which Kotlin refuses by C1, is encoded and sent by `fetch`. The comment on `path` in `packages/core/src/ports/transport.ts` says so.

### The answer caps (item 8)

| Class | Calls | Cap |
|---|---|---|
| Tokenless | The four pre-sign-in routes and the two sign-in posts | 1 MiB (1 048 576 bytes) |
| Session write | A session's `POST` and `DELETE` (PlaybackInfo, playstate reports, user configuration, `ActiveEncodings`) | 4 MiB |
| Session read | A session's `GET` | 8 MiB |
| Logout | `POST /Sessions/Logout` | The body is not read (today's `readBody = false`) |

- Each is below 32 MiB and at least 40 times the largest recorded answer of its class (Facts). The class is decided from the authority and the method alone, so Kotlin holds no copy of the gateway's route list.
- `send` takes the cap. When the answer declares a `Content-Length` above it, the call is refused without reading the body. Otherwise at most cap + 1 bytes are requested, as today. Either way `UnusableAnswer` is thrown before `parse`, and the result is `{ error: "unexpected-response" }`, one of the core's seven codes, with no status. A 4xx or 5xx answer has the same cap.
- `ResponseCapTest` hard-codes the byte counts from this table (it names no constant, so it compiles on main). Per class it sends valid JSON of cap + 1 bytes with status 200, once with a declared length and once chunked, and expects `unexpected-response`; and a body of exactly the cap, which crosses. For sign-in the oversized answer is a valid sign-in answer with a padded field; the result is the error alone, with no `session` key.
- The caps are not mirrored in the reference transport: it runs in Node against fixtures.

### The log check (item 4)

`scripts/check-session-logs.mjs` exports `findLogViolations(files)` and a `main` that reads the tree; `pnpm lint:logs` runs it.

- Scope: Kotlin and Java under `modules/session/android/src/main/`, TypeScript under `modules/session/src/` and `apps/tv/src/host/`, and `modules/session/android/build.gradle`. It fails when it reads no file, as `pnpm lint:network` does.
- G1. The identifier `HttpLoggingInterceptor` in any scoped source, or the artifact `logging-interceptor` in the Gradle file.
- G2. A log call with an argument that is not constant text.
