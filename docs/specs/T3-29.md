# T3-29: Narrow the dex check's socket exemption to client sockets and close its D0 gaps

Task: `pnpm task show T3-29`. Domain: Security & Redaction. Depends on T3-19 (done, PR #267). Source: the T3-19 review's lows (`docs/plans/active/008-t3-19-review-followups.md`, "Follow-ups") and backlog lines 206 and 212 to 218, taken by the Product Owner pass in `tasks/product-owner-log.md:251-256`.

Implementers: `implementer` for the scripts, their tests and the documents (milestones 1 to 4 and 6); `native-engineer` for the Kotlin in `apps/tv/native/app/src/test/` (milestone 5 and the Kotlin half of milestone 4). No file under `modules/` or `apps/tv/android/` changes, and the PlayerEngine port is not touched.

This is not a playback task: it has no Jellyscale wire test.

## Goal

The release APK's dex check (`scripts/tv-apk-dex.mjs`, T3-19) stops accepting four things it accepts today, and its twin before R8 (`NetworkPathRules.kt`, T3-04) gets the same fence:

1. A listening or datagram socket in the one client's socket factory. Today `ONE_CLIENT_CLASSES.S4` exempts the whole S4 kind.
2. A dex whose R8 marker carries no `pg-map-id`, judged against any mapping; and a cut-short APK, which today ends in a stack trace or in a message that does not say to rebuild.
3. Octave Kotlin that names a socket, socket factory, channel, channel provider, `MediaExtractor` or `MediaMetadataRetriever`, which no rule by type refuses before R8.
4. An Octave module whose code sits outside `dev.octave.`, which both checks would judge as a library.

It also splits the judge to about 400 lines, rewrites commit citations that name commits not on `main`, and states the rules as built in `docs/security.md`.

### D1: the exemption by method (item 1)

Lists. The S4 row gains:

```js
// What a one-client class (ONE_CLIENT_CLASSES.S4) may do of this kind: make a client socket. Everything else in
// `methods`, a listening or datagram socket above all, fails D1 there too (T3-29).
oneClientMethods: [
  { classes: ["java.net.Socket"], names: ["<init>"] },
  { classes: ["javax.net.SocketFactory"], names: ["createSocket"] },
],
```

It is an allow-list of class and method pairs on the sink row, not a key of `lists` and not a second sink id: the frozen fixture lists carry the production sink rows and no new key, the id `S4` stays for D2 rows and the existing tests, and a method added to S4 later is not exempt until someone lists it.

Judge. D1 as built:

- A sink reference with a `dev.octave.` frame fails unless its innermost remaining frame is on `ONE_CLIENT_CLASSES` for the sink's id (unchanged), **and**, when the reference matched the sink through `methods`, every original class and method that matched is on the sink's `oneClientMethods`. A sink row with no `oneClientMethods` exempts no method match. A match through `anyReference`, `anyReferencePrefix`, `factoryInvokes` or a declaration (S1 only, among the one-client kinds) is exempt as before.
- "Every" matters where R8 gives several candidate originals for one dex method: one candidate off the list fails.
- Both ways into `judgeSink` carry the matched pairs: the direct match in `judgeInstruction` and the superclass walk over `pending`. `methodSinks` returns the matched holders with each sink.
- The per-site `found` set must not let an exempt match hide a later one: a walk step that matches a pair off the list is judged even when the sink id was already found at that site.
- `SSLSocket.<init>`, `SSLSocketFactory.createSocket` and `SocketChannel.open` are not on the list. `DirectSocketFactory` uses none; they fail D1 there until a task lists them with a reason.
- Message, one per holder, sink and member: `D1 <holder> holds S4 (<what>) at <where>, outside the one client: <class>.<method> is not client-socket creation, and <holder> may only construct java.net.Socket and call SocketFactory.createSocket; <SEND_THROUGH>`. It starts as today's D1 line does, so the framework-sinks tests keep matching. The report key includes the member, so two different opens in one class give two lines.

This narrows T3-19's D1 and is flagged for the owner's veto in the Product Owner log (`tasks/product-owner-log.md:251`); the PR calls it out.

### D8: Octave's modules sit in `dev.octave.` (item 4)

**Choice: the guard.** Finding Octave's code from the modules would have to change the judge's every use of the prefix, D7's rule and the R8 keep rule in `apps/tv/app.config.ts` (a module in another package is not covered by `-keep … dev.octave.**`, so R8 would merge its classes and D7's premise would fall). The guard keeps one definition of "Octave's code" and makes the case it cannot see impossible to ship. The Product Owner log allows either (`tasks/product-owner-log.md:254`, point 4).

- `scripts/octave-module-packages.mjs` exports `readOctavePackages(root)` and `foreignPackages(root)`, and runs as `node scripts/octave-module-packages.mjs [--root <dir>]`. It reads, through `readOctaveSource(root)` from `scripts/check-network-paths.mjs`, every Kotlin and Java file of `modules/*/android/src` and `apps/tv/native` outside `src/test` (it drops the `apps/tv/plugins/*.js` files that function also returns, which have no package), and the `namespace` of each `modules/*/android/build.gradle` or `build.gradle.kts`. A file's package is its first `package` declaration; a file with none is in the default package. A package is Octave's when it is `dev.octave` or starts with `dev.octave.`. It fails closed: no module source read is an error.
- Output: `octave packages: <n> files and <m> namespaces, all under dev.octave` and exit 0, or one `ERROR octave packages: <path> declares package <name>, outside dev.octave.; …` line per file or namespace and exit 1.
- The dex check: `main` calls `foreignPackages(system.repoRoot ?? <this repository>)` after the missing-file rule and before it reads the APK, and fails with `ERROR tv apk dex: D8 <path> declares package <name>, outside dev.octave.; the check finds Octave's code by that prefix and would judge this module as a library (a row, D2) instead of failing it (D1); move it under dev.octave.`. `system.repoRoot` is optional, so the frozen harness, which does not pass it, runs the guard on the real repository, where it passes; that read is made once per process (spec check issue 8). Rule D8 is not the D8 dexer whose `~~D8` marker `MARKER` reads: the header comment and `docs/security.md` say so once, and no other ERROR line holds the word, since the frozen item 4 cases pick rule D8's line by `\bD8\b` (spec check issue 7; the name stays, the frozen tests pin it).
