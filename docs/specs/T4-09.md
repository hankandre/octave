## Goal

`JellyfinGateway` derives `DeviceId = SHA-256(installId:serverId:username)` and makes up a random install id when its caller passes none (`packages/core/src/jellyfin/gateway.ts:208`). Nothing in the TV app stores an install id, so every gateway the app would build gets a new one, and the server would see a new device on every launch (`ARCHITECTURE.md:100`: "Never generate a new one per launch").

After this task:

1. The app makes one install id, from the Crypto port, the first time a gateway is needed, and keeps it in one small file in the app's no-backup directory. The file holds a version 4 UUID and nothing else.
2. One factory in `apps/tv/src/host/` is the only place under `apps/tv` that constructs a `JellyfinGateway`, and it always passes the stored id. A lint rule and a scan fail any other construction.
3. A relaunch keeps the id; clearing the app's data gives a new one; a backup and restore on the emulator does not bring the old one back.

## Approach

### The native module

One module, one function. The module is not a key-value store.

```kotlin
// store/InstallIdStore.kt: the interface a Swift implementation mirrors
interface InstallIdKeeper {
    // The stored id; or, when none is stored, the candidate after storing it; or null when the candidate is refused
    // or the store cannot be read or written.
    fun keep(candidate: String): String?
}

class InstallIdStore(private val directory: File) : InstallIdKeeper
```

- A valid id matches `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$` (the pattern the device test already holds `randomId()` to).
- `keep` refuses a candidate that is not valid: it returns `null` and writes nothing. This is what keeps a token, a URL or any other text out of the file.
- The file is `octave-install-id` in `directory`. `keep` reads at most 64 bytes; when the content is exactly one valid id it returns it and ignores the candidate. Anything else (missing, empty, longer, not valid) is replaced: the candidate is written to `octave-install-id.tmp` in the same directory, synced, and renamed over the file with `File.renameTo`; then the candidate is returned.
- **Failure.** `keep` returns `null` on each of: an `IOException`; a `SecurityException`; and **a `File.renameTo` that returns `false`** (`renameTo` reports failure by its return value and does not throw). On every failure path the `.tmp` file is deleted before `keep` returns, in a `finally`, so no `octave-install-id.tmp` is left behind; a failure never returns the candidate. Nothing is logged, and no message leaves the function.
- A `.tmp` file left by a killed process is overwritten by the next `keep` that has to store, and is never read as an id.
- One process-wide lock (a private object in a companion) around the whole of `keep`, so two calls cannot both store.
- `OctaveInstallIdModule`: `Name("OctaveInstallId")` and `AsyncFunction("keep") { candidate: String, promise: Promise -> … }`. The body hands the call to the module's IO scope and resolves the promise (the threading note in `OctaveSessionModule.kt`). The store is `InstallIdStore(context.noBackupFilesDir)`; with no React context the function resolves `null`. No event, property, constant or view.

```ts
// modules/install-id/src/index.ts
export interface OctaveInstallIdNative {
  keep(candidate: string): Promise<string | null>;
}
```

### The install id source

```ts
// apps/tv/src/host/install-id.ts
export type InstallIdSource = () => Promise<string>;
export function createInstallIdSource(native: () => Pick<OctaveInstallIdNative, "keep">, crypto: Crypto): InstallIdSource;

// apps/tv/src/host/host-gateway.ts
export const hostInstallId: InstallIdSource; // createInstallIdSource(loadInstallIdModule, hostCrypto)
```

- The first call takes `crypto.randomId()`, calls `native().keep(candidate)` and checks the answer against the same pattern. `native` is a function so that importing the file loads no native module (Jest renders screens without one).
- The source keeps the promise, so concurrent and later callers get the same id with one native call. A rejection, a `null` or a malformed answer rejects with `new Error("The install id is not available.")` and clears the kept promise, so a later call tries again.
- It never returns the candidate on failure. A failure never turns into an id that lasts one launch.

### The gateway factory

```ts
// apps/tv/src/host/gateway.ts
export interface GatewayHost { crypto: Crypto; transport: Transport; installId: InstallIdSource }
export interface GatewayStores {
  confirmations?: LanHttpConfirmationStore;
  streamingLimits?: StreamingLimitStore;
  deviceCapabilities?: DeviceCapabilitySource;
}
export type GatewayFactory = (serverUrl: string, stores?: GatewayStores) => Promise<JellyfinGateway>;
export function createGatewayFactory(host: GatewayHost): GatewayFactory;

// apps/tv/src/host/host-gateway.ts
export const hostGateway: GatewayFactory;
```

- The factory awaits `host.installId()`, checks the pattern again (an `undefined` fourth argument would silently select the constructor's random default), and returns `new JellyfinGateway(serverUrl, host.crypto, host.transport, id, stores?.confirmations, stores?.streamingLimits, stores?.deviceCapabilities)`.
- The factories and the wired exports are in separate files because `scripts/tv-host.test.ts` only scans `crypto.ts` and never imports it ("hostCrypto calls a native module, so it runs only on the device"): a file that imports `./crypto` cannot be loaded by Vitest. `transport.ts` and `session-module.ts` are split the same way.
- `hostGateway` builds its host on first use: `hostCrypto`, `createSessionTransport(loadSessionModule())` and `hostInstallId`. T4-02 and T4-03 are the first production callers; they call `hostGateway(serverUrl, stores)` and construct nothing themselves. Neither depends on T4-09 in the task list, and the lint rule makes the order safe: a `new JellyfinGateway` in a screen fails `pnpm lint`.
- An install id failure reaches the caller as a rejection with the fixed message. T4-02's copy table row "anything else" covers it; this task adds no screen and no copy.
- A bad server address still throws the gateway's own typed error, after the id is read. No request is made in either case.

### The lint rule

A rule on the constructor's name alone misses an aliased import (`import { JellyfinGateway as G }`), a namespace member (`new core.JellyfinGateway(`) and a subclass. So the rule closes the **value import of the class**, not only its construction. In every file under `apps/tv/**` except `apps/tv/src/host/gateway.ts`, ESLint fails each of:

1. `new JellyfinGateway(…)` by that name.
2. A named import of `JellyfinGateway` as a value from a module whose path ends in `jellyfin/gateway`, under any local name. This is what catches the alias and the subclass, which both need the value.
3. A namespace or default import of that module, and `require()` or `import()` of it.
4. A re-export from that module (`export { JellyfinGateway } from …`, `export * from …`).

Allowed everywhere: a type import of the class (`import type { JellyfinGateway }` and `import { type JellyfinGateway }`), which the factory's callers need to name what they hold, and a value import of the module's other exports (`HOME_ROW_LIMIT`, the messages).

The mechanism is `no-restricted-syntax` selectors, because the `no-restricted-imports` in use has no type-import allowance (Facts). A starting point, which the implementer confirms against `@typescript-eslint/parser`'s tree and the frozen tests:

- `NewExpression[callee.name='JellyfinGateway']`
- `ImportDeclaration[importKind!='type'][source.value=/(^|\/)jellyfin\/gateway$/] > ImportSpecifier[importKind!='type'][imported.name='JellyfinGateway']`
- `ImportDeclaration[source.value=/(^|\/)jellyfin\/gateway$/] > :matches(ImportNamespaceSpecifier, ImportDefaultSpecifier)`
- `:matches(ExportNamedDeclaration, ExportAllDeclaration)[exportKind!='type'][source.value=/(^|\/)jellyfin\/gateway$/]`
- `CallExpression[callee.name='require'][arguments.0.value=/(^|\/)jellyfin\/gateway$/]` and `ImportExpression[source.value=/(^|\/)jellyfin\/gateway$/]`

The entries are added to every `no-restricted-syntax` list that covers `apps/tv` (flat config replaces a rule's options), and one later block for `apps/tv/src/host/gateway.ts` restates the list without them. The message is "Build gateways with the factory in apps/tv/src/host/gateway.ts, which passes the stored install id."

**The gap that stays, stated in `docs/security.md`:** the rule reads names and module paths. It does not see a class reached through an object at run time (`someGateway.constructor`), or a new core module that re-exports the class under another path (none exists today; `pnpm lint:boundaries` and review cover a new core export). The rule is a guard against a mistake, not a boundary against hostile code.

### The wire tests

`WireContext` gains `gateway(base: string): Promise<JellyfinGateway>`. `run-wire.ts` builds it per pair with `createGatewayFactory({ crypto: host.crypto, transport, installId: hostInstallId })` (`hostInstallId` from `host-gateway.ts`), where `transport` is the pair's seam-recorded transport, so the calls are recorded as before. The three tests replace their constructor call with `await gateway(base)`; a rejection is handled as each test handles a thrown `connect` today (added to the seam, reported by `codeOf`). Their result lines do not change. The DeviceId they send is now the emulator's stable one; every test logs out, and Jellyfin keeps one token per DeviceId, so runs do not pile up device rows.

### The device stage

App side, `apps/tv/src/e2e/install-id-run.ts`, `runInstallId({ crypto, installId }, log)`. It imports `createGatewayFactory` from `../host/gateway` and `deriveDeviceId` from the core, and takes the Crypto and the source as arguments; `root.tsx` passes `hostCrypto` and `hostInstallId`:

1. Writes `OCTAVE_INSTALL start`.
2. Reads the id from `installId()`. Builds two gateways with `createGatewayFactory` and a recording Transport written in the file (it answers `GET /System/Info/Public` with a fixed version and server id, answers `signIn` with a fixed session and user, and keeps the `deviceId` of each `signIn`). Server `https://octave-e2e.invalid`, user `octave-e2e-user`. Nothing reaches the network.
3. Writes `OCTAVE_INSTALL id shape=<ok|bad> stable=<yes|no> mark=<16 hex>`: `shape` is the id against the UUID pattern; `stable` is yes when both gateways sent the same DeviceId and it equals `deriveDeviceId(crypto, id, <the fixed server id>, "octave-e2e-user")`; `mark` is the first 16 hex digits of `crypto.sha256Hex("octave-e2e-mark:" + deviceId)`.
4. A throw writes `OCTAVE_INSTALL threw` in place of the `id` line. Then `OCTAVE_INSTALL done`.

The lines hold fixed words and the mark only: never the install id, a DeviceId or an error message. `root.tsx` runs this first and conformance after it whatever its result, so `pnpm tv:e2e`'s first stage and `pnpm tv:wire` see the lines they see today plus lines with a prefix neither reads. This part runs on every device, a real TV included: it clears nothing and changes no setting.

Host side, `scripts/tv-install-id.mjs`. Every adb call goes through the runner `openAdb({ adbPath, serial })` returns (`./tv-adb.mjs`); the file starts no program itself, so `scripts/check-adb-output.mjs` passes it.

Pure functions whose words are the spec's own (frozen tests):

- `extractInstallIdLines(logcatLines)`: the `ReactNativeJS` messages that start with `OCTAVE_INSTALL `.
- `judgeInstallId({ fresh, relaunch, afterClear, afterRestore, transport, backup })` returns `ERROR tv install id: <reason>` lines. Each of the four launches must hold exactly one `start`, one `id` line and one `done`, no `threw`, `shape=ok`, `stable=yes` and a 16-hex mark. `relaunch` has `fresh`'s mark; `afterClear`'s differs from `fresh`'s; `afterRestore`'s differs from `afterClear`'s and from `fresh`'s; `transport` must be `"selected"`; `backup` must be `"success"` or `"refused"`, never `"none"`. It takes these three as already-parsed words and reads no device output. Without the last two the restore leg would prove nothing, because the `pm clear` before it already gives a new id.
- `INSTALL_ID_SKIP_LINE`, the one fixed skip line: `install-id stage: skipped, the device is not an emulator`.
- `installIdResultLine({ relaunch, clear, restore, transport, backup })`: `relaunch=same|differs clear=new|same restore=new|same transport=selected|missing backup=success|refused|none`.

Pure functions whose words come from the device (written after milestone 1, tested in the implementer's file):

- `isEmulator(properties)`: `properties` is an object of the named properties milestone 1 chose, each read with its own `adb shell getprop <name>`. It is `true` only when a property holds exactly the value milestone 1 recorded for an emulator. An empty value, a missing property, a failed read and any other value are all `false`. It never reads the whole `getprop` list, which holds the device's serial properties.
- `stageDecision({ emulator, mustRun })` returns `"run"`, `"skip"` or `"fail"`: `"run"` when `emulator` is `true`, whatever `mustRun` is; `"fail"` when it is not and `mustRun` is `true`; `"skip"` otherwise. The environment is an input, never read inside it.
- `backupOutcome(output, applicationId)` reads the `bmgr backupnow` output: `success` when it holds `Package <application id> with result: Success` (sourced, Facts); `refused` when it holds the refusal form milestone 1 recorded for that package; `none` otherwise, a result line for another package included.
- `transportSelected(output)`: `"selected"` only when the output holds "Selected transport" (sourced, Facts), else `"missing"`.

`runInstallIdStage({ adbPath, serial, evidenceDir, env = process.env, open = openAdb })`, called last by `scripts/tv-e2e.mjs`, returns `{ outcome: "ran" | "skipped" | "failed", errors }`:

1. **Decide.** Read the named properties, one `getprop <name>` each. `mustRun` is `env.GITHUB_ACTIONS === "true" || env.OCTAVE_INSTALL_ID_STAGE === "required"`. Take `stageDecision({ emulator: isEmulator(properties), mustRun })`.
   - `"skip"`: write `INSTALL_ID_SKIP_LINE` and nothing else to `release-evidence/tv/e2e-install-id.txt`, print `tv e2e: install-id stage skipped, the device is not an emulator`, and return `skipped` with no error. `pnpm tv:e2e` exits 0. **The skip path has issued only the `getprop` reads: no `pm clear`, no `bmgr` command, no launch, no force-stop.**
   - `"fail"`: write the one fixed line `install-id stage: not run, the device was not recognised as an emulator and this run requires the stage` to the same file, and return `failed` with `ERROR tv install id: the device was not recognised as an emulator, and this run requires the stage`. `pnpm tv:e2e` exits 1. Like the skip path, it has issued only the `getprop` reads.
   - `"run"`: steps 2 to 6.
2. Remember `bmgr enabled` and the selected transport of `bmgr list transports`.
3. `pm clear`, launch, read the lines (`fresh`); force-stop, launch (`relaunch`); `pm clear`, launch (`afterClear`).
4. `bmgr enable true`; select `com.android.localtransport/.LocalTransport` (`transportSelected`); `bmgr backupnow <application id>` (`backupOutcome`); `pm clear`; the restore form milestone 1 recorded; launch (`afterRestore`).
5. In a `finally`: select the remembered transport, restore the remembered enabled state, force-stop the app.
6. Judge. Write `release-evidence/tv/e2e-install-id.txt`: per launch `shape` and `stable`, then the `installIdResultLine`. Print the result line. No mark, no serial. Any `judgeInstallId` error makes the outcome `failed`.
- A launch clears logcat, starts the leanback activity as the first stage does, waits up to 60 s for `OCTAVE_INSTALL done`, and force-stops.
- Neither fixed line holds a serial or a mark, and both go through nothing that could add one.

How the ruling's conditions are met:

| Condition | Where |
|---|---|
| (1) Runs only on a positive emulator; a real device and one that cannot be told apart are both skipped; the skip path runs no `pm clear` and no `bmgr` | `isEmulator` is `true` only on an exact recorded value; step 1 returns before any other adb call. Tested with a recording fake runner |
| (2) The skip is one fixed line in `e2e-install-id.txt`, no serial, no mark, and is printed | `INSTALL_ID_SKIP_LINE`; step 1 |
| (3) A skip is never proof; in the CI `tv` job a skip fails; no edit to `ci.yml`; not the started-marker variable | `mustRun` from `GITHUB_ACTIONS`, which the runner sets for both `tv` runs (precedent: `scripts/ci-emulator-retry.mjs:73`). The task's evidence quotes the ran-stage result line from the `tv` job; the reviewer refuses evidence that holds the skip line |
| (4) The guard and the skip-or-fail decision are a pure function with tests, written once milestone 1 has the property's words | `isEmulator` and `stageDecision`, tested in `scripts/tv-install-id-device.test.ts` |

`OCTAVE_INSTALL_ID_STAGE=required` is for the implementer's own emulator: without it, an emulator the guard does not recognise would give a skip and a green `verify` on a workstation. The implementer's device run for this task sets it, and so do the validation commands below. It is never needed on a real TV, where the variable is left unset and the stage is skipped.

With backup off, `backupnow` is expected to answer `refused` (the package is not allowed to back up) and the restore to bring nothing. What each outcome proves differs, and `docs/security.md` must say which one ran:

- `backup=refused`: Android refused to back the app up at all. That is the only device fact the backup leg proves. `restore=new` is true by construction (the `pm clear` before the restore already gives a new id), so the no-backup directory was never exercised, and its exclusion rests on Android's documentation.
- `backup=success`: a backup ran and the restore did not bring the id back, so the no-backup directory's exclusion is proven for the local transport. It would also mean `allowBackup="false"` did not hold on that image, which the implementer reports as a finding against T3-22.

## Implementation record

### Milestone 1: the emulator probe (2026-11-22, `native-engineer`)

On the implementer's own `fluster_tv` emulator (Android TV, API 36, x86_64, started read-only with `-no-snapshot`), with the e2e APK built from this branch at `9c6fdc2b` installed. The serial is left out. Each command was run once, by hand, with `-s` naming that emulator.

- Properties, one `getprop <name>` each: `ro.boot.qemu` is `1`; `ro.kernel.qemu` is `1`; `ro.build.characteristics` is `emulator`; `ro.hardware` is `ranchu`. **The guard reads `ro.boot.qemu` and `ro.kernel.qemu` and is `true` when either is exactly `1`** (after trimming whitespace). Both are set by the emulator's kernel command line and absent on a production device (unverified on the Shield; a missing property reads as empty, which the guard treats as not an emulator).
- `bmgr enabled` before the stage: `Backup Manager currently disabled`; after `bmgr enable true`: `Backup Manager now enabled`, then `Backup Manager currently enabled`.
- `bmgr list transports` while backup is disabled: `    com.android.localtransport/.LocalTransport`, with **no `*` marker**. After a selection it prints `  * com.android.localtransport/.LocalTransport`. The local transport is present.
- `bmgr transport com.android.localtransport/.LocalTransport`: `Selected transport com.android.localtransport/.LocalTransport (formerly com.google.android.gms/.backup.BackupTransportService)`. The words "Selected transport" match the sourced script.
- `bmgr backupnow dev.octave.tv`, after the two steps above:
  ```
  Running incremental backup for 1 requested packages.
  Package dev.octave.tv with result: Backup is not allowed
  Backup finished with result: Success
  ```
  The refusal form is `Package <application id> with result: Backup is not allowed`. The last line says `Success` for the run as a whole even though the package was refused, so `backupOutcome` reads only the line for the exact application id.
- `bmgr list sets`: `  1 : Local disk image`. `bmgr help` gives the restore form `bmgr restore TOKEN PACKAGE...`. After `pm clear`, `bmgr restore 1 dev.octave.tv` printed `Scheduling restore: Local disk image`, `restoreStarting: 0 packages`, `restoreFinished: -1000`, `done`. **The stage restores with `bmgr restore <the first token of bmgr list sets> <application id>`.**
- Putting the transport back: `bmgr transport com.google.android.gms/.backup.BackupTransportService` printed `Unknown transport 'com.google.android.gms/.backup.BackupTransportService' specified; no changes made.` The image names a Play services transport as its setting but has none registered, so the earlier selection cannot be put back by name. `bmgr enable false` printed `Backup Manager now disabled`.

Decisions from the probe:

- 2026-11-22 (implementer). **The remembered transport is the one the selection reports as `formerly`.** `bmgr list transports` marks none while backup is disabled, so it cannot say what was selected. In the `finally`, the stage selects the remembered transport again; when Android answers `Unknown transport` (no such transport is registered, as on this image) the stage prints that the earlier transport could not be put back and does not fail: there was no working transport to return to. The enabled state is always put back.
- 2026-11-22 (implementer). **`isEmulator` reads two named properties.** Either `ro.boot.qemu` or `ro.kernel.qemu` exactly `1`. Two names guard against an image that sets only one; neither is read as a list.
