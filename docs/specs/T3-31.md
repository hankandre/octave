## Goal

`pnpm tv:build` and `pnpm tv:e2e:build` both run `:app:assembleRelease` and write the same APK path and the same R8 mapping path. The e2e build moves its APK to `apps/tv/dist/e2e/` but leaves its mapping at the release path, so the three checks that need an APK and its own mapping can only be run on the release APK. `pnpm tv:e2e` installs the e2e APK after judging only its network security configuration.

After this task the e2e build keeps its mapping beside its APK, and `pnpm tv:e2e` runs the dex check (T3-19, T3-29), the inspector check (T3-16) and the native inspector check (T3-28) on the e2e APK with that mapping before it runs adb at all. One failing check stops the run with the check's own `ERROR` lines, and the APK is not installed.

## Approach

### The build

In `scripts/tv-build.mjs`:

- `export const E2E_MAPPING = join(APP_DIR, "dist", "e2e", "octave-tv-e2e.mapping.txt");`
- `SYSTEM.releaseMapping` is `RELEASE_MAPPING`, imported from `./tv-apk-inspector.mjs` (it already exports the path, and importing it runs nothing); `SYSTEM.e2eMapping` is `E2E_MAPPING`.
- In `build()`, for an e2e build, after the probe APK count is checked and before anything is moved: when `system.releaseMapping` does not exist, return ``ERROR tv build: Gradle wrote no R8 mapping at <relative path>``. `buildTv` then removes the release APK, as for every failed e2e build.
- The moves, in this order: remove the stamp, remove an old `e2eMapping`, rename the APK, rename the probe APK, rename `releaseMapping` to `e2eMapping`, write the stamp. The stamp is last, so a build cut short between two moves leaves no stamp and is rebuilt.
- `e2eApkIsCurrent()` adds `existsSync(E2E_MAPPING)`. This is what makes an e2e APK built before this task stale, since `scripts/` is not in the source hash.
- A release build is unchanged. It neither reads nor writes `dist/e2e/`.
- The success line names the mapping too: `tv build: e2e APK at …, mapping at …, probe APK at …`.

**Choice: move, not copy.** The mapping goes the way the APK does, so after an e2e build the release paths hold nothing an e2e build wrote, and `pnpm tv:apk:check` run by mistake fails on a missing file instead of reading an e2e build's mapping. The cost is that the next build reruns R8, because Gradle reruns a task whose output file is gone (Gradle's up-to-date rule; that AGP declares `mapping.txt` as an output of the R8 task is unverified here, see Risks and Validation commands).

A failed e2e build leaves the mapping where Gradle wrote it. It holds no harness code, and both mapping guards refuse it for an APK of another build.

### The mapping path

- `node scripts/tv-e2e.mjs [apk [probe-apk [mapping]]]`. `const mapping = args[2] ?? E2E_MAPPING;`. With no argument, the APK, the probe and the mapping are the three files `pnpm tv:e2e:build` wrote.
- An explicit APK with no third argument is judged against `E2E_MAPPING`. If that is another build's mapping, dex D0 and inspector N2 fail on the `pg-map-id`. The checks are never skipped and no fallback reads the release path.
- `scripts/tv-e2e.mjs` checks the file itself, beside the two existing existence checks: `no R8 mapping at <path>; pass it after the probe APK or run pnpm tv:e2e:build`.
- `scripts/tv-e2e.mjs` and `scripts/tv-e2e-apk.mjs` import no `RELEASE_MAPPING` and no `RELEASE_APK`, and `checkE2eApk` passes the mapping to the dex and inspector checks as an explicit argument, so neither check falls back to its default. Item 1 is proved by the path the checks are given, not by a `pg-map-id` mismatch: the two builds compile the same classes and may carry the same id (unverified).

### The checks

New `scripts/tv-e2e-apk.mjs`:

```js
// The checks the e2e APK gets before pnpm tv:e2e installs it (T3-31), each with the lists and rules of pnpm tv:apk:check.
export const E2E_APK_CHECKS = [
  { script: "scripts/tv-apk-dex.mjs", run: ({ apk, mapping }) => dexMain([apk, mapping]) },
  { script: "scripts/tv-apk-inspector.mjs", run: ({ apk, mapping }) => inspectorMain([apk, mapping]) },
  { script: "scripts/tv-apk-native-inspector.mjs", run: ({ apk }) => nativeInspectorMain([apk]) },
];

// Runs every check, in order, on { apk, mapping }. Each check prints its own lines. Returns one
// `ERROR tv e2e: …` line per check that failed; empty when all three exited 0.
export async function checkE2eApk({ apk, mapping }, checks = E2E_APK_CHECKS)
```

- A check fails when its `run` returns or resolves to anything but `0`, or throws. The line is ``ERROR tv e2e: the e2e APK failed <script> (exit <code>); it was not installed``; a throw gives `(<the error's message>)` in place of the exit code.
- **All three run, whatever the first says**, so one run shows every `ERROR` line. The checks are independent and read only files.
- The checks' own output is not captured: their `ERROR` lines go to stderr and their one-line summaries to stdout, as under `pnpm tv:apk:check`. The summaries are the evidence that the e2e APK passed.
- `checks` is a parameter only so a test can pass fakes; `scripts/tv-e2e.mjs` calls `checkE2eApk({ apk, mapping })` with no second argument. No option, environment variable or argument of `scripts/tv-e2e.mjs` skips or replaces a check.
- No `lists` is passed to the dex check, so it uses `PRODUCTION_LISTS`.
- The manifest check (`scripts/tv-apk-manifest.mjs`) and the badging check are not in the task's acceptance and are not added.

### Where the run stops

In `main` of `scripts/tv-e2e.mjs`, after the existing network security block (unchanged, `:155-164`) and before `adb get-state`:

```js
const apkErrors = await checkE2eApk({ apk, mapping });
if (apkErrors.length > 0) {
  for (const error of apkErrors) console.error(error);
  process.exit(1);
}
```

No adb command runs before this point today (`runner.run` is first called at `:165`), and none is added. The file is 213 lines and stays under 400.

### No row for the e2e APK

- The dex check and the inspector check read the dex and the mapping; the native check reads `lib/<abi>/*.so`. None reads the JavaScript bundle (`docs/security.md:103` says so for the dex check).
- The two builds differ only in the bundle (Facts, "Only Metro reads the flag"). The harness under `apps/tv/src/e2e/` is JavaScript; it adds no class and no library.
- So the e2e APK needs no row the release APK does not, and it must not get one: D3 fails a stale row on the release APK, and a row that only an e2e build needs would mean the e2e build links code the release build does not, which is the thing these checks exist to show.
- **If the first real run disagrees** (a D2, D5, D6, N3, N4, L2 or L3 line on the e2e APK that the release APK of the same commit does not give), the implementer stops, adds no row, and reports the lines. A row for the e2e APK alone would be a new export in its own file, passed through `system.lists`, never spread into `PRODUCTION_LISTS`; adding it is a scope change for the Product Owner and an amendment to this spec.
