# Commands

Every command an agent or contributor runs in Octave. `AGENTS.md` holds the rules; this file holds the how.

- Use the Node version in `.node-version` (mise reads it via `mise.toml`; run `mise exec --` in non-interactive shells).
- Install: `pnpm install`
- Core unit tests (Vitest, Node environment): `pnpm --filter @octave/core test`; `pnpm test` runs them, then the root scripts and workflow tests
- Type-check: `pnpm typecheck`
- Lint: `pnpm lint`, `pnpm lint:boundaries`, `pnpm lint:network` (T3-04: no network path around the one client), `pnpm lint:logs` (T3-16: no log call with a value and no `HttpLoggingInterceptor` in the session module or its seam), `pnpm lint:ghost-terms`, `pnpm lint:backlog`, `pnpm lint:flow`
- Task workflow tests: `pnpm test:workflow`
- App component tests (Jest and React Native Testing Library, `*.test.tsx` under `apps/tv/src`): `pnpm --filter @octave/tv test`; `pnpm test` includes them
- All checks: `pnpm check`
- Fixture servers: `pnpm fixture:up` starts the three pinned servers under this checkout's own Compose project (`octave-<10 hex>`, from `tests/integration/compose-project.mjs`; T3-05) and stops first, naming the holder and the command that removes it, when another project holds port 18096, 18097 or 18098; `pnpm fixture:setup` creates the users and libraries (it waits for the library scans, so run `pnpm samples:generate` first); `pnpm fixture:down` removes this checkout's project only. The ports are fixed, so only one checkout can have servers up at a time.
- Server tripwire (needs `pnpm samples:generate`, `pnpm fixture:up`, `pnpm fixture:setup`): `pnpm test:tripwire`
- Jellyscale fixture check (needs the fixture servers up and set up): `pnpm fixture:check-jellyscale` re-probes the pinned Jellyscale and fails if its endpoint inventory changed.
- Task CLI: `pnpm task next`, `pnpm task show <id>`, `pnpm task list [--status s] [--phase p]`, `pnpm task set <id> --status s [--owner o] [--evidence-file f]`.
- TV app (needs the Android SDK in `ANDROID_HOME` and the JDK `mise.toml` names): `pnpm tv:prebuild` (generate `apps/tv/android`), `pnpm tv:build` (release APK), `pnpm tv:apk:check` (its badging, network security configuration, permissions, queries and backup setting, and, through `scripts/tv-apk-inspector.mjs [apk] [mapping]`, no Expo network inspector or dev-launcher package in the release APK, T3-16, and the network entry points in its dex, which needs the mapping file of the same build, T3-19, and no native library wired to the C++ inspector's network dispatcher, `scripts/tv-apk-native-inspector.mjs [apk]`, T3-28; takes no argument), `pnpm tv:native:test` (the app's and modules' JVM tests), `ANDROID_SERIAL=<your own emulator> pnpm tv:smoke` (first focus on an Android TV emulator; it also fails if the app connects to the development server port: stop Metro first, and run one smoke test per host at a time, because the watch holds host port 8081 and counts a connection from any emulator or other host process), `pnpm tv:e2e:build` (the e2e APK and the session module's cleartext probe APK), and `ANDROID_SERIAL=<your own emulator> pnpm tv:e2e` (the e2e APK's network security, the core's conformance suites under Hermes on the emulator, then the cleartext probe and the resolved-address check (T3-20); builds both APKs when either is missing or stale)
- Wire tests (T3-05): `ANDROID_SERIAL=<your own emulator> pnpm tv:wire [--task <id>]` runs the tagged tests of `apps/tv/src/e2e/wire/wire-tests.json` in the e2e app against a local mock and the pinned Jellyfin and Jellyscale servers. It starts the fixture servers when a selected real target does not answer, builds the e2e APK when stale, and records every request through one recorder per test and target. It waits until the device's adb daemon has run for 60 s, and a run whose adb connection dropped (a reverse gone or adbd changed at its end) is void and runs once more. `--list` prints the selected tests and needs no device. It sets the device-global `http_proxy` for the whole run and sets and removes `adb reverse` ports, so it runs only on your own emulator: never on the Shield or another shared device, whose owner's proxy setting it would clear. These hold from T3-26:
  - **Evidence.** `release-evidence/wire` is removed at the start of every invocation, `--list` and an unknown argument included, as the first thing `main` does, so a file there is from the last invocation. A directory without `summary.txt` is not a result (a run stopped by a signal, or a module that failed to load before `main`, can leave one). `OCTAVE_WIRE_EVIDENCE` overrides the directory for a test of the CLI: it must be an absolute path ending in `release-evidence/wire`, and any other value is refused because the directory is removed recursively.
  - **What the files hold.** `<test>-<target>.jsonl`: per request, the method, path, query names, whether `Authorization` was present, its scheme, whether its `Token` field had a value, the `Host`, the answer's status and `Retry-After`, and whether the URL held a known secret; never a header value, a query value or a body. `summary.txt`: one `<test> <target> <task> pass|fail` line per pair. `app-lines.txt`: the app's `OCTAVE_WIRE` lines. `device.txt`: adbd and reverse state, the resumed package, and how the log was kept; never the serial. `global-proxy.txt`: a count, and the method and `Host` of each request that reached the proxy listener. Any field or line that holds a known secret (the canary, the passwords, each issued token, in the forms `findSecret` knows) is written as `[holds a secret]`, every file is read back and scanned, and a replacement fails every pair of the run. The kept logcat is never written there.
  - **Signals.** SIGINT and SIGTERM restore the device: the proxy is cleared, the app force-stopped and each reverse the run made removed (never `--remove-all`), and the run exits 130 or 143. The handlers are registered when the first reverse or the proxy is set, and Node runs them only between synchronous calls, so the runner makes only short `adb` calls while the proxy is set. During `fixture:up`, the APK build and `adb install` nothing is set. SIGKILL and a hung `adb` cannot be handled; the next run clears the proxy at its start.
  - **The log.** `adb logcat` is streamed to the host from before the app starts, so the device's buffer size does not matter. The run fails (`cannot tell that the run's whole log was kept`) when the start or end marker never arrives, the stream closed, no line arrived, or a numbered interval marker written during the run did not arrive. The judge reads the kept lines and the final `logcat -d`.
- Not yet built: `pnpm tv:visual` (T3-07).

## Native tests

- `pnpm tv:native:test` runs the app's and the native modules' JVM tests; `node scripts/tv-native-test-only.mjs <filter>` runs one class.
