# Commands

Every command an agent or contributor runs in Octave. `AGENTS.md` holds the rules; this file holds the how.

- Use the Node version in `.node-version` (mise reads it via `mise.toml`; run `mise exec --` in non-interactive shells).
- Install: `pnpm install`
- Core unit tests (Vitest, Node environment): `pnpm --filter @octave/core test`; `pnpm test` runs them, then the root scripts and workflow tests
- Type-check: `pnpm typecheck`
- Lint: `pnpm lint`, `pnpm lint:boundaries`, `pnpm lint:network` (T3-04: no network path around the one client), `pnpm lint:logs` (T3-16: no log call with a value and no `HttpLoggingInterceptor` in the session module or its seam), `pnpm lint:ghost-terms`, `pnpm lint:backlog`, `pnpm lint:flow`
- Task workflow tests: `pnpm test:workflow`
- App component tests (Jest and React Native Testing Library, `*.test.tsx` under `apps/tv/src`): `pnpm --filter @octave/tv test`; `pnpm test` includes them
- All checks: `pnpm check`
- Fixture servers: `pnpm fixture:up` starts the three pinned servers under this checkout's own Compose project (`octave-<10 hex>`, from `tests/integration/compose-project.mjs`; T3-05) on host ports of this checkout's own (T3-27). It chooses them with `tests/integration/fixture-ports.mjs`: the ports already recorded when they are free or held by this checkout's own project, else three consecutive ports of a slot (slot k is 18096 + 3k to 18098 + 3k, 300 slots up to 18995), starting at the slot the project name gives and walking on past any port another Compose project or process holds; 18096 to 18098 is slot 0 and the default every reader uses when there is no record. The record is `tests/integration/.fixture-ports` (gitignored; keys `OCTAVE_FIXTURE_PORT_JELLYFIN_10_11`, `OCTAVE_FIXTURE_PORT_JELLYFIN_12`, `OCTAVE_FIXTURE_PORT_JELLYSCALE`), and Compose publishes through `tests/integration/docker-compose.ports.yml` (needs Docker Compose 2.24.4 or later) with `--env-file` on it. When `up` fails because a chosen port was taken meanwhile, it chooses again, at most three times. A project left by a deleted checkout is stepped around, not removed: stop it with `pnpm fixture:down` in its checkout or `.claude/workflows/fixtures-down.mjs`. `node tests/integration/fixture-ports.mjs` prints this checkout's origins and `--check` tells whether its recorded ports are still usable. `pnpm fixture:setup` creates the users and libraries (it waits for the library scans, so run `pnpm samples:generate` first) and `pnpm test:tripwire`, the recorders and `pnpm tv:wire` read the origins from the record; `pnpm fixture:down` removes this checkout's project only.
- Server tripwire (needs `pnpm samples:generate`, `pnpm fixture:up`, `pnpm fixture:setup`): `pnpm test:tripwire`
- Jellyscale fixture check (needs the fixture servers up and set up): `pnpm fixture:check-jellyscale` re-probes the pinned Jellyscale and fails if its endpoint inventory changed.
- Task CLI: `pnpm task next [--lane l]`, `pnpm task show <id>`, `pnpm task list [--status s] [--phase p] [--lane l]`, `pnpm task set <id> --status s [--owner o] [--evidence-file f]`.
- TV app (needs the Android SDK in `ANDROID_HOME` and the JDK `mise.toml` names): `pnpm tv:prebuild` (generate `apps/tv/android`), `pnpm tv:build` (release APK), `pnpm tv:apk:check` (its badging, network security configuration, permissions, queries and backup setting, and, through `scripts/tv-apk-inspector.mjs [apk] [mapping]`, no Expo network inspector or dev-launcher package in the release APK, T3-16, and the network entry points in its dex, which needs the mapping file of the same build, T3-19, and no native library wired to the C++ inspector's network dispatcher, `scripts/tv-apk-native-inspector.mjs [apk]`, T3-28; takes no argument), `pnpm tv:native:test` (the app's and modules' JVM tests), `ANDROID_SERIAL=<your own emulator> pnpm tv:smoke` (first focus on an Android TV emulator; it also fails if the app connects to the development server port: stop Metro first, and run one smoke test per host at a time, because the watch holds host port 8081 and counts a connection from any emulator or other host process; a second run on the host fails at once, before it touches the device, and names the first run's process; a control command that fails fails the run, and a connection made before the controls run is counted apart; console output and evidence hold the device serial as given and its host-and-port forms only as `[device]`, which `scripts/tv-adb.mjs` writes (an address the serial does not contain is not replaced, see docs/security.md), in this script and in `pnpm tv:e2e` and `pnpm tv:wire`), `pnpm tv:e2e:build` (the e2e APK and the session module's cleartext probe APK), and `ANDROID_SERIAL=<your own emulator> pnpm tv:e2e` (the e2e APK's network security, the core's conformance suites under Hermes on the emulator, then the cleartext probe and the resolved-address check (T3-20), then the install-id stage (T4-09); builds both APKs when either is missing or stale. On an emulator the install-id stage clears the app's data and switches the backup transport for the length of the stage, then puts the backup enabled state back and selects the earlier transport again (on an emulator image whose earlier transport is not registered, Android refuses that, the local transport stays selected and the stage says so), and writes its result line to `release-evidence/tv/e2e-install-id.txt`. On a device that is not recognised as an emulator (a real TV) the stage is skipped after reading two properties by name, clears and changes nothing, prints the skip and writes it to the same file, and the command still passes on its other stages. `OCTAVE_INSTALL_ID_STAGE=required` makes a skip a failure, as it is in CI, where `GITHUB_ACTIONS` does the same; set it on your own emulator so an unrecognised emulator cannot pass with a skip)
- Wire tests (T3-05): `ANDROID_SERIAL=<your own emulator> pnpm tv:wire [--task <id>]` runs the tagged tests of `apps/tv/src/e2e/wire/wire-tests.json` in the e2e app against a local mock and the pinned Jellyfin and Jellyscale servers. It starts the fixture servers when a selected real target does not answer, builds the e2e APK when stale, and records every request through one recorder per test and target. It waits until the device's adb daemon has run for 60 s, and a run whose adb connection dropped (a reverse gone or adbd changed at its end) is void and runs once more. `--list` prints the selected tests and needs no device. It sets the device-global `http_proxy` for the whole run and sets and removes `adb reverse` ports, so it runs only on your own emulator: never on the Shield or another shared device, whose owner's proxy setting it would clear. These hold from T3-26:
  - **Evidence.** `release-evidence/wire` is removed at the start of every invocation, `--list` and an unknown argument included, as the first thing `main` does, so a file there is from the last invocation. A directory without `summary.txt` is not a result (a run stopped by a signal, or a module that failed to load before `main`, can leave one). `OCTAVE_WIRE_EVIDENCE` overrides the directory for a test of the CLI: it must be an absolute path ending in `release-evidence/wire`, and any other value is refused because the directory is removed recursively.
  - **What the files hold.** `<test>-<target>.jsonl`: per request, the method, path, query names, whether `Authorization` was present, its scheme, whether its `Token` field had a value, the `Host`, the answer's status and `Retry-After`, and whether the URL held a known secret; never a header value, a query value or a body. `summary.txt`: one `<test> <target> <task> pass|fail` line per pair. `app-lines.txt`: the app's `OCTAVE_WIRE` lines. `device.txt`: adbd and reverse state, the resumed package, and how the log was kept; never the serial. `global-proxy.txt`: a count, and the method and `Host` of each request that reached the proxy listener. Any field or line that holds a known secret (the canary, the passwords, each issued token, in the forms `findSecret` knows) is written as `[holds a secret]`, every file is read back and scanned, and a replacement fails every pair of the run. The kept logcat is never written there.
  - **Signals.** SIGINT and SIGTERM restore the device: the proxy is cleared, the app force-stopped and each reverse the run made removed (never `--remove-all`), and the run exits 130 or 143. The handlers are registered when the first reverse or the proxy is set, and Node runs them only between synchronous calls, so the runner makes only short `adb` calls while the proxy is set. During `fixture:up`, the APK build and `adb install` nothing is set. SIGKILL and a hung `adb` cannot be handled; the next run clears the proxy at its start.
  - **The log.** `adb logcat` is streamed to the host from before the app starts, so the device's buffer size does not matter. The run fails (`cannot tell that the run's whole log was kept`) when the start or end marker never arrives, the stream closed, no line arrived, or a numbered interval marker written during the run did not arrive. The judge reads the kept lines and the final `logcat -d`.
- Not yet built: `pnpm tv:visual` (T3-07).

## Native tests

- `pnpm tv:native:test` runs the app's and the native modules' JVM tests; `node scripts/tv-native-test-only.mjs <filter>` runs one class.

## CI

Two rules for `.github/workflows/ci.yml` (T1-17), both read by `scripts/ci-rules.test.ts`:

- **Skip.** The `changes` job runs `scripts/ci-device-jobs.mjs` on pull requests. When every path the merge commit changes is under `docs/` or `tasks/`, the `tripwire`, `tv` and `wire` jobs are skipped, and a skipped job reports success to the required checks. Any other changed path, a diff that cannot be read, a push to main and a merge group run all three. `checks` and `dependency-review` always run. No step of the three jobs reads a path under `docs/` or `tasks/`; add a prefix to the list only with that proof.
- **Retry.** An emulator step of `tv` or `wire` runs once more only when the emulator never reached its test script (for example `adb: device offline` during boot). A pnpm shim, `scripts/ci-script-started.sh`, creates a start marker before the real pnpm starts, and `scripts/ci-emulator-retry.mjs` reads it after a failed first attempt. A started script is never retried, whatever its result, and a case that cannot be told apart is not retried.
- Pipeline cost: `node scripts/pipeline-cost.mjs [--projects <dir>] [--merged <ID>,…] [--json]` (T1-20). It reads the workflow journals read-only, has no `pnpm` alias, and is not part of `pnpm check`.
